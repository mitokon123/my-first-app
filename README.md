# ABYSS CHRONICLE

**世界名: Monstoria**　／　ジャンル: モンスター育成 × ローグライク

深淵（Abyss）へ挑み、モンスターを仲間にしながら最深部を目指す。
挑む場所は**ステージ選択**で選び、マップは毎回ランダム生成される。仲間やアイテムも毎回異なる。

> ゲーム名・世界名は `data/config.js` の `gameTitle` / `worldName` で管理している。

**現在のバージョン: α-1**（更新履歴は `data/patchnotes.js`。タイトル画面の「パッチノート」から読める）

HTML / CSS / JavaScript のみで開発（フレームワーク・ライブラリなし、ES6以降）。

## 画面の流れ

```
タイトル ──[新しく始める]──▶ 拠点 ──[ダンジョンへ潜る]──▶ ダンジョン選択 ──[挑む]──▶ 探索
   ▲          (※確認あり)     │  ▲                    ▲              │           │
   └────[Esc]─────────────────┘  │                    └──[Esc]───────┘           │
   │                              └──────────[Esc / 全滅]────────────────────────┘
   └──[続きから]──▶ 拠点（セーブした仲間・持ち物・図鑑・クリア済みを引き継ぐ）

※「新しく始める」は、セーブデータがある場合のみ「はい / いいえ」の確認が出る
　（既定は「いいえ」。この時点ではセーブデータは消えない）

探索 ──[敵と遭遇]──▶ 戦闘 ──▶ 探索
探索 ──[仕掛けを踏む]──▶ 宝箱 / 泉 / 罠 ──▶ 探索
探索 ──[階段で降りる]──▶ 加護を選ぶ ──▶ 探索（次の階）
探索 ──[全滅]────▶ 拠点（そのランで拾ったアイテムを失う）
拠点 ──[持ち物 / 図鑑 / 設定]──▶ 各画面 ──▶ 拠点
探索 ──[P/Tab]────▶ なかま ──▶ 探索
拠点 ──[なかま]────▶ なかま ──▶ 拠点
探索 ──[ボス撃破]──▶ 拠点（そのダンジョンがクリア済みになり、次が開放される）
探索 ──[最後のボス撃破]──▶ エンディング ──▶ タイトル
```

## パッチノート

タイトル画面の「パッチノート」から開く。**左にバージョンの一覧、右にその内容**を出す。
過去のバージョンも同じ操作で読み返せる。

項目の種類は**色つきの札**で示し、上部に凡例を出す。

| 札 | 色 | 意味 |
|---|---|---|
| 追加 | 緑 | 新しく増えた要素 |
| 調整 | 黄 | 数値のバランス調整 |
| 変更 | 水色 | 仕様や操作の変更 |
| 修正 | 赤 | 不具合の修正 |
| 削除 | 灰 | 取り除いた要素 |

| 操作 | 内容 |
|---|---|
| ↑↓ | 左でバージョンを選ぶ／右で読み進める |
| →・決定 | 内容側へ移る |
| ← | バージョンの一覧へ戻る |
| ホイール | **カーソルが乗っている側**をスクロール |

### 更新履歴を足すとき

`data/patchnotes.js` の `versions` の**先頭**に1エントリ足すだけでよい。

```js
{
  version: "α-2", date: "2026-08-20",
  summary: "ひと言でどんな更新か",
  entries: [
    { type: "added",   text: "新しく増えたもの" },
    { type: "balance", text: "数値の調整" }
  ]
}
```

種類（`types`）を増やすときも同じファイルに1エントリ足すだけで、
**色つきの札と凡例に自動で反映される**（画面のコードは変更不要）。

## ゴールドと装備

ローグライクの土台として、**3つの時間軸**で持ち物を分けている。

| 時間軸 | 何が該当するか | 全滅したとき |
|---|---|---|
| 1回の挑戦の中だけ | **加護**（階を降りるたびに選ぶ強化） | 消える |
| 拠点に持ち帰れば残る | アイテム・素材 | そのランで拾った分を失う |
| ずっと残る | **ゴールド・装備** | **失わない** |

### ゴールド

- 敵を倒すと手に入る（`data/monsters.js` の `goldReward`）
- **相手のレベルが高いほど多い**（`data/growth.js` の `goldRewardPerLevel`、現在 0.15）
  もらえる量 = `floor( goldReward × (1 + (相手のLv - 1) × 0.15) )`
- 最初の所持金は `data/player.js` の `startingGold`（現在 50G）
- 全滅しても失わない。拠点の右上に常に表示される

| モンスター | 基準 | Lv5 | Lv8 |
|---|---|---|---|
| スライム | 4 | 6 | 8 |
| コケネズミ | 6 | 9 | 12 |
| キノコン | 9 | 14 | 18 |
| 坑道の主（Lv8） | 60 | — | 123 |

### 装備

**装備はアイテムの一種**として `data/items.js` に置いてある。こうすると持ち物・ドロップ・図鑑・
（今後の）ショップが**すべて同じ仕組みで扱える**ので、装備専用の処理を増やさずに済む。

```js
stoneBand: {
  id: "stoneBand", name: "石の腕輪", category: "equipment",
  description: "ずしりと重い腕輪。守りが上がるが、少し鈍くなる。",
  maxStack: 9, effect: null, usableIn: [],
  equip: {
    effects: [
      { type: "statBonus",      stat: "defense", value: 3 },
      { type: "statMultiplier", stat: "speed",   value: 0.9 }
    ]
  }
}
```

- **効果の書き方は特性とまったく同じ**。`statBonus`（加算）だけが装備用に追加された種類
- 1体が着けられるのは `data/config.js` の `equipMax`（現在 **1つ**）
- 拠点の「仲間」画面で仲間を選び、**「装備」**を選ぶと着け替えの一覧が開く（**E キー**でも直接開ける）。
  1つも持っていない場合も画面は開き、その旨を表示する
- **選んでいる装備にしたときのステータスの変化が、その場で「8 → 5」の形で出る**。
  上がる値は緑、下がる値は赤。外すときも同じように確認できる
- 着けると持ち物から減り、外すと持ち物へ戻る。**持ち物がいっぱいなら外せない**（装備が消えないように）

**現在の装備**

| 装備 | 効果 |
|---|---|
| 石の腕輪 | 防御 +3／素早さ ×0.8 |
| 牙のお守り | 攻撃 +2 |
| 光る提灯 | 光属性の与ダメージ ×1.15／PP +1 |
| 苔の護符 | HP +8／受けるダメージ ×0.9 |

> 入手経路は**ショップで買う・工房で作る・低確率でドロップ**の3つ。
> 現在はショップのみ実装済み。

## ショップ

拠点の「ショップ」から開く。**←→ で「買う」と「売る」を切り替える**。

| 品物 | 買値 | 並ぶ条件 |
|---|---|---|
| 薬草 | 20G | 最初から |
| 回復薬 | 60G | 最初から |
| 牙のお守り | 100G | 最初から |
| 石の腕輪 | 120G | 苔むす坑道をクリア |
| 光る提灯 | 150G | 苔むす坑道をクリア |
| 深淵の雫 | 300G | 灼熱の亀裂をクリア |

- 値段は `data/items.js` の `price`。**売値は買値 × `sellRate`（現在 0.5）**
- `price: 0` のアイテムは**売り買いできない**（古びた鍵などの重要アイテム）
- 素材（鉱石のかけら 8G・光る鱗粉 12G・苔むした核 50G）は売って現金にできる
- 買えないときは理由が出る（お金が足りない／持ち物がいっぱい）。
  **持ち物に入らなかった場合はお金を払わない**

### 売り買いの確認（誤操作を防ぐ）

決定を押すとすぐには売買せず、**買うときも売るときも2段階**に分かれる。

```
品物を選ぶ → ①個数を決める → ②「買いますか?／売りますか?」はい／いいえ → 実行
              ↑ Esc で戻る      ↑ Esc・いいえ で①へ戻る
```

①の画面には、**個数・1個あたりの値段・合計金額・そのあとの所持金**を同時に出す。

- **↑↓ で1個ずつ、←→ で10個ずつ**（`data/ui.js` の `shop.quantityStep`）
- 個数は上限を超えられない
  - 買う … **所持金・所持数の上限・持ち物の空き**のいちばん厳しいもの
  - 売る … **持っている数**
- そもそも1個もやりとりできない場合は、個数の画面に入らず理由だけ出る
- 買うときに入りきらなかった分は買わず、**受け取った数のぶんだけ支払う**

## 工房

拠点の「工房」から開く。拾った素材とゴールドで、道具や装備を作る。

**作るのにゴールドは要らない。素材だけで作れる。**

| 作れるもの | 素材 | 解放 |
|---|---|---|
| 回復薬 | 薬草×2 | 最初から |
| 石の腕輪 | 鉱石のかけら×3 | 最初から |
| 光る提灯 | 光る鱗粉×2／鉱石のかけら×2 | 苔むす坑道をクリア |
| **苔の護符** | **苔むした核×1**／鉱石のかけら×6 | 苔むす坑道をクリア |

> 費用が要るレシピを作りたい場合は `gold` を書けばよい。
> **書かなければ無料**で、画面にも費用の行が出ない。

- 苔の護符は**ボスの落とす「苔むした核」**でしか作れない（HP +8／受けるダメージ ×0.95）
- 素材の過不足は「3/5」の形で出て、**足りないものは赤く表示**される
- 作れないものは一覧で薄く表示され、選ぶと理由が出る
- 作る前に「はい／いいえ」の確認が入る
- **素材を使い切って持ち物の枠が空く場合も作れる**（枠がいっぱいでも詰まらない）

### 作れるものを増やすとき

`data/recipes.js` に1エントリ足すだけでよい。

```js
newItem: {
  id: "newItem", order: 5,
  result: { item: "作るアイテムのid", count: 1 },
  materials: [ { item: "oreShard", count: 3 } ],
  unlockedBy: "mossyMine"   // 省略すると最初から作れる
  // gold: 50               // 書けば費用が要る。省略で無料
}
```

> 判定は `js/systems/CraftSystem.js`。画面に依存しないので、
> 「ダンジョン内の作業台」などを作るときもそのまま使える。

### 品揃えを変えるとき

`data/shop.js` の `stock` に1行足すだけでよい。装備もアイテムの一種なので同じ書き方で並ぶ。

```js
stock: [
  { item: "potion" },                          // 最初から並ぶ
  { item: "elixir", unlockedBy: "mossyMine" }, // クリアで並ぶ
  { item: "herb", price: 15 }                  // この店だけ安くする
]
```

> 判定は `js/systems/ShopSystem.js`。画面に依存しないので、
> 「ダンジョン内の行商」など別の売り場を作るときもそのまま使える。

### 効果の集計（EffectSystem）

特性・装備は、出どころが違っても**同じ形式の効果**として `js/systems/EffectSystem.js` が
まとめて集計する。ステータス計算も戦闘のダメージ計算も、この1か所を見るだけでよい。

```
実効ステータス = floor( 基礎値 × 成長 × 性格 × 効果倍率 ) + 個体値 + 効果加算
```

> 今後「階を降りるたびの強化」を足すときも、`collectEffects` に出どころを1つ増やすだけで
> 戦闘側の変更は要らない。

## 挑戦（ラン）

ダンジョンへ入ってから拠点へ戻るまでが **1回の挑戦（ラン）**。
「潜って、生きて帰る」ことに意味を持たせるための仕組み。

| 帰り方 | 拾ったアイテム | スカウトした仲間 | HP・PP |
|---|---|---|---|
| Esc で自分の足で戻る | 持ち帰れる | 残る | 全回復 |
| ボスを倒して帰還 | 持ち帰れる | 残る | 全回復 |
| **全滅** | **そのランで拾った分をすべて失う** | 残る | 全回復 |

- 失うのは**そのランで拾った分だけ**。出発前から持っていた分は減らない
  （薬草を3個持って入り、2個拾って全滅 → 手元には3個残る）
- 全滅しても仲間は失わない
- ラン中は回復手段が**道具と泉だけ**。拠点へ戻ると全回復する

設定は `data/run.js` にある。

```js
loseItemsOnDefeat: true,     // 全滅で拾ったアイテムを失う
loseMonstersOnDefeat: false, // 全滅でスカウトした仲間も失う（現在は無効）
healOnReturn: true           // 拠点へ戻ると全回復する
```

> 記録は `js/systems/RunSession.js` が持つ。
> `game.giveItem` / `game.addMonster` を通していれば自動で記録されるので、
> 宝箱など新しい入手経路を足しても、ここを直す必要はない。

## 加護（階を降りるたびの強化）

階段を降りると、**3つの候補から1つ選ぶ**画面が出る。選んだ加護は**パーティ全員**に効き、
**そのラン限り**で拠点へ戻ると消える。深く潜るほど重ねられるので、先へ進む理由になる。

| 加護 | 効果 | 出やすさ | weight | 1枠に出る確率 |
|---|---|---|---|---|
| 猛る鼓動 | 攻撃 ×1.1 | よく出る | 1.0 | 15% |
| 硬い皮 | 防御 ×1.1 | よく出る | 1.0 | 15% |
| 疾風の加護 | 素早さ ×1.1 | よく出る | 1.0 | 15% |
| 魔力の器 | PP +2 | ふつう | 0.9 | 13% |
| 一撃の冴え | 与ダメージ ×1.08 | ふつう | 0.7 | 10% |
| 守りの霧 | 受けるダメージ ×0.92 | ふつう | 0.7 | 10% |
| 残り火の記憶 | 火属性の与ダメージ ×1.20 | 少ない | 0.5 | 7% |
| 光の導き | 光属性の与ダメージ ×1.20 | 少ない | 0.5 | 7% |
| 背水の構え | HPが1/4以下で攻撃 ×1.30 | まれ | 0.4 | 6% |

**画面には数値ではなく言葉で出す**（よく出る／ふつう／少ない／まれ）。
言葉と色の対応は `data/run.js` の `blessing.rarityLabels` で決まる。

- 候補は**重み付きで抽選**され、1回の選択肢に同じものは並ばない
- **一度取った加護は再び候補に出ない**（`data/run.js` の `allowRepeat` で変更できる）
- 候補が尽きたら画面自体が出ない
- 途中でスカウトした仲間にも、それまでの加護がすべて掛かる
- 同じステータスへの加護は掛け合わさる（×1.12 と ×1.2 なら ×1.344）

**苔むす坑道では2回**選べる（B1F→B2F と B2F→B3F）。最深階の階段はボス戦なので加護は出ない。

設定は `data/run.js` の `blessing`（出すかどうか・候補の数・重複を許すか）、
中身は `data/blessings.js`。

### 加護を増やすとき

`data/blessings.js` に1エントリ足すだけでよい。**効果の書き方は特性・装備とまったく同じ**。

```js
ironWill: {
  id: "ironWill", name: "鉄の意志",
  description: "仲間全員の防御が上がり、受けるダメージも減る。",
  weight: 0.6,
  effects: [
    { type: "statMultiplier", stat: "defense", value: 1.15 },
    { type: "damageTaken", value: 0.95 }
  ]
}
```

> 効果は `RunSession` が持ち、`Game` が連れている全員の `runEffects` へ配る。
> `EffectSystem` はそれを他の出どころ（特性・装備）と同じように集計するだけなので、
> **戦闘やステータス計算のコードは一切変更していない**。

## 仕掛けマス（宝箱・泉・罠）

階層を生成するたびに、床のどこかへランダムに置かれる。

| 仕掛け | 記号 | 内容 |
|---|---|---|
| 宝箱 | 宝（黄） | 中身を1つ抽選（薬草 重み1.0×1個／鉱石のかけら 0.4×1〜2個／回復薬 0.2×1個） |
| 泉 | 泉（水色） | 仲間全員のHPとPPを**最大値の50%**回復。1回だけ |
| 罠 | 罠（赤） | **踏むまで見えない**。仲間全員が最大HPの12%のダメージ |

- どれも**一度使うと消える**
- 開始位置と階段の上には置かれない
- 罠では**HPが1未満にならない**ので、罠だけで全滅することはない
- 仕掛けを踏んだその一歩では敵と遭遇しない
- 宝箱の中身はランの記録に入るので、**全滅すると失う**

個数は `data/dungeon.js` の `featureCounts`（全ダンジョン共通の既定）。
ダンジョンごとに変えたい場合は `data/dungeons.js` の `features` に書く。

```js
featureCounts: {
  chest:  { min: 1, max: 2 },
  spring: { min: 0, max: 1 },
  trap:   { min: 1, max: 2 }   // 中身は data/features.js の chest.effect.table
}
```

### 仕掛けを追加するとき

`data/features.js` に1エントリ足し、個数を指定するだけでよい。

```js
healSpot: {
  id: "healSpot", name: "祠", mark: "祠", color: "#e8b4ff",
  hidden: false, once: true,
  effect: { type: "heal", hpRatio: 1.0, ppRatio: 1.0 }
}
```

| 効果の種類 | 内容 |
|---|---|
| `giveItem` | `table`（重み付き）から1つ選んで渡す |
| `heal` | `hpRatio` / `ppRatio` の割合で回復 |
| `damage` | `hpRatio` の割合でダメージ。`leaveAtLeast` は必ず残すHP |

- `hidden: true` にすると踏むまで表示されない（罠など）
- 新しい**効果の種類**を足すときは `js/systems/FeatureSystem.js` の
  `EFFECT_HANDLERS` に関数を1つ追加する

## ダンジョン（ステージ選択）

拠点の「ダンジョンへ潜る」を選ぶと**ダンジョン選択画面**が開く。
挑む場所を選ぶ形式で、場所ごとに深さ・出る敵・ボスが違う。
**マップそのものは今までどおり毎回ランダム生成**される。

| ダンジョン | 最深 | 出現Lv | 敵の数 | ボス | 開放条件 |
|---|---|---|---|---|---|
| 苔むす坑道 | B3F | 階ごと（下記） | 階ごと（下記） | 坑道の主（モスゴーレム Lv8） | 最初から |
| 灼熱の亀裂 | B4F | 1〜8 | 2〜3体 | 灼熱の獣（フレイミン Lv18） | 苔むす坑道をクリア |
| 静寂の深層 | B5F | 1〜16 | 2〜3体 | 深淵の王（キングスライム Lv28） | 灼熱の亀裂をクリア |

- **最深階の階段でボスが出る**。それより浅い階の階段は次の階へ降りるだけ
- ボスに勝つと、そのダンジョンが**クリア済み**になり、次のダンジョンが開放されて拠点へ戻る
- `isFinal: true` のボス（深淵の王）を倒したときだけエンディングへ進む
- 未開放のダンジョンは灰色で表示され、決定を押しても入れない（開放条件が出る）
- ボス名は**クリアするまで「？？？」**（`data/messages.js` の `dungeonSelect.unknownBoss`）
- クリア済みの記録はセーブに含まれる（古いセーブを読み込んだ場合は「未クリア」扱い）

### ダンジョンを追加するとき

`data/dungeons.js` に1エントリ足すだけでよい（コードの変更は不要）。

```js
frozenHollow: {
  id: "frozenHollow", order: 4,
  name: "凍てつく空洞",
  subtitle: "一覧に出る短い説明",
  description: "詳細に出す説明。\n改行できる。",
  floors: 6,
  unlockedBy: "silentDepths",          // null なら最初から挑める
  generation: { width: 25, height: 18, roomMin: 3, roomMax: 7, roomCount: 8 },
  encounter: {
    rate: 0.09,                         // 1歩あたりの遭遇確率
    groupSize: { min: 2, max: 3 },
    levelRange: { min: 18, max: 24 },
    table: [ { species: "slime", weight: 1.0 } ]
  },
  boss: "frostLord"                     // data/bosses.js のid
}
```

- `order` が選択画面の並び順。`unlockedBy` は**クリアが必要なダンジョンid**
- `generation` を省いた項目は `data/dungeon.js` の既定を使う（画面が広がる訳ではないので `width`/`height` は画面サイズが上限）
- `encounter.rate` を省くと `data/enemies.js` の `encounterRate` を使う
- ボス側は `data/bosses.js` に同じidで足す

> 開放条件の判定は `js/systems/DungeonCatalog.js` が行う。
> 条件を「2つクリアしたら」等に変えたい場合は `isUnlocked` だけを直せばよい。

## 戦闘システム（3対3）

- 連れていけるのは最大 **6体**（`config.partyMax`）、盤面に出るのは先頭から **3体**（`config.battleFieldSize`）
- 盤面の味方**全員のコマンドを決めてから**、味方・敵をまとめて**素早さの大きい順**に行動する
- 素早さは `baseSpeed`（`data/monsters.js`）から、レベル・性格・個体値を掛けて算出する
- 味方が倒れると、控えが自動で盤面へ繰り上がる。**全員倒れて初めて敗北**
- 戦闘中だけ使う印（`_removed` / `_defending` / `_onField`）は、**戦闘開始時に必ず消してから付け直す**
  （`BattleSystem._resetFieldMarks`）。特にスカウトで仲間になった個体に `_removed` が残ると、
  その仲間は次の戦闘以降ずっと行動しなくなる
- 攻撃対象は「並びの番号」ではなく**選んだ個体そのもの**で覚える。先に別の相手が倒れて並びがずれても、狙った相手を攻撃する（狙った相手が倒れていた場合だけ他へ切り替わる）
- 同じ名前の敵が並んだときは **A・B・C** の印が付き、ログでは敵の名前に **「敵の」** が付く（味方と敵に同名がいても見分けられる）
- 同じ素早さのときの順番は `data/battle.js` の `speedTieBreak` で決める

### 計算式

```
実効ステータス = floor( 基礎値 × (1 + (Lv-1) × 成長率) × 性格補正 × 特性倍率 ) + 個体値

基礎ダメージ = 攻撃力×0.75 + 技威力×0.55 - 防御力×0.25   （0未満は0）
ダメージ     = floor( 基礎 × 属性倍率 × 会心倍率 × 防御倍率 × 特性倍率 × 乱数(0.9〜1.1) )
                                                                       （最低1）

属性倍率 = 1 - 相手の耐性 × 0.07      （無効属性なら 0）
会心倍率 = 2.0（確率 3% ＋ 技のcriticalBonus）
命中     = 技の accuracy（未指定なら 100%）
行動順   = 素早さ × 乱数(0.8〜1.2) の大きい順
必要経験値 = floor( 12 × Lv ^ 1.5 )

もらえる経験値 = floor( expReward × (1 + (相手のLv - 1) × 0.15) )
```

**倒した相手のレベルが高いほど、もらえる経験値が増える**（`data/growth.js` の `expRewardPerLevel`）。
`monsters.js` の `expReward` は Lv1 のときの量。0 にするとレベルに関係なく一定になる。

| | Lv1 | Lv3 | Lv6 | Lv10 |
|---|---|---|---|---|
| コケネズミ（基準13） | 13 | 16 | 22 | 30 |
| キノコン（基準17） | 17 | 22 | 29 | 39 |
| モスゴーレム（基準100） | 100 | 130 | 175 | 234 |

坑道の主（Lv8）を倒すと **204** もらえる。

通常攻撃は「威力0の技」として同じ式で計算する（`data/skills.js` の `normalAttack`）。

### 属性と耐性

属性は **火・水・風・地・雷・光・闇** の7種＋**無**（`data/elements.js`）。
「無」は耐性の影響を受けない（`physical: true`）。通常攻撃や体当たりに使う。

耐性は `data/monsters.js` の `resistances` に **-5〜10** で書く。

| 耐性 | 倍率 |
|---|---|
| 10 | 0.30倍 |
| 5 | 0.65倍 |
| 0 | 1.00倍（等倍） |
| -5 | 1.35倍 |

`immunities: ["light"]` のように書くと、その属性は**完全無効**（ダメージ0）になる。

### 成長率

`data/monsters.js` の `growthRate` でモンスターごとに設定する。**0.01〜0.55**の範囲（`data/growth.js` の `minGrowthRate` / `maxGrowthRate`）に自動で収まる。

```js
growthRate: 0.10                                          // 全ステータス共通
growthRate: { hp: 0.15, attack: 0.15, defense: 0.17,      // ステータスごとに指定
```

- 書かなかった項目は `default` →（それも無ければ）`growth.js` の `defaultGrowthRate` の順に使う
- 未指定の種族は `defaultGrowthRate`（0.06）

### 特性（アビリティ）

モンスターが常に持っている効果。`data/abilities.js` で定義し、`data/monsters.js` の `abilities` に
特性idを書いて割り当てる。

> **1体が持てる特性は `data/config.js` の `abilityMax`（現在 1つ）まで。**
> データに多く書いても、先頭から数えてこの数までしか効かない。
> 複数持たせたくなったら `abilityMax` を増やすだけでよい。

```js
guts: {
  id: "guts", name: "こんじょう",
  description: "HPが少なくなると攻撃が大きく上がる。",
  effects: [
    { type: "statMultiplier", stat: "attack", value: 1.5,
      condition: { hpBelow: 0.25 } }
  ]
}
```

| 効果の種類 | 内容 |
|---|---|
| `statMultiplier` | HP・攻撃・防御・素早さ・PP に倍率（`stat` で指定） |
| `damageDealt` | 自分が**与える**ダメージに倍率。`element` で属性を限定できる |
| `damageTaken` | 自分が**受ける**ダメージに倍率。`element` で属性を限定できる |

条件（`condition`）を付けると、その状況のときだけ効く。

| 条件 | 内容 |
|---|---|
| `hpBelow` | HP割合がこの値以下のとき（0.25 なら1/4以下） |
| `hpAbove` | HP割合がこの値以上のとき |

同じ種類の効果が複数あれば、倍率はすべて掛け合わされる。

### 戦闘の演出

計算は一瞬で終わるが、結果は**1つずつ順番に見せる**。

- 攻撃が表示された瞬間に、その相手のHPバーが**少しずつ減る**
- ダメージ量が対象の**頭のすぐ上**に浮かび上がる。出た瞬間は大きく、上へ流れながら薄くなる
- 同じ相手に続けて出しても重ならないよう、左右へ少し散らばる
- 倒れた相手は演出が終わるまでその場に残り、HPバーが0になった時点で姿を消す
- **決定キーを押している間は早送り**できる
- メッセージ欄が埋まったら **古い行を消さずに送り待ち**になる（`▼` が出る）。
  行が流れて消えないので、味方が何をしたか必ず読める

| 効果は抜群 | 橙 24px | 揺れる＋橙に光る |
| 効果はいまひとつ | 灰 17px | なし |
| 無効 | 紫「0」 | なし |
| 外れ | 灰「MISS」 | なし |
| 回復 | 緑「+数値」 | 緑に光る |

### 戦闘コマンド

| コマンド | 内容 |
|---|---|
| 攻撃 | 通常攻撃。技を選ばずそのまま対象を選ぶ。**PPを使わない** |
| 技 | 技を選び、対象の敵を選ぶ。**PPを消費する** |
| 防御 | そのターンの間、受けるダメージが **0.5倍**（属性も会心も問わない）。次のターンで解除 |
| スカウト | 敵を仲間に誘う。成功率は `data/scout.js` の式（HPが低いほど上がる）。**成功するとその場で戦闘が終わる**。連れていける数がいっぱいでも誘える（下記） |
| 道具 | `usableIn` に `"battle"` を含むアイテムを、味方に使う |
| 逃げる | 1体でも選べば逃走判定を行う |

### PP（技を使うための資源）

- 技には `pp`（消費量）があり、**通常攻撃は0**なので何度でも出せる
- PPが足りない技は選べない（一覧では薄く表示され、選ぶと「PPが足りない!」）
- 敵は `data/battle.js` の `enemyAi.skillRate`（現在 **25%**）の確率で技を使い、それ以外は通常攻撃
- 敵もPPを見て技を選び、足りなくなると通常攻撃になる
- 最大PPは `basePp × (1 + (Lv-1) × 成長率pp)`。性格補正と個体値は掛からない
- 拠点へ戻って全回復すると、HPと一緒にPPも戻る

| コウモリ | 4 | 0.12 | 4 | 8 | 13 | 22 |
| フレイミン | 5 | 0.12 | 5 | 10 | 16 | 28 |

### スカウトの行動順

スカウトは他のコマンドと扱いが違う。

1. スカウトを選んだ時点で、**他の仲間のコマンド選択は行われない**
2. 誘った1体が**素早さに関係なく最初に行動**する
3. **成功** → その場で戦闘終了（敵は行動しない）
4. **失敗** → そのあと**敵だけ**が行動する（他の仲間は動かない）

つまりスカウトは「1ターンを丸ごと賭ける」行動になっている。

### 連れていける数がいっぱいのとき

以前は「これ以上連れていけない!」で終わっていたが、**判定は行い、成功したら行き先を選ぶ**。

| 選択肢 | 内容 |
|---|---|
| 入れ替える | 連れている仲間を1体選ぶ。**その仲間は拠点の預かり所へ送られ**、新しい仲間が加わる |
| 逃がす | 仲間にしない。図鑑には「仲間にした」記録が残る |
| 拠点に送る | 新しい仲間をそのまま預かり所へ送る |

- 預かり所もいっぱいだった場合は、理由を出して**選び直しになる**（相手は消えない）
- この画面は取り消せない。誘いに応じた相手の行き先は必ず決める

## 拠点の預かり所

連れていける6体に入りきらない仲間を預けておく場所。上限は `data/config.js` の `storageMax`（**30体**）。

拠点の「仲間」画面で **←→** で「連れていく / 預かり所」を切り替える。

**「仲間を選ぶ → その仲間に何をするか決める」**という一方向の流れになっている。

| いる場所 | 決定を押すと選べること |
|---|---|
| 連れていく仲間 | 預かり所へ預ける／並び替える／装備／やめる |
| 預かり所 | パーティに加える／装備／やめる |

- **最後の1体は預けられない**（戦えなくなるため）
- パーティが満杯のときは加えられないので、**先に誰かを預ける**
- 並び替えを選ぶと移動先を選ぶ状態になり、決定でその位置と入れ替わる
- 預かり所は6体より多く入るので、一覧は画面に収まる分だけ窓のようにずらして表示する
- 預かり所の中身はセーブに含まれる（古いセーブを読み込んだ場合は空）

> 以前は「2体を選んで入れ替える」方式だったが、
> 何が起きるか分かりにくく、預かり所が空のときに操作できない問題もあったため作り直した。

### 敵の数

ダンジョンごとに `encounter.groupSize: { min, max }` で指定する（盤面上限 3 を超えない）。
書かなければ `data/enemies.js` の `defaultGroupSize` を使う。

### 出現レベル

**ダンジョンごと**にも**モンスターごと**にも設定できる。

```js
encounter: {
  levelRange: { min: 4, max: 8 },        // このダンジョンの既定
  table: [
    { species: "flamin", weight: 1.2 },  // 既定（Lv4〜8）で出る
    { species: "slime",  weight: 0.4, minLevel: 1, maxLevel: 6 }  // この種族だけ別枠
  ]
}
```

階ごとに変えたい場合は `perFloor` を書く（書いた項目だけが上書きされる）。

```js
encounter: {
  levelRange: { min: 1, max: 1 },
  groupSize:  { min: 1, max: 1 },
  table: [ ... ],
  perFloor: {
    "1": { levelRange: { min: 1, max: 1 }, groupSize: { min: 1, max: 1 } },
    "3": { levelRange: { min: 2, max: 4 }, groupSize: { min: 1, max: 2 } }
  }
}
```

レベルは**上から順に、最初に見つかったもの**を使う。

1. `table` の `minLevel` / `maxLevel` … モンスターごと
2. `perFloor` の `levelRange` … その階の指定
3. `encounter` の `levelRange` … その場所の既定
4. `data/enemies.js` の `defaultLevel` … 全体の既定（現在 Lv1）

敵の数と遭遇率も同じ順に探す（`perFloor` → その場所 → 全体の既定）。

### 戦闘中の表示

- **敵のレベルは表示しない**（味方のみ表示）
- 味方は**HPバーの下にPPバー**を出す。数値も左にPP・右にHPで並べる
- PPバーは残量で色が変わらない（`theme.ppBarColor`）。**色が変わるのはHPだけ**なので、
  減っていても危険かどうかをHPの色だけで判断できる
- 技を選ぶときは、左のメッセージ欄に**属性・威力・命中・PP・説明**が出る。
  道具を選ぶときも同じ場所に説明が出る（文言は `data/skills.js` / `data/items.js` の `description`）

### 戦闘の終わり方

| 結果 | 経験値 | ドロップ | 戻る先 |
|---|---|---|---|
| `win`（全滅させた） | あり | あり | 探索 |
| `scouted`（スカウト成功） | なし | なし | 探索 |
| `flee`（逃走成功） | なし | なし | 探索 |
| `lose`（全滅した） | なし | なし | 拠点（HP全回復） |

## アイテムドロップ

倒したモンスターが落とすアイテムは `data/monsters.js` の `drops` で指定する。

```js
drops: [
  { item: "herb", rate: 0.07, min: 1, max: 1 }
]
```

- `rate` は落とす確率（0〜1）。**各エントリを独立して判定する**ので、1体から複数種類が同時に落ちることもある
- `min` / `max` は個数の範囲（省略時は1個）
- 複数体倒した場合、同じアイテムはまとめて表示される
- 持ち物がいっぱいで入らなかった場合は「持ちきれなかった」と表示される

判定は `js/systems/DropSystem.js` が行う。戦闘に依存しないので、宝箱や採取など別の入手経路にも使える。

**現在の設定**

| モンスター | 落とすもの | 確率 |
|---|---|---|
| スライム | 薬草 | 7% |
| コケネズミ | 薬草 | 8.5% |
| キノコン | 薬草 | 10% |
| イワゴロー | 鉱石のかけら（1〜2個） | 15% |
| ヒカリムシ | 光る鱗粉 | 16.67% |
| モスゴーレム（坑道の主） | 苔むした核 | 100% |

**素材アイテムの所持上限**：鉱石のかけら 99／光る鱗粉 99／苔むした核 99

## 図鑑画面

**モンスター／アイテム／特性／性格／加護**を **←→** で切り替える（タブのクリックでも切り替わる）。

| 表 | 中身 | 伏せるか |
|---|---|---|
| モンスター | 出会った相手 | 未発見は ??? |
| アイテム | 手に入れたもの | 未入手は ??? |
| 特性 | 持っている仲間がいる特性 | 未判明は ??? |
| **性格** | ステータス補正の一覧 | **最初から全部見える** |
| **加護** | 効果と出やすさの一覧 | **最初から全部見える** |

性格と加護は「集めるもの」ではなく**確認するための一覧**なので伏せていない。
加護は今後ショップでの購入や厳選を予定しているため、
どんなものがあるかを先に見られるほうが計画を立てやすい。

説明が枠に入りきらないときは、**決定キーで詳細にカーソルを移し、↑↓で読み進める**（Esc または決定で一覧へ戻る）。続きがあるときは枠の右端に ▲▼ が出て、読んでいる間は色が変わる。

**マウスなら、説明の上でホイールを回すだけで読み進められる**（読むモードに入らなくてもよい）。

- 右の詳細は「行の配列」を組み立ててから、枠に入る分だけ描いている。
  項目を増やしても**はみ出さず、自動でスクロールできる**
- モンスターの詳細では、0でない**耐性が属性の色つきで並ぶ**
- スプライトは枠の上部に固定し、その下だけがスクロールする
- 折り返す文字数は `data/ui.js` の `dex.detail.charsPerLine`

## アイテムを追加するとき

`data/items.js` に1エントリ足すだけでよい。

```js
antidote: {
  id: "antidote", name: "解毒薬", category: "heal",
  description: "毒を消す薬。", maxStack: 99,
  effect: { type: "healHp", value: 0 },   // 効果の種類は ItemUsage が処理する
  usableIn: ["home"]
}
```

- 新しい**効果の種類**を足すときは `js/systems/ItemUsage.js` の `EFFECT_HANDLERS` に関数を1つ追加する。
- `usableIn` に `"battle"` を入れると戦闘中の「道具」コマンドに出る。`"home"` は拠点の持ち物画面。
- ゲーム中にアイテムを渡すときは必ず `game.giveItem(itemId, count)` を使う（持ち物と図鑑が同時に更新される）。仲間を加えるときは `game.addMonster(monster)`。

未実装の項目を有効にするときは、`js/scenes/HomeScene.js` 冒頭の `MENU_ITEMS` で
その項目の `ready` を `true` にし、`_openFeature` に処理を追加する。
項目の並び順や表示名も同じ場所（並び順は `MENU_ITEMS`、表示名は `data/messages.js` の `home`）で変更できる。

## 設定画面

拠点の「設定」から開く。左でゲーム設定を調整し、右で操作キーを確認する。

| 項目 | 内容 |
|---|---|
| 戦闘速度 | **8段階**（最も遅い〜最速）。演出の進む速さが変わる |
| スクロール速度 | **5段階**（1行ずつ〜5行ずつ）。マウスのホイールを1段回したときに動く行数 |
| 全体音量 / BGM音量 / 効果音量 | 0〜100%（音声は未実装） |

- 設定値は localStorage に保存され、次回起動時も引き継がれる
- 操作キーの一覧は `data/keys.js` の内容をそのまま表示するため、キーを変えれば表示も自動で変わる
- **音声システムは未実装**のため、音量は現在「保存されるだけ」（画面にもその旨を表示）

設定項目を増やすときは `data/settings.js` の `items` に1エントリ足すだけでよい。

```js

  min: 1, max: 5, step: 1, default: 3 }
```

## 起動方法

`app.html` を **ダブルクリック** して開くだけで動作します（ローカルサーバ不要）。

> **ファイルの読み込みについて**
> `app.html` はスクリプトを配列で並べて読み込んでいる。
> 通常の `<script src="...">` だと、ブラウザが**古いファイルを使い回して**
> 「一部だけ古い処理が動く」という分かりにくい不具合が起きるため、
> 読み込みごとに変わる印（`?t=...`）を付けて必ず最新が読まれるようにしている。
> ファイルを追加したときは `app.html` の配列に**順番を守って**足すこと。

> `file://` での動作を優先しているため、データは `.json` ではなく `data/*.js` として持っています。
> 各データファイルは `MyGame.rawData` に登録され、`DataLoader` → `GameData` を通して参照されます。

## ボスを追加するとき

`data/bosses.js` にエントリを足し、`data/dungeons.js` の `boss` からそのidを指すだけでよい
（コードの変更は不要）。

```js
frostLord: {
  id: "frostLord", species: "kingSlime", level: 32, title: "凍える王",
  canScout: false, canFlee: false, isFinal: false
}
```

- `species` は `data/monsters.js` の種族id。ボス専用の種族を追加してもよい。
- `canScout` / `canFlee` が false のときは、戦闘コマンドからその項目自体が消える。
- ボスは**そのダンジョンの最深階**に出る（何階かは `data/dungeons.js` の `floors`）。
- `isFinal: true` のボスを倒すとエンディングへ。false ならクリア記録を付けて拠点へ戻る。

## マウス操作

キーボードと同じことをマウスでもできる。**どちらで操作してもよく、混ぜて使える**。

| 操作 | 内容 |
|---|---|
| 重ねる | その項目・行・相手に選択が移る |
| 左クリック | 決定（重ねているものを選ぶ） |
| 右クリック | 取り消し・戻る（Esc と同じ） |
| ホイール | 一覧の上では選択を上下、図鑑の説明の上ではその説明をスクロール |

> **ホイールは端で止まる**（回り込まない）。いちばん下まで送ったつもりが先頭へ戻ってしまい、
> どこを見ていたか分からなくなるため。キーボードの ↑↓ は今までどおり端で折り返す。

ホイール1段で動く行数は、**設定画面の「スクロール速度」**（1〜5行）で変えられる。
`Input` が設定を見て `pointer.wheel` を倍にするので、**一覧にも図鑑の説明にも同じだけ効く**。
| 「戻る」ボタン | 各画面の右下。1つ前へ戻る（Esc と同じ） |

**「戻る」ボタン**は全画面の同じ位置（右下）に出る。カーソルを重ねると色が変わる。
途中の状態（ショップの個数選び・工房の確認・装備の選択など）で押すと、画面を閉じずに**1つ前へ戻る**。
位置は `data/ui.js` の `theme.backButton` で全画面まとめて変えられる（部品は `js/ui/BackButton.js`）。

対応している場所：

- 拠点・タイトルなどの**縦並びメニュー**（`CommandMenu` を使う画面すべて）
- 持ち物・図鑑・ショップ・工房・装備選択などの**一覧**（`ScrollList` を使う画面すべて）
- 図鑑とショップの**タブ**、仲間画面の**連れていく／預かり所の切り替え**
- 仲間・預かり所の**行**、ダンジョン選択の**行**
- 戦闘の**コマンド／技／道具**、**狙う相手**（敵の絵かHP欄を押す）
- 戦闘のメッセージ送り（画面のどこを押しても進む）

### 作りについて

マウスの状態は `js/core/Input.js` が持つ。**キーボードと同じ入り口（`game.input`）から見えるので、
画面ごとにマウス用の処理を書き足さなくてよい**。

- 位置は**キャンバス座標に直してから**渡すので、画面が拡大縮小されていても
  `data/ui.js` に書いた座標とそのまま比べられる
- 当たり判定は `Panel.containsPoint(rect, point)` で共通化してある
- **カーソルを動かしたときだけ**選択が移る。置いたままキーボードで操作しても邪魔にならない
- 一覧は `ScrollList.clickedEntry(input)` が「行が押されたか」を返すので、
  呼び出し側は `決定キー または クリック` と書くだけでよい

> まだ対応していないもの：ダンジョン内の移動（クリックで移動するには経路探索が要る）、
> ショップの個数指定。いずれもキーボードで操作できる。

## 操作方法

- 移動: `W A S D` または 矢印キー
- 決定: `Enter` / `Space` / `Z` / **左クリック**
- キャンセル / 戻る: `Esc` / `X` / **右クリック**（探索中は拠点へ、拠点ではタイトルへ）
- パーティ編成: `P` / `Tab`（探索中）
- 預かり所へ預ける: `Q`（仲間画面）
- 装備を着け替える: `E`（仲間画面）
- セーブ: `F`（探索中）／ロードはタイトルの「つづきから」
- ダンジョン再生成（確認用）: `R`

## 開発方針

- 数値（HP・攻撃力・出現率・捕獲率・スキル威力など）は `data/` のデータファイルで管理する。
- モンスター・スキル・アイテム・敵・ボス・特性はデータ駆動。追加はデータファイル編集だけで対応できる構造にする。
- ロジックと描画を分離し、責務ごとにファイルを分割する。
- グローバル変数を極力使わない（`MyGame` 名前空間 + IIFE）。
- 小さな機能単位で実装し、毎回動作確認できる状態を保つ。
- データ管理部分（DataLoader/GameData）は分離しており、将来 JSON へ移行しやすい。
