# ABYSS CHRONICLE

**世界名: Monstoria**　／　ジャンル: モンスター育成 × ローグライク

深淵（Abyss）へ挑み、モンスターを仲間にしながら最深部を目指す。
挑む場所は**ステージ選択**で選び、マップは毎回ランダム生成される。仲間やアイテムも毎回異なる。

> ゲーム名・世界名は `data/config.js` の `gameTitle` / `worldName` で管理している。

**現在のバージョン: α-2**（更新履歴は `data/patchnotes.js`。タイトル画面の「パッチノート」から読める）

HTML / CSS / JavaScript のみで開発（フレームワーク・ライブラリなし、ES6以降）。

## 画面の流れ

```
タイトル ──[新しく始める]──▶ 拠点 ──[ダンジョンへ潜る]──▶ ダンジョン選択 ──[挑む]──▶ 探索
   ▲          (※確認あり)     │  ▲                    ▲              │           │
   └────[Esc]─────────────────┘  │                    └──[Esc]───────┘           │
   │                              └──────────[Esc / 全滅]────────────────────────┘
   └──[続きから]──▶ 拠点（セーブした仲間・持ち物・図鑑・クリア済みを引き継ぐ）

※「新しく始める」は、セーブデータがある場合のみ「はい / いいえ」の確認が出る
　（既定は「いいえ」。この時点ではセーブデータは消えない）

探索 ──[敵と遭遇]──▶ 戦闘 ──▶ 探索
探索 ──[仕掛けを踏む]──▶ 宝箱 / 罠 ──▶ 探索
探索 ──[泉を踏む]────▶ 使う / やめておく ──▶ 探索
探索 ──[階段]────▶ 降りる / 拠点へ戻る / まだ潜る を選ぶ
探索 ──[降りる]───▶ 加護を選ぶ ──▶ 探索（次の階）
探索 ──[帰る・全滅]─▶ 結果 ──▶ 拠点
拠点 ──[持ち物 / 図鑑 / 設定]──▶ 各画面 ──▶ 拠点
探索 ──[P/Tab]────▶ なかま（並び替え・装備）──▶ 探索
探索 ──[I]───────▶ もちもの（回復アイテムを使う）──▶ 探索

探索 ──[最後のボス撃破]──▶ エンディング ──▶ タイトル
```

## パッチノート

タイトル画面の「パッチノート」から開く。**左にバージョンの一覧、右にその内容**を出す。
過去のバージョンも同じ操作で読み返せる。

項目の種類は**色つきの札**で示し、上部に凡例を出す。

| 札 | 色 | 意味 |
|---|---|---|
| 追加 | 緑 | 新しく増えた要素 |
| 調整 | 黄 | 数値のバランス調整 |
| 変更 | 水色 | 仕様や操作の変更 |
| 修正 | 赤 | 不具合の修正 |
| 削除 | 灰 | 取り除いた要素 |

| 操作 | 内容 |
|---|---|
| ↑↓ | 左でバージョンを選ぶ／右で読み進める |
| →・決定 | 内容側へ移る |
| ← | バージョンの一覧へ戻る |
| ホイール | **カーソルが乗っている側**をスクロール |

### 更新履歴を足すとき

`data/patchnotes.js` の `versions` の**先頭**に1エントリ足すだけでよい。

```js
{
  version: "α-2", date: "2026-08-20",
  summary: "ひと言でどんな更新か",
  entries: [
    { type: "added",   text: "新しく増えたもの" },
    { type: "balance", text: "数値の調整" }
  ]
}
```

種類（`types`）を増やすときも同じファイルに1エントリ足すだけで、
**色つきの札と凡例に自動で反映される**（画面のコードは変更不要）。

## ゴールドと装備

ローグライクの土台として、**3つの時間軸**で持ち物を分けている。

| 時間軸 | 何が該当するか | 全滅したとき |
|---|---|---|
| 1回の挑戦の中だけ | **加護**（階を降りるたびに選ぶ強化） | 消える |
| 拠点に持ち帰れば残る | アイテム・素材 | そのランで拾った分を失う |
| ずっと残る | **ゴールド・装備** | **失わない** |

### ゴールド

- 敵を倒すと手に入る（`data/monsters.js` の `goldReward`）
- **相手のレベルが高いほど多い**（`data/growth.js` の `goldRewardPerLevel`、現在 0.15）
  もらえる量 = `floor( goldReward × (1 + (相手のLv - 1) × 0.15) )`
- 最初の所持金は `data/player.js` の `startingGold`（現在 50G）
- 全滅しても失わない。拠点の右上に常に表示される

| モンスター | 基準 | Lv5 | Lv8 |
|---|---|---|---|
| スライム | 4 | 6 | 8 |
| コケネズミ | 6 | 9 | 12 |
| キノコン | 9 | 14 | 18 |
| 坑道の主（Lv8） | 60 | — | 123 |

### 装備

**装備はアイテムの一種**として `data/items.js` に置いてある。こうすると持ち物・ドロップ・図鑑・
（今後の）ショップが**すべて同じ仕組みで扱える**ので、装備専用の処理を増やさずに済む。

```js
stoneBand: {
  id: "stoneBand", name: "石の帽子", category: "equipment",
  description: "ずしりと重い石の帽子。かぶると守りが上がる。",
  maxStack: 9, effect: null, usableIn: [],
  equip: {
    slot: "armor",   // weapon / armor / accessory
    effects: [
      { type: "statBonus",      stat: "defense", value: 4 }
    ]
  }
}
```

- **効果の書き方は特性とまったく同じ**。`statBonus`（加算）だけが装備用に追加された種類
- 拠点の「仲間」画面で仲間を選び、**「装備」**を選ぶと着け替えの一覧が開く（**E キー**でも直接開ける）。
  1つも持っていない場合も画面は開き、その旨を表示する
- **選んでいる装備にしたときのステータスの変化が、その場で「8 → 5」の形で出る**。
  上がる値は緑、下がる値は赤。外すときも同じように確認できる
- 着けると持ち物から減り、外すと持ち物へ戻る。同じ装備を `maxStack`（9個）まで持っているときだけ外せない（装備が消えないように）

### 装備枠は4つ（α-7）

1体につき **武器1・防具1・アクセサリー2**（`data/config.js` の `equipSlots`）。
各装備がどの枠かは `equip.slot`。書いていない装備はアクセサリー扱い。

- 着け替えの一覧は枠ごとに見出しで分かれ、「武器 1/1」のように埋まり具合が出る
- 枠が埋まっている装備を選ぶと、**その枠でいちばん古いもの**と入れ替わる（外したものは持ち物へ戻る）
- **同じ装備は2つ着けられない**（`Game.equipItem` が `duplicate` で止める）。
  アクセサリー枠が2つあっても、同じ指輪を重ねて効果を倍にはできない
- `EffectSystem.getEquipments` も同じ決まりで数えるので、データを直に触られても枠を超えた分は効かない
- 仲間画面の装備欄は「武器：灼牙の戦刃」「防具：-」のように**空いている枠も出す**
- 古いセーブ（1枠）はそのまま読める。装備の種類から枠へ振り分けられる

> **数値は4枠前提で下げてある。** 1枠のころの値（攻+11、防+13 など）は、
> 武器＋アクセサリー2つで足し合わさると序盤で敵を一撃にしてしまう。
> `statBonus` はレベルで増えないので、序盤ほど効きが大きい。

### 倒して手に入る装備

`data/monsters.js` の `drops` に書くだけでよい。**装備もアイテムの一種**なので、
素材や薬草とまったく同じ書き方で落とせる（`DropSystem` は変更していない）。

```js
drops: [
  { item: "oreShard",  rate: 0.15, min: 1, max: 2 },
  { item: "stoneMail", rate: 0.08, min: 1, max: 1 }   // 装備も同じ書き方
]
```

**落とすものは図鑑で確認できる。** ただし「一度でも仲間にした」種族だけ。

```
落とすもの
・黄泉竜の鱗  35%
・深淵の欠片  28%
・竜牙の指輪  20%
```

- 見ただけの種族では**見出しごと出ない**（「（未加入）」で止まる）
- 一度仲間にすれば、**まだ拾ったことのない品まで全部見える**。
  何が取れるか分からないまま同じ相手を倒し続ける、という状態を避けるため
- 何も落とさない種族（コウモリなど）では、見出しごと出ない

**確率はそのモンスターの出現率で薄まる。** 落とす確率だけを見て決めないこと。

### ★ 見るのは「戦闘あたり」ではなく「挑戦（ラン）あたり」

1回の挑戦で戦う回数はダンジョンごとに違う（実測：坑道 6.4戦／亀裂 9.2戦／深層 10.2戦。
宝箱を拾いながら歩いた場合。最短で階段へ向かうと 2.3／3.4／3.9戦）。
**同じ「50戦に1つ」でも、坑道なら8回・深層なら5回の挑戦**になる。

| 装備 | 落とす確率 | 1つ手に入るまで（率を上げる前の実測） |
|---|---|---|
| 風乗りの羽飾り | ハイバネ 13% | 6%のとき 41戦 ＝ 4回の挑戦（亀裂） |
| 帯電の芯 | ビリムシ 15% | 7%のとき 46戦 ＝ 5回（深層） |
| 岩鎧の欠片 | イワゴロー 19% | 13%のとき 52戦 ＝ 8回（坑道） |
| 髑髏の護符 | ヌマボネ 16% | 5%のとき 約5回（毒沼） |
| 竜牙の指輪 | ヨミリュウ 20% | 77戦 ＝ **8回**（深層） |

> **α-8 で、落とす装備の率をまとめて上げた**（岩鎧 13→19%・風の羽飾り 6→13%・
> 帯電の芯 7→15%・髑髏の護符 5→16%）。上の「1つ手に入るまで」は上げる前の実測なので、
> いまはおおむねその半分の回数で手に入る。**率を触ったらランあたりで測り直すこと。**

> **竜牙の指輪だけ確率が飛び抜けているのは、竜そのものが出ないから。**
> B4Fにしか出ず、しかも単体出現。「レアな相手」×「レアなドロップ」で二重に薄まる。
> 5%だったころは実測 **417戦＝27回の挑戦**（他の3つは4〜8回）で、
> 竜を約20体倒す計算だった。20%なら竜5体で1つになる。
>
> 当時のコメントには「約130戦に1つ」と書いてあったが、
> これは竜の出現率を通していない数字で、実際は3倍以上厳しかった。
> **率を触るときは必ずランあたりで測り直すこと。**

素材のほうも、坑道だけ薄かったので底上げしてある
（薬草 7〜10%→12〜15%、鉱石 15%→25%、光る鱗粉 16.7%→25%）。
坑道は1回の挑戦で6.4戦しかないぶん、同じ率でも渇いて感じるため。

> 入手経路は**ショップで買う・工房で作る・低確率でドロップ**の3つ。すべて実装済み。

## BGMと効果音

音源ファイルは `assets/audio/` に置き、`data/audio.js` に1行書くだけ。コードは触らない。

```js
bgm: { title: { file: "title.mp3", volume: 0.7 } },
se:  { hit:   { file: "hit.wav",   volume: 0.6 } }
```

### 音源が無くても動く

`file` を書いていない音、読み込めなかった音は**黙って無音になる**。
エラーも出ず、ゲームも止まらない。**音源を1つも置いていない状態でも今までどおり遊べる。**

一度失敗した音は覚えておき、二度と読みに行かない。毎フレーム読みに行って失敗が積み上がるのを防ぐため。

### `new Audio()` で鳴らす（Web Audio を使わない）

Web Audio の `decodeAudioData` は `fetch` が要る。**`fetch` は `file://` では止められる**ので、
ダブルクリックで起動したときに音だけ鳴らないことになる。
このゲームは `file://` での起動を大事にしているので、音声要素で鳴らす方を選んだ。

### 最初の操作まで鳴らせない

どのブラウザも、**一度も触られていない画面では音を鳴らさない**。
タイトルでいきなり `playBgm` しても、そこでは鳴らない。

そこで鳴らせなかったBGMを覚えておき、**最初のクリックかキー入力**で鳴らし直す。
その1回目を捕まえるのは `Game._update` の1行（`input.isAnyPressed()`）。
場面ごとに書くと入れ忘れるので、入力を見ている場所に集約してある。

### 決まりごと

| | |
|---|---|
| 同じBGMは鳴らし直さない | 拠点 → 仲間・持ち物・設定 → 拠点 で曲が途切れないように。店と工房は自分の曲を持つ（`shop` / `craft`）ので、入ると切り替わり、戻ると拠点の曲が頭から流れる |
| 効果音は1種類につき4個まで重なる | 複数体が同時に殴られる場面がある。1つだと頭に戻ってしまう |
| `solo: true` の効果音は重ねない | メニュー音（決定・キャンセル・カーソル）。連打で4つ重なって膨らむのを防ぐ。鳴っていても頭から鳴り直す |
| 音量 | `素材のvolume × 全体音量 × BGM（または効果音）音量` |
| 素材ごとの音量差 | `data/audio.js` の `volume` で吸収する。設定はプレイヤーの好みだけに使う |

### 種類を増やす —— コードを触らずにできること

| やりたいこと | 書く場所 |
|---|---|
| 同じ場面で音を散らす（毎回ランダム） | `file: ["hit1.wav", "hit2.wav"]` と配列で書く |
| ダンジョンごとのBGM | `bgm` にidを足し、`data/dungeonThemes.js` の `bgm` から指す |
| 主ごとのBGM | `bgm` にidを足し、`data/bosses.js` の `bgm` から指す |
| 技ごとの効果音 | `se` にidを足し、`data/skills.js` の `se` から指す |
| 仕掛けごとの効果音（宝箱・泉・罠） | `se` にidを足し、`data/features.js` の `se` から指す |
| 状態異常ごとの効果音（毒・麻痺・眠り） | `se` にidを足し、`data/statuses.js` の `se` から指す |
| 当たった音を演出の型で変える（打撃／斬撃） | `se` にidを足し、`data/effects.js` の `shapes` の `hitSe` から指す |
| 決定・キャンセル・カーソル・失敗の音 | `data/audio.js` の `ui`（どのキーがどの音か） |

- 配列の音は**使い回さず毎回作り直す**（同じ Audio を使い回すと同じファイルしか鳴らない）。
  1つだけの音は今までどおり使い回す
- 技の音は**技を出した瞬間**に鳴る。**`se` を持つ技は、当たったときの打撃／斬撃音を鳴らさない**（炎の音のあとに「ドン」が来るのは変なので、技の音だけで完結させる。`BattleScene._hitSeFor` が `null` を返す）。
  属性の基本技はそれぞれの属性の音（`fire` / `water` / `wind` / `earth` / `thunder` / `light` / `dark`）、シャインは `shine`、
  火の息は `fireBreath`、奈落の息は `darkBreath`、どくのいきは `venomBreath`、あわは `bubble`、ボディプレスは `bodyPress`、どくばりは `venomSting`。
  体当たり・噛みつく・吸血と、回復・強化・弱体の技（キュア・こうか・ちからぬき）は出した瞬間の音は無く、当たったとき／効いたときの音だけ
  （体当たりは打撃音、噛みつく・吸血は斬撃音）
- **当たった音**（`se` の無い技だけ）は演出の型で決まる（`BattleScene._hitSeFor`）。`slash` 型は `slash`（斬撃）、それ以外は `hit`（打撃、2つからランダム）。技に `hitSe` を書けば上書きできる（`"hit"` / `null`）。
  通常攻撃は種族の `attackEffect`（`data/monsters.js`）で型が決まるので、コウモリ・マグマウルフ・ハイバネ・フレイミン・ヨミリュウの通常攻撃は斬撃音になる。
  会心も同じ音（専用の音は付けない、と決めてある）
- **回復の音（`heal`）は回復ぜんぶ共通**：技のHP回復・吸血・道具のHP／PP回復・状態異常を治す（戦闘中も持ち物画面からも）。
  道具の出来事は `se: "heal"` を持つので、HP回復のぶんで二重には鳴らない
- **強化／弱体**は掛かった瞬間に `buff` / `debuff`（`modifier` の出来事の `raised` で分ける）
- **外れた音（`miss`）**は 命中しなかった・かわされた・無効（`immune`）・状態異常が効かなかった（`statusImmune` / `statusMiss`）。「いまひとつ」（`resisted`）は音なし
- **逃げる音（`flee`）**は成功でも失敗でも鳴る（「逃げようとした」音）
- **できなかったときの音（`ui.error`）**は `game.playError()` で鳴らす。**その操作の決定音の代わりに**鳴る（重ならない）。
  いまは戻る音と同じファイル。お金が足りない・使えない道具・装備できない・預かり所がいっぱい・作れない・
  空のセーブファイル・加護の上限・戦闘中の「逃げられない」「PPが足りない」「控えがいない」などで鳴る
- 状態異常の音は**掛かった瞬間**（`status` の出来事）と**ターン終了時の毒ダメージ**（`statusDamage`）で鳴る。
  7種すべてに音がある。`se` を消せば無音。探索中に歩いて受ける毒ダメージでは鳴らさない
- 毒のダメージは攻撃と同じく**見せた瞬間にHPバーが減る**（以前は結果を見せ終わるまで減らなかった）。
  数字は緑で、画面は揺らさない（`ui.battle.animation.styles.statusDamage`）

**新しい場面で鳴らしたいとき**（宝箱が空だった、など）だけは、
その瞬間のコードに `game.audio.playSe("id")` を1行足す必要がある。
戦闘の出来事なら、画面側が作る出来事に `se: "id"` を持たせれば**見せた瞬間**に鳴る（スカウト成功がこの形）。

### 決定・キャンセル・カーソルの音は1か所で鳴らす

メニューの部品は多く（`CommandMenu`・`ScrollList`・各画面の直書き）、ひとつずつ足すと必ず鳴らない場所が残る。
そこで `Game._pickUiSound` が**入力そのもの**を見て、決定キー／クリック → `confirm`、
キャンセルキー／右クリック → `cancel`、矢印キー → `cursor` を鳴らす。
画面が `game.playError()` を呼んだフレームは、決めておいた音の代わりに `ui.error` を鳴らす（`_uiSoundOverride`）。

- **探索中は矢印が歩く操作**なので、`DungeonScene` は `silentCursor = true` でカーソル音だけ止めている
- 画面の切り替え中は鳴らさない（押しても何も起きない間）
- どの音を鳴らすかは画面を動かす**前**に決め、鳴らすのは**後**。
  前に決めるのは、決定で画面が切り替わると「切り替え中」になって鳴らせなくなるため。
  後に鳴らすのは、設定で効果音量を変えた直後のカーソル音を、**変えた後の大きさ**で聞かせるため

いま鳴る場所：決定・キャンセル・カーソル・失敗（全画面）、宝箱（`chest`）・泉（`spring`）・罠、階段、セーブ（拠点・中断・初クリア）、買う・売る（`buy`。加護を買うのは決定音だけ）、
作る（`itemGet`）、帰還の石（`escape`）、逃げようとした（成功・失敗とも）、倒れる、状態異常7種（掛かった瞬間と毒のダメージ）、打撃・斬撃・回復・強化・弱体・外れ、技を出した瞬間（属性・息・あわ・ボディプレス・どくばり）、レベルアップ（これだけ合成音）。
**音を付けない、と決めてあるもの**：会心・いまひとつ・スカウトの成否・防御・入れ替え・状態異常が解けた・動けなかったターン・主の登場・戦闘後の経験値やドロップ・初クリア・図鑑の新登録・加護の切り替えと購入（決定音だけ）。
即死で倒れたときは `death.wav` が倒れる音を兼ね、直後の `faint` は鳴らさない（`faint` の出来事に `statusId` が付いていて、その状態異常が `se` を持つとき）

### 合成の効果音（ファイルを置かない音）

`file` が無く `synth` がある効果音は、ゲームが **Web Audio で波形から作って鳴らす**（`AudioManager._playSynth`）。
ファミコン風の電子音になる。`file` を書けばそちらが優先されるので、素材に差し替えるときは `synth` を消さなくてよい。

```js
hit: { file: null, volume: 0.45, synth: [
  { kind: "noise", filterFrom: 1400, filterTo: 200, duration: 0.11, gain: 0.7 },
  { kind: "tone", wave: "square", from: 180, to: 70, duration: 0.10, gain: 0.35 }
] }
```

- 1つの音は**層（layer）の配列**。`tone`（波形 `wave`、周波数 `from` → `to`）と `noise`（フィルタの周波数 `filterFrom` → `filterTo`、`filterType` は `lowpass`（既定）/ `highpass` / `bandpass`）の2種類
- `start` で鳴り始めをずらせるので、3音のアルペジオ（レベルアップ）も層を並べるだけ
- `attack`（何秒かけて膨らむか）と `hold`（最大のまま何秒保つか）で形を作れる。落ち方は速い（0.001 への指数減衰）ので、伸ばしたい層は `hold` を書く
- どの層も鳴り終わりに向けて音量が 0 へ落ちる（ぶつ切りにならない）
- いま波形から作っている音：`levelUp` だけ。`miss` は合成の指定を残したまま `file`（`se_miss.wav`）を優先。`fireSynth` は炎を波形で作った見本（どの技からも指していない。`file` を外して `synth` を残すとこの音になる）
- `AudioContext` は最初に鳴らすときに作る（操作前に作ると止められる）。使えない環境では黙って鳴らない
- 音量は他の効果音と同じ式（`volume × 全体 × 効果音`）

### BGMのフェード

曲が切り替わるとき、前の曲は `fadeMs`（600ms）かけて消え、次の曲は 0 から同じ時間で上がる（クロスフェード）。
`playBgm` は前の Audio を `_fadeOut` に渡して手放し、新しい Audio を `_fadeIn` する。
設定で音量を変えたときは `_bgmTarget` を書き換えるだけで、出はじめの途中なら `_fadeIn` が追いつく。

### 素材のクレジット

## 主人公の名前・服の色・性別・一人称

新しく始めるとき（セーブファイルを選んだ直後）に決める。拠点の**「設定」→「名前と見た目」**から
いつでも変えられる。**どちらも同じ画面**（`PlayerSetupScene`）で、違うのは
やめたときの戻り先だけ（`mode: "new"` / `"edit"`）。

**4つともセーブファイルごとに別々。** 設定（`SettingsManager`）に持たせていないのは、
3つのファイルで別の冒険をしているのに名前だけ共通になってしまうため。保存先はセーブデータ
（`playerName` / `playerColor` / `playerGender` / `playerFirstPerson`）。

| 欄 | 選び方 | 選択肢の置き場所 |
|---|---|---|
| なまえ | 決定で文字盤を開く | `data/naming.js` |
| ふくの色 | ←→ か色見本を押す | `data/player.js` の `appearance.colors` |
| 性別 | ←→ か札を押す | `data/player.js` の `genders`（男性・女性） |
| 一人称 | ←→ か札を押す | `data/player.js` の `firstPersons`（私・僕・俺・あたし・うち・自分） |

- **性別と一人称はゲームの進み方に何も影響しない**（ストーリー構成.md の 2）。組み合わせも自由
- 一人称は物語の台詞の `{me}` に差し込まれる（`StoryScene._fill`）
- 古いセーブには無いので、既定（`defaultGender` / `defaultFirstPerson`）になる
- 札は1行に6つまで（`data/ui.js` の `playerSetup.chip` の幅）

### 色を増やすのに絵は要らない

`data/player.js` の `appearance.colors` に1つ足すだけ。
`js/systems/PlayerLook.js` が起動時に、**もとの絵のパレットの3色だけを差し替えた写し**を作る。

```
playerWalk1 ＋ 赤 → playerWalk1_red
```

| | |
|---|---|
| 差し替える色 | `colorKeys` の base / light / shadow の**3つで1組** |
| 触らない色 | 輪郭・肌・髪 |
| 作られる枚数 | 色 × コマ数（いまは 6色 × 2コマ = 12枚） |

> **3色まとめて替えるのが要点。** 地の色だけ替えると影と光の面が青いまま残り、
> 赤い服に青い影がついて濁る。

**呼ぶ場所に注意。** `js/main.js` で `AssetLoader.build` の**前**に
`PlayerLook.buildVariants(gameData)` を呼ぶ。絵を組み立てたあとに足しても描画物が作られない。

### 設定から開く項目の作り方

`data/settings.js` に `type: "action"` の項目を書くと、数値ではなく
「別の画面を開くボタン」になる。

```js
{ id: "playerLook", label: "名前と見た目", type: "action", action: "playerSetup" }
```

- 左右では変わらない。**決定（またはクリック）で `action` の画面が開く**
- 横棒の代わりに**いまの中身**が出る（`ゆうし / 紫`）
- 開く先を増やすときは `SettingsScene._activate` に `case` を1つ足す

## 地図を歩く主人公

**向きを持たない（カニ歩き）。** 上下左右どちらへ動いても正面を向いたまま横へずれていく。
ファミコンのドラクエ1と同じ作り。

理由は2つ。**4方向ぶん描くと絵が4倍になり、直すたびに4枚直すことになる**のと、
32pxでは後ろ姿と横向きが見分けられないため。顔がいつも見えているほうが、
誰を動かしているのかも分かりやすい。

### 2枚で歩かせる

`playerWalk1` と `playerWalk2` は **足の位置が1pxずれているだけ**で、上半身はまったく同じ。
交互に出すと下半身だけが左右に振れて、横歩きして見える。

コマの切り替えは**すでにある仕組み**（`data/motions.js` のコマ絵）に任せている。

```js
// data/player.js
appearance: {
  sprite: ["playerWalk1", "playerWalk2"],  // 並べて書くとコマ絵になる
  walkMotion: "playerWalk",                // 歩いているあいだ
  idleMotion: "breathe"                    // 立ち止まっているあいだ
}
```

```js
// data/motions.js
playerWalk: {
  frames:  { interval: 150 },
  offsetY: { amplitude: -1, period: 150, wave: "bounce" }
}
```

- 跳ねる `period` は `interval` と**同じ**にしてある。足が入れ替わる瞬間に体がいちばん高くなる
- 立ち止まると `idleMotion` に切り替わる。コマ絵の指定が無いので**1コマ目で止まる**。
  ずっと足を動かし続けさせたいなら `idleMotion` を `"playerWalk"` にすればよい
- 歩いているかどうかは **`player.isSettled()`**（見た目の位置が本当の位置に追いついたか）で見る。
  歩数を数えたりタイマーを持ったりしていない

### 見た目はプレイヤーの持ち物

`Player.js` は**位置だけを預かる**入れ物にしてある。絵も動きも `data/player.js` の
`appearance` にあり、描く側（`DungeonScene._renderPlayer`）が読む。
絵を差し替えるのにコードを触らなくて済む。

> 以前は `Player.spriteId = "player"` とコードに書いてあり、
> 動きは `data/ui.js` の `dungeon.playerMotion` にあった。
> 見た目が2か所に分かれていたので、`data/player.js` へまとめた。

## セーブファイル（スロット）

**3つある。** 数は `data/save.js` の `slotCount` で決まる。

### キーの付け方 —— スロット1だけ特別

```
スロット1 … my-first-app.save          ← 昔からのキーをそのまま使う
スロット2 … my-first-app.save.slot2
スロット3 … my-first-app.save.slot3
```

**スロット1に番号を付けてはいけない。** 全スロットに `.slot1` のような番号を付けると、
**それまで遊んでいたセーブがどのスロットからも見えなくなる**。
判定は `SaveManager.keyFor()` の1か所だけ。

### 書き込む先の決まり方

保存の入口は `Game.saveProgress()` **ひとつだけ**。
`Game.setSaveSlot(n)` で向き先を変えておけば、拠点のセーブも初クリアの自動セーブも
同じファイルへ書かれる。**呼び出し側は何も知らなくてよい。**

スロットを決めるのは `SaveSlotScene` だけ（新規なら選んだとき、続きからなら読み込んだとき、
**拠点のセーブなら書く先を選んだとき**）。

### 拠点のセーブは書く先を選べる（α-8）

拠点の「セーブ」は `SaveSlotScene`（mode `"save"`）を開く。いま遊んでいるファイルが最初に選ばれている。

- 別の**中身入り**ファイルを選ぶと、赤字で「上書きします」
- 書けたら `save` の音が鳴り、少し見せてから拠点へ戻る（`ui.saveSlot.returnDelay`、既定 900ms）
- 書いた先が、以後のセーブ先になる（`setSaveSlot`）
- 書いたファイルに残っていた古い中断は消す（新しく始め直したときの、前の冒険の中断など）

### 探索中は「中断」（α-8）

**探索中にセーブは無い。** `F` で「中断」すると、問いかけのあと**中断データ**を書いてタイトルへ戻る。

```
スロット1 … my-first-app.save.suspend        ← セーブ本体（my-first-app.save）とは別のキー
スロット2 … my-first-app.save.slot2.suspend
```

- セーブ本体は書き換えない。中断データには、セーブと同じ中身に加えて
  **挑戦の記録（選んだ加護・拾ったもの・得たゴールド）とその階の仕掛け（開けた宝箱など）**も入る（`Game.suspendRun`）
- タイトルに**「中断したところから」**が出る（中断のあるファイルが1つでもあるとき、先頭に）
- 再開すると**中断データは消える**（`Game.resumeSuspended` → `clearSuspend`）。
  同じところから何度もやり直せない、ローグライクの中断と同じ扱い。
  途中で閉じると、最後の拠点セーブに戻る
- 「つづきから」で中断のあるファイルを選んでも、**中断のほう（新しい状態）から再開する**
- コピー・移動・削除は中断データも一緒に運ぶ／消す（本体と中断がずれないように）
- 中断だけあって本体が無い（拠点で一度もセーブせずに中断した）ファイルも、一覧に「中断中：〜」と出て再開できる

> それまでの「探索中セーブ」は、書いてはいたが**読むときに拠点へ戻していた**（`DungeonScene(game, def, savedState)` を呼ぶ側が無かった）。
> 中断がその役目を正しく引き継いだ。

### ファイルの整理（コピー・移動・削除）

「つづきから」の一覧で **「整理する」ボタン（または Q/E）** を押すと整理モードに入る。
同じ画面のまま、見出しと選べる相手だけが変わる。

| 段階 | phase | すること |
|---|---|---|
| ファイルを選ぶ | `list` | 中身のあるファイルだけ選べる |
| 何をするか | `action` | コピー／移動／削除／やめる |
| 行き先を選ぶ | `pick` | **空きも選べる**。元と同じファイルは選べない |
| 確認 | `confirm` | 消えるものがあるときだけ赤字 |

- **中身は一切読まずに、保存されている文字列をそのまま移す。**
  読み込んで組み立て直すと、いま遊べない形のデータ（古い形式）を移すときに壊れる
- **移動は「写してから消す」順で行う。** 先に消すと、書き込みに失敗したときに
  データが消えてなくなる（`SaveManager.moveSlot`）
- 消えるものがあるときだけ赤くする。**空きへのコピーは何も失わない**ので、
  そこまで赤くすると「危ない操作」の重みが薄れる
- 整理モードでは**読めないファイルも選べる**。消す・移すのに中身は要らない

> **`_canSelect()` の判定順に注意。** 「行き先を選んでいる最中か」を
> 整理モードの判定より**先**に見ること。逆にすると
> 「中身のあるものだけ選べる」が効いて、**空きスロットへコピーできなくなる**。

### 選択画面

「新しく始める」も「続きから」も `SaveSlotScene` を通る。違うのは2点だけ。

| | 選べる相手 | 選んだあと |
|---|---|---|
| `"new"` | **どれでも**（空きでも中身があっても） | 進行データを消して拠点へ |
| `"continue"` | **中身があって壊れていないものだけ** | 読み込んで拠点へ（中断があればそこから探索へ） |
| `"save"` | **どれでも** | そのファイルへ書いて拠点へ |
| `"resume"` | **中断のあるものだけ** | 中断したところから探索へ |

- **どちらも「はい／いいえ」を挟む。** 既定は「いいえ」
- 中身のあるファイルに新規で入るときは、**赤字で「上書きします」**と、
  消えるデータの中身（`スライム Lv5 のデータが消えます`）を出す
- **選んだ時点では書き込まない。** 実際に書くのは拠点のセーブか初クリアの自動セーブ。
  選んだ直後に消してしまうと、「間違えた」と思ってタイトルへ戻ったときには手遅れになる
- 一覧に出す中身は `SaveManager.peek()` が読む。**`load()` は使わない**
  （3つ並べるためだけにモンスターの個体を組み立てるのは無駄なので、
  保存された数値をそのまま読むだけにしてある）

### 一覧に出す情報

```
スロット1                           3時間45分   ← 合計プレイ時間
  スライム Lv12  ほか2体                  拠点   ← どこにいたか
  1240G   クリア 2                   9/23 14:08   ← いつ保存したか
```

`savedAt` / `party` / `gold` / `clearedDungeons` は元から保存されていた。
**「どこにいたか」（`dungeon.dungeonId`）と「合計プレイ時間」（`playTime`）は後から足した。**
どちらも古いセーブには無いので、その場合は「拠点」「0分」と出る。
**保存形式のバージョンは上げていない**（古いセーブが読めなくなるほうが困るため）。

#### 合計プレイ時間

`Game.playTime`（ミリ秒）を毎フレーム `dt` ぶん足し、セーブに含める。

- **`Game.clock` とは別に持つ。** `clock` は「起動してからの時間」で、
  ファイルをまたいで進み続ける。`playTime` は**読み込むとそのファイルの値に戻る**
- 新しく始めると 0 から（`SaveSlotScene._startNewGame`）
- 表示は分まで（1時間未満は「45分」、それ以上は「3時間45分」）。
  一覧で見るのは「どれだけ進めたファイルか」なので、秒は出さない
- 文は `data/messages.js` の `saveSlot.playTime` / `playTimeMin`

## タイトル画面

項目は **「新しく始める」「続きから」の2つ**。探索を中断したファイルがあるときだけ
**「中断したところから」が先頭に足される**（`enter` のたびに組み直す）。どれもセーブファイルの選択へ進む。

**パッチノートはメニューに置いていない。** 遊ぶための入口（始める・続ける）と読み物は
性質が違うため、右下のバージョン表記の隣に書のアイコンを置いた。

- ふだんは薄く（`idleAlpha`）、カーソルを乗せるとはっきり出る（`activeAlpha`）
- 乗せているあいだは**バージョン表記も一緒に明るくなる**。
  アイコンだけ光っても「どこが押せるのか」が伝わりにくいため
- 乗せたときだけ「パッチノート」という文字が出る
- 当たり判定はアイコンの四角そのもの（`data/ui.js` の `title.patchButton`）。
  位置を変えれば押せる場所も一緒に動く

## 遊び方の案内（チュートリアルとよくある質問）

**2本立てになっている。** 出るタイミングも役割も違う。

| | いつ出るか | 何を書くか | データ |
|---|---|---|---|
| **チュートリアル** | 初めてその場面に来たとき、勝手に出る | 操作を1つだけ。**5行まで** | `data/tutorial.js` |
| **よくある質問** | 拠点の「遊び方」を開いたとき | 詰まったときの答え。長くてよい | `data/help.js` |

### チュートリアル

初めてその場面に来たときだけ、ふきだしが出る。**一度見たら二度と出ない**（見た記録はセーブに残る）。

出る場面（`trigger`）は8つ。

| trigger | いつ |
|---|---|
| `homeReturn` | 初めて拠点の画面を開いた |
| `dungeonEnter` | 初めてダンジョンに入った |
| `battleStart` | 初めての戦闘（**戦い方・つづき・並び順の3つ**） |
| `enemyWeak` | 盤面の敵が半分以下まで弱った（スカウトの案内） |
| `battleWon` | 初めて戦闘に勝った（締めのひとこと） |
| `levelUp` | 初めてレベルが上がった |
| `poisoned` | 初めて状態異常を受けた |

- **コマンドは1つずつ矢印で指して教える。** `pointAt` にコマンドの `value` を書くと、
  その項目が四角で囲まれ、ふきだしから矢印が伸びる

```js
cmdAttack: {
  id: "cmdAttack", trigger: "battleStart", order: 2,
  pointAt: "attack",          // ← コマンドの value
  title: "攻撃",
  lines: ["選ぶと、相手のモンスターを攻撃します。", "PPを使いません。何度でも使えます。"]
}
```

- **指し先は位置ではなく `value` で引く。** コマンドの並びは場面で変わる
  （スカウトや交代が出たり出なかったり）ので、`CommandMenu.rectOfValue()` に聞く
- **戦闘の説明が出るのはコマンドを選ぶ瞬間**（`_beginCommandPhase`）。
  開始時に出すと、指す相手がまだ画面に無い。読んだ直後に試せる利点もある
- 指し先が画面に無いときは、**矢印が出ないだけで説明は出る**
- 場面の側が `tutorial.setTargetResolver(fn)` で「どこを指すか」を教える。
  ふきだしは画面の中身を知らないので、場所は場面に聞きに行く
- 1枚は2〜3行に抑える。指している項目を見ながら読むので、長いと目が往復する
- `enemyWeak` は**スカウトできる戦い**でしか出ない（`allowScout` が false の主では出さない）
- **出ているあいだは、その場面の操作が止まる。** 読んでいる裏で戦闘が進まないように
- **Esc でいつでも止められる。** 止めると設定の「チュートリアル」が「出さない」になる。
  「出す」に戻せば、まだ見ていないぶんはまた出る。
  設定はセーブファイルごとなので、止めたのはそのファイルだけ（新しく始めたファイルでは出る）
- ふきだしの高さは**行数から計算する**ので、3行でも5行でも収まる

説明を増やすときは `data/tutorial.js` に1つ足すだけ。既にある `trigger` を使うならコードは触らない。

> **`id` は変えないこと。** 見たかどうかを id でセーブに残しているので、
> 変えると一度見た人にもう一度出てしまう。

### 物語の場面

決まった場面に来たとき、1度だけ流れる物語。中身は `data/story.js`、
物語の設定と決まりごとは `ストーリー構成.md`（**そこに無い固有名詞・設定は足さない**）。

| 部品 | 役目 |
|---|---|
| `data/story.js` | 場面の中身（ページ・見せ方・話す人） |
| `js/systems/StorySystem.js` | どの場面をもう見たか。セーブに入る（`story.seen`） |
| `js/scenes/StoryScene.js` | 場面を流す画面（文字・立ち絵・揺れと光・見出し） |
| `js/ui/StoryBackdrop.js` | 場面の背景を描く（状態を持たず、経過時間から絵を決める） |
| `Game.playStory(trigger, 次の画面)` | まだ見ていない場面があれば流してから次の画面へ。無ければそのまま次の画面へ |

```js
mineCleared: {
  id: "mineCleared", trigger: "homeReturn", when: { cleared: "mossyMine" }, order: 10,
  draft: true,              // 右上に「（仮の文章）」。文章が決まったら消す
  letterbox: true,          // 上下の黒い帯
  bgm: "home", bg: "mine",  // 曲と最初の背景
  pages: [
    { style: "narration",
      actors: [{ monster: "mossGolem", x: 400, y: 530, size: 150, enter: "grow", glow: "#6fd183" }],
      lines: ["坑道の奥で眠っていた、苔むす石の巨人。", "…"] },
    { bg: "camp", style: "dialogue", speaker: "試験官", lines: ["戻ったか。…"] }
  ]
}
```

| 見せ方（style） | 見た目 |
|---|---|
| `narration` | 真ん中に、行の塊が浮かぶ（語り）。背景の上でも読めるよう文字に影を付ける |
| `dialogue` | 画面の下の窓。話す人の名前が窓の上の縁に乗る（会話） |
| `title` | 大きな見出し。字間を広いところから詰めながら浮かび、上下の線が真ん中から伸びる |
| `choice` | 選択肢。前のページの台詞を窓に出したまま、右上に項目を並べる（↑↓・マウス・決定）。選んだ項目の `pages` がすぐあとに入り、終わったら選択肢の後ろの共通ページへ続く |

**ページの出し分け**
- `if`：条件を満たすときだけ入るページ（書き方は `when` と同じ）。場面の始まりで決まる
- `marks`：そのページを見たら、別の場面を見たことにする。
  例：初めての全滅がヨミリュウ戦だったとき、場面8のページを場面4-負けに差し込み（`if: { notSeen: ["firstDefeat"] }`）、
  `marks: "firstDefeat"` で場面8を別には流さない
- `transition: "black"` は、背景が前のページと同じなら暗転しない（差し込んだページのあとで二度暗くならないように）

**演出**（どれもページごとに書ける。書かなければ前のページのまま）

| 項目 | 中身 |
|---|---|
| `bg` | 背景。`data/ui.js` の `story.backdrops` の id。変わるときは溶けて切り替わる（`bgFade`） |
| `actors` | 立たせるもの（`monster` / `player` / `sprite`）。**前のページにいなかったものだけ**登場の動き（fade / rise / drop / left / right / grow）をする。`silhouette` で影だけ、`glow` で後ろに光 |
| `fx` | ページの頭の揺れ（`shake`）・光（`flash`）。**設定「エフェクトの濃さ」に従う**（0 なら出ない。戦闘と同じ表） |
| `se` / `bgm` | ページの頭で効果音を鳴らす／曲を変える（`"none"` で止める） |
| `fx` の `memory` | 別の背景（燃える村など）を一瞬だけ重ねる。記憶がよぎる演出。光ではないので濃さの設定では消えない |
| `transition: "black"` | 暗転。真っ暗から明けていく（`blackFade`）。背景の切り替えを隠せる |
| `delay` | 文字が出はじめるまで待つ（「少し間を置く」） |
| `cue` | **文字を出しきったあと**に起きる演出（`{ actors, fx, se, hold, at }`）。1回目の決定で文字が出きり、演出が起き、2回目で演出の終わりまで進む |
| 下がる立ち絵 | 前のページにいて、いなくなったものは、その場で薄れて消える（`actorExit`） |
| `letterbox`（場面全体） | 上下の黒い帯。始まりに外から滑り込む |

人物の絵（オルド・イレーネ・探索者）は `data/sprites_story.js`（`npcOrd` / `npcIrene` / `npcScout`）。
見た目はこの絵で確定。主人公と同じ 32×32。探索者は主人公と同じ形で、髪と服の色だけ変えてある。
本文の元は `scenario_yoran.md`（揺籃の穴 場面1〜8）。

| 背景（`story.backdrops`） | 絵 |
|---|---|
| `void` | 一色の闇 |
| `abyss` | タイトルと同じ、奥へ広がり続ける同心円と降る粒 |
| `burning` | 燃える村の夜。赤い空・揺れる炎・家並みの影・舞い上がる火の粉 |
| `camp` | 拠点の夜。拠点の画面と同じ地面・穴・たき火を、会話の窓に隠れないよう上へずらして描く |
| `night` | 星の瞬く夜空。ときどき流れ星 |
| `mine` / `ember` / `depths` / `venom` | 各ダンジョンの中。岩壁の影と漂う塵。色は `data/dungeonThemes.js` から |

**流れる場面（trigger）**

| trigger | いつ | 呼んでいる所 |
|---|---|---|
| `newGame` | 新しく始めて、名前と見た目を決めた直後 | `PlayerSetupScene._finish` |
| `homeReturn` | 拠点に着いたとき（探索の結果画面のあと・「続きから」） | `ResultScene`・`SaveSlotScene._continueGame` |

- `when` で条件を付けられる：`cleared`（そのダンジョンをクリア済み）／`event`（その出来事を済ませた）／
  `result`（その出来事の戦いの結果。`win` / `lose` / `flee` / `scouted`。`Game.setEventResult` が残す。`null` で「結果が残っていない古いセーブ」）／
  `caught`（その種族を仲間にしたことがある）／`seenAny`・`notSeen`（場面を見たか）
- 全滅すると `doneEvents.defeated` が立つ（`DungeonScene._returnToHome`。ヨミリュウの待ち伏せで負けたときも含む）。場面8の条件に使う
- ヨミリュウの報告（場面4）は結果で4つに分かれる：`yomiryuReport`（負け）／`yomiryuReportFled`／`yomiryuReportWon`／`yomiryuReportScouted`。
  場面7（`reportAccepted`）は、負け・逃げ・勝ちの報告を見たあとでヨミリュウを仲間にしたときだけ流れる
- いまの `homeReturn` の場面：坑道クリア → 亀裂クリア → ヨミリュウに襲われた → 深層クリア → 毒沼クリア（試験の終わり）。
  **条件を満たした場面が2つ以上あれば、order の順に続けて流れる**（流し終えた `StoryScene` が同じ trigger の続きを探す）
- 「続きから」でも見るのは、主を倒した直後にセーブせず閉じた人のため（見た印はセーブしたときに残る）
- 増やすときは、その画面で `scenes.change(次)` の代わりに `game.playStory(trigger, 次)` を呼ぶ。
  ★ 画面の `enter` の中では呼ばないこと（切り替えの途中で次の切り替えが上書きされる）。`update` か、画面を出る側で呼ぶ
- **1場面は1度だけ。** 取り出した時点で「見た」になる
- **この仕組みより前のセーブ**は、その時点の場面を全部「見た」扱いにする（チュートリアルと同じ）。
  あとで足した場面は、その人にもふつうに流れる
- 文字は1文字ずつ出る（`data/ui.js` の `story.charsPerSecond`）。決定で途中を出しきり、もう一度で次のページ
- **Esc は2回で飛ばす。** 1回目で右下が「もう一度 Esc で飛ばす」に変わる（`skipWindow` の間だけ）。
  1回で飛ぶと、読み進めるつもりの押し間違いで取り返しがつかないため
- `{player}` は主人公の名前、`{me}` は主人公の一人称（プレイヤーが選んだもの）に置き換わる

### 愛情度

仲間ひとりひとりとの絆。段階と報酬は `data/affection.js`、物語の決まりは `ストーリー構成.md` の 10。

| 段階 | 必要な回数 | 報酬 |
|---|---|---|
| 出会い | 0 | ― |
| 慣れ | 20 | 全能力 +3% |
| 信頼 | 60 | さらに +3%（合わせて +6%） |
| 絆 | 120 | その種族だけの報酬（`data/monsters.js` の `bondReward`）。専用技・既存の技・能力・耐性のどれか（組み合わせも可） |

- **上がり方**：勝った戦闘で、一度でも場に出ていた仲間に `gainPerWin`（1）。控えには入らない。
  逃げた・負けた・誘って終わった戦闘では増えない。途中で倒れても、交代で出ても数える
  （`BattleSystem` が場に出た仲間に `_appeared` の印を付け、勝ったとき `_awardAffection` で足す）
- **能力の上がり**：`MonsterInstance.getAffectionEffects` が `statMultiplier` を返し、`EffectSystem.collectEffects` が読む。
  特性・装備と同じ仕組みなので、ステータス計算は変えていない。段階が上がった瞬間は、最大値が増えたぶん今のHP・PPも増える
- **表示**：戦闘の終わりに「〇〇 との関係が「慣れ」になった!」。仲間の「様子を見る」の名前の下に「愛情度 慣れ（34/60）」の札、
  右下の「効果」欄に「全能力 ×1.03（慣れ）」と、絆の報酬の能力・耐性
- **愛情度の詳細**：札を押す（または決定）と、「様子を見る」の上に窓が開く。いまの段階・次までの棒と残り回数・
  段階ごとの必要な回数と報酬・深まり方の説明。決定・Esc・クリックで閉じる（`PartyScene._renderAffectionDetail`、配置は `data/ui.js` の `party.affectionDetail`）。
  絆の報酬は、届くまで「？？？」と伏せる（`data/affection.js` の `hideBondRewardUntilReached`）
- **絆の報酬**（`bondReward`）：全モンスターに専用技があるわけではない。`{ skill }` で技を覚える（専用技でも既存の技でも）、
  `{ effects }` で能力・耐性が上がる（書き方は特性・装備と同じ）。両方書いてもよい。古い書き方の `bondSkill` も読める
- **図鑑の記録**：種族ごと。その種族でいちばん深まった段階（`Discovery.affectionStages`）までの `records` が、図鑑の説明文のあとに
  「― 慣れ ―」の見出しつきで書き足される。預けても失っても、読めるようになった記録は残る
- **セーブ**：個体の `affection`、図鑑の `affectionStages`。古いセーブは 0 から（図鑑の段階は、連れている仲間から拾い直す）
- **まだ無いもの**：記録の本文（`records`）と絆の報酬（`bondReward`）はどの種族にも書いていない。
  報酬はあとで書けば、もう絆に届いている仲間も次に読み込んだとき受け取る

### 一度きりの出来事（ヨミリュウの待ち伏せ）

決まった階で**必ず起きる戦い**。`data/dungeons.js` の `events` に書く（書き方はファイルの冒頭）。

| 項目 | ヨミリュウの待ち伏せ |
|---|---|
| 起きる場所 | 静寂の深層の地下4階。**着いてから1歩目**（`floor: 4` / `afterSteps: 1`） |
| 相手 | ヨミリュウ1体。倍率と行動の順番は**同じ階の出現表の竜から引く**（調整は1か所で済む） |
| 曲 | 主の戦いの曲（`bgm: "boss"`） |
| 逃げる・誘う | どちらもできる |
| 負けたとき | **ふつうの全滅と同じ**。その潜行で拾ったものを落として拠点へ戻る（`keepItemsOnDefeat: false`）。物語の場面8「素材は、どこにもない」と合わせてある |
| 回数 | 同じファイルでは一度きり。**起きた瞬間に**済ませた印が付く（`doneEvents`、セーブに入る） |
| 起きないとき | その深層をクリアした後（`onlyBeforeClear`）。古いセーブでクリア済みの人には出ない |

- 負けることを想定した戦いだが、勝つこともできる（ストーリー構成.md の 6）
- 竜はこれまでどおり、地下4階に確率でも出る（待ち伏せとは別）
- 始めの一言は `data/messages.js` の `events`

### よくある質問

拠点の「遊び方」から開く。左に質問の一覧（分類ごと）、右に答え。**↑↓で質問を選び、Q/E とホイールで答えを送る**。

- **画面そのものは最初から開いている。** 困るのは遊んでいる最中なので、クリア条件は付けていない
- **質問ごとには `unlockedBy` を付けられる。** まだ使えない機能の質問は並ばない。

- 中身が1つも無い分類は、見出しごと出さない
- 答えは段落の配列で書く。段落のあいだに1行空く
- 折り返しは文字数で行い、**行頭に「。」「、」が来ないよう1文字ぶん前の行へ送る**
- 数字はできるだけ書かず、仕組みのほうを説明している
  （ここの数字はデータと自動では連動しないため）

  持っているときだけ（素材は99個なので、実際にはお金だけが条件になる）

### 売り買いの確認（誤操作を防ぐ）

決定を押すとすぐには売買せず、**買うときも売るときも2段階**に分かれる。

```
品物を選ぶ → ①個数を決める → ②「買いますか?／売りますか?」はい／いいえ → 実行
              ↑ Esc で戻る      ↑ Esc・いいえ で①へ戻る
```

①の画面には、**個数・1個あたりの値段・合計金額・そのあとの所持金**を同時に出す。

- **↑↓ で1個ずつ、←→ で10個ずつ**（`data/ui.js` の `shop.quantityStep`）
- 個数は上限を超えられない
  - 買う … **所持金・所持数の上限・持ち物の空き**のいちばん厳しいもの
  - 売る … **持っている数**
- そもそも1個もやりとりできない場合は、個数の画面に入らず理由だけ出る
- 買うときに入りきらなかった分は買わず、**受け取った数のぶんだけ支払う**

```
実効ステータス = floor( 基礎値 × 成長 × 性格 × 効果倍率 ) + 個体値 + 効果加算
```

> 今後「階を降りるたびの強化」を足すときも、`collectEffects` に出どころを1つ増やすだけで
> 戦闘側の変更は要らない。

## 挑戦（ラン）

ダンジョンへ入ってから拠点へ戻るまでが **1回の挑戦（ラン）**。
「潜って、生きて帰る」ことに意味を持たせるための仕組み。

| 帰り方 | 拾ったアイテム | スカウトした仲間 | HP・PP |
|---|---|---|---|
| Esc で自分の足で戻る | 持ち帰れる | 残る | 全回復 |
| ボスを倒して帰還 | 持ち帰れる | 残る | 全回復 |
| **全滅** | **そのランで拾った分をすべて失う** | 残る | 全回復 |

- 失うのは**そのランで拾った分だけ**。出発前から持っていた分は減らない
  （薬草を3個持って入り、2個拾って全滅 → 手元には3個残る）
- 全滅しても仲間は失わない
- ラン中は回復手段が**道具と泉だけ**。拠点へ戻ると全回復する

設定は `data/run.js` にある。

```js
loseItemsOnDefeat: true,     // 全滅で拾ったアイテムを失う
loseMonstersOnDefeat: false, // 全滅でスカウトした仲間も失う（現在は無効）
healOnReturn: true           // 拠点へ戻ると全回復する
```

> 記録は `js/systems/RunSession.js` が持つ。
> `game.giveItem` / `game.addMonster` を通していれば自動で記録されるので、
> 宝箱など新しい入手経路を足しても、ここを直す必要はない。

| 一撃の冴え | 与ダメージ ×1.08 | ふつう | 0.7 |

### ★ 抽選は「等級を先に引く」

選択肢の枠1つごとに、**まず等級を固定確率で引き**、そのあとその等級の加護の中から
編成しているものを選ぶ。

| 等級 | 枠1つがこの等級になる確率 |
|---|---|
| よく出る | 45% |
| ふつう | 34% |
| 少ない | 15% |
| まれ | **6%** |

引いた等級の加護を1つも編成していないときは、**より出やすい等級へ順に落とす**。
いちばん出やすい等級まで落ちても空なら、**その枠は出ない**（選択肢が3つより少なくなる）。
そのとき加護の画面に「編成している加護が偏っているので、選択肢が減っている」と出る。

> **なぜこうしたか。** 以前は「編成した加護をまとめて weight で引く」形だった。
> これだと weight は**プールの中での比率**にしかならず、
> プールの中身をプレイヤーが決められる以上、レア度が意味を持たない。
>
> | 編成のしかた | 旧・まれの出現率 | 旧・1階あたりの選択肢 |
> |---|---|---|
> | 初期のまま（9個） | 6% | 3.00 |
> | 強い順に9個 | **32%** | 3.00 |
> | 強い順に3個だけ | **100%** | 2.00（3階で必ず全部そろう） |
>
> `activeMax: 9` は**天井であって床ではない**ため、
> 「強い3個だけ残す」が最適解になっていた。**減らすほど得**という向きだった。
>
> いまはこうなる。まれが出るランはどの編成でも42〜43%で一定。
>
> | 編成のしかた | 新・1階あたりの選択肢 | 3つとも取れたラン |
> |---|---|---|
> | 初期のまま（9個） | 2.99 | 100% |
> | 全部（14個） | 2.99 | 100% |
> | 強い順に9個 | **1.09** | 44% |
> | 強い順に3個だけ | **0.18** | **0%** |
>
> 絞り込むほど選択肢が減るので、「強いものだけ残す」が損になる。
> 拠点の「加護を選ぶ」画面には**等級ごとの編成数**を出してあり、
> 0個の等級は赤くなる（そこが空く枠）。

- 同じ等級の中では **weight で重み付け**して選ぶ
- 1回の選択肢に同じものは並ばない
- **一度取った加護は再び候補に出ない**（`data/run.js` の `allowRepeat` で変更できる）
- 候補が尽きたら画面自体が出ない
- 途中でスカウトした仲間にも、それまでの加護がすべて掛かる
- 同じステータスへの加護は掛け合わさる（×1.12 と ×1.2 なら ×1.344）

**苔むす坑道では2回**選べる（B1F→B2F と B2F→B3F）。最深階の階段はボス戦なので加護は出ない。

設定は `data/run.js` の `blessing`（出すかどうか・候補の数・重複を許すか・編成の上限・等級の表）、
中身は `data/blessings.js`。

### 買う・編成する（静寂の深層をクリアしてから）

深層をクリアすると、**ショップに「謎の商人」のタブ**が増え、
拠点のメニューに **「加護を選ぶ」** が増える。この2つは対で、
片方だけでは成り立たない（買っても入れ替えられない／入れ替える相手がいない）。

| | 保存される場所 | 意味 |
|---|---|---|
| `Game.boughtBlessings` | セーブ | 買った加護（恒久。消えない） |
| `Game.offBlessings` | セーブ | 選択肢から外している加護 |

- **買った加護は売れない。** 店では「所持」と出て、決定を押しても何も起きない
  （行の `value` を持たせないことで表している）。
  買ったあとも右の説明欄で中身を読み返せる。
  「いま選択肢に入っているか」もそこに出るので、上限で外れていても気づける
- **選択肢に入れておけるのは9個まで**（`data/run.js` の `blessing.activeMax`）。
  1階降りるごとに1つしか取れないので、9個あれば9階ぶん。
  買い足すほど選択肢が薄まる、という事故を防ぐための上限。
  **下限は設けていない** —— 減らしすぎると等級の穴が空いて選択肢が減るので、
  絞り込みは仕組みのほうで損になる（上の「抽選は等級を先に引く」を参照）
- 最初から9種持っているので**すでに上限いっぱい**。買った加護は自動では入らず、
  「（選択肢がいっぱい。拠点で入れ替える）」と知らせが出る
- 抽選は `BlessingSystem.pickChoices(run, game)` が行う。
  `game` を渡すと「買っていない」「外している」加護が候補から抜ける。
  渡さない場合は保険として `locked` の加護だけを弾く

> 店の側は **`data/shop.js` に `type: "blessing"` を書くだけ**で、
> 何を売るかは `data/blessings.js` の `locked` / `price` が決める。
> 加護を増やせば自動的に店に並ぶので、店のデータは触らなくてよい。

### 加護を増やすとき

`data/blessings.js` に1エントリ足すだけでよい。**効果の書き方は特性・装備とまったく同じ**。

```js
ironWill: {
  id: "ironWill", name: "鉄の意志",
  description: "仲間全員の防御が上がり、受けるダメージも減る。",
  weight: 0.6,
  effects: [
    { type: "statMultiplier", stat: "defense", value: 1.15 },
    { type: "damageTaken", value: 0.95 }
  ]
}
```

> 効果は `RunSession` が持ち、`Game` が連れている全員の `runEffects` へ配る。
> `EffectSystem` はそれを他の出どころ（特性・装備）と同じように集計するだけなので、
> **戦闘やステータス計算のコードは一切変更していない**。

## 絵の動き（モーション）

**1枚の絵を動かして見せる**方式。コマ絵を描き足さなくても、
`data/motions.js` の定義を種族に1行つけるだけで動く。

```js
// data/monsters.js
slime: { ..., sprite: "slime", motion: "float" }
```

**α-5で全19種が専用の動きを持つようになった。** 同じ動きを共有している種族はいない。

| 種族 | 名前 | 動き |
|---|---|---|
| スライム | `slimeIdle` | コマ絵4枚と上下の揺れを合わせて跳ねる |
| コウモリ | `batFlutter` | 翼を横に開閉する速い羽ばたき（340ms） |
| コケネズミ | `ratHop` | 跳ねて、着地した瞬間に潰れる |
| イワゴロー | `rockIdle` | ほとんど動かず、4.6秒かけて1.4度傾く |
| ヒカリムシ | `bugGlow` | 羽ばたきだけ速く（240ms）、光はゆっくり明滅 |
| キノコン | `sporeSway` | 根が生えているので、ゆっくり傾いて胞子がにじむ |
| モスゴーレム | `golemBreathe` | 5.2秒に1呼吸。足元は動かさない |
| スミビ | `emberIdle` | 小刻みに揺れ、火の勢いが安定しない |
| フレイミン | `flameHop` | 気性が荒い。落ち着かず細かく跳ねる |
| ハイバネ | `ashDrift` | 羽ばたきは速いが、体は熱に乗ってゆっくり漂う |
| ヒビイワ | `crackPulse` | 岩の遅い呼吸に、ひびから漏れる熱の明滅を重ねる |
| マグマガニ | `crabIdle` | じっと動かない。たまに横へ体重を移すだけ |
| マグマウルフ | `beastBreathe` | 獣の呼吸。竜より速く浅い |
| ヨドミ | `murkFloat` | 浮きながら、裾の滴が伸び縮みする |
| カゲヅタ | `riftIdle` | 上端を固定したまま縦に伸び縮みし、亜空間へ出入りする |
| ミズダマリ | `waterWobble` | 縦横が入れ替わるように波打つ |
| ビリムシ | `boltFlit` | 帯電で小刻みに震える（150〜300ms） |
| ヨミリュウ | `dragonBreathe` | 縦と横をずらして、体と翼が別々に動く深い呼吸 |
| キングスライム | `kingWobble` | 大きなゼリーの塊がゆっくり波打つ |

`float` / `flutter` / `hop` / `sway` / `glow` / `heavy` / `none` は**汎用のひな形**として
`data/motions.js` に残してある。新しい種族を足すときの出発点になる。
`breathe` は店主、`blaze` は拠点のたき火が使っている。

> **地に足がついているものは `offsetY` を使わない。** 浮かせると重さが消える。
> イワゴロー・モスゴーレム・マグマウルフ・マグマガニ・ヒビイワ・ミズダマリ・
> キングスライム・ヨミリュウは、足元が1pxも動かないことを実測で確認してある。

動かせるのは **左右・上下・大きさ（全体／縦／横）・濃さ** の6つ。それぞれに
「どれだけ（`amplitude`）」「どの速さで（`speed`）」「どんな波で（`wave`）」を書く。

```js
float: { offsetY: { amplitude: -2.5, speed: 0.0018 } }
hop:   { offsetY: { amplitude: -3.5, speed: 0.0042, wave: "bounce" } }

// 縦と横を少しずらすと、1枚の絵のままでも「息をしている」ように見える
dragonBreathe: { scaleX: { amplitude: 0.028, period: 4200 },
                 scaleY: { amplitude: 0.024, period: 4200, phase: 0.18 } }
```

- 画面は下が＋なので、**上へ動かすには負の値**
- `wave` は `sin`（往復・既定）/ `bounce`（片方向。跳ねる用）/ `blink`（かちっと切替）
- 伸縮は**足元を基準**にする（中央基準だと地面へめり込む／浮いて見える）。
  ぶら下がっているものだけ `anchor: "top"` と書いて**上端を基準**にする。
  カゲヅタは裂け目が上にあるので、これがないと蔦ではなく裂け目の方が動いてしまう
- `scale` が全体の倍率、`scaleX` / `scaleY` はそこへ掛かる。
  **同じ速さで位相だけずらす**のが要点。同時に動かすとただの拡大縮小になる

### 仕組み

```
data/motions.js ──▶ ui/Motion.js ──▶ SpriteRenderer.drawMotion
   （何を、どれだけ）   （今この瞬間の値）      （その位置に描く）
```

- `Motion` は**状態を持たない**。時間を渡せば答えが返るので、
  シーンごとに動きを覚えておく必要がない
- 時間は `game.clock`（起動からの経過ミリ秒）を1つだけ共有する
- 同じ種族が並んでも動きが揃わないよう、個体ごとに**位相をずらす**。
  種族id・性格・個体値から作るので、画面を開き直しても動きが飛ばない
- 戦闘・拠点・なかま・図鑑・ダンジョンが同じ関数を通るので、
  1か所直せば全画面に効く

### タイトル画面の演出

「深淵へ落ちていく」イメージを、次の順に重ねて描いている。

```
たてグラデーション → 同心円 → 粒子3層 → ふちの暗さ → 題字 → メニュー → 明転
```

| 要素 | 動き | 設定 |
|---|---|---|
| 同心円 | ゆっくり外へ広がり続ける（毎秒5.5px、一周50秒） | `abyss.expandSpeed` |
| 粒子 | 奥・中・手前の3層。奥ほど小さく遅く薄い。横にも流れる | `particleLayers` |
| ふちの暗さ | 画面の四隅を落として中央へ視線を集める | `vignette` |
| 題字 | ゆっくり浮き沈み＋光のにじみが増減（11〜29） | `logo.float` / `logo.glowPulse` |
| 明転 | 開いたとき、黒から1秒かけて明け、題字がせり上がる | `intro` |
| カーソル | 選択中の「▶」が明滅（1.0〜0.72） | `theme.cursorPulse` |

- 円は**湧いた瞬間と消える瞬間が透明**になるので、入れ替わりが見えない
  （1フレームあたりの濃さの変化は最大0.003）
- 明転は**1度だけ**。更新履歴から戻るたびには流れない
- カーソルの明滅は `CommandMenu.render(clock)` に時計を渡した画面だけで効く。
  渡さない画面は今までどおり点滅しない

### 拠点の演出

穴（揺籃の穴）のそばで、たき火を囲む場所を背景の絵で見せる。
拠点の名前はまだ決まっていないので、見出しの下の一言（`messages.home.subtitle`）は出していない。

```
グラデーション → 地面 → 穴 → たき火の明かり → たき火 → 火の粉 → パネル
```

| 要素 | 内容 | 設定 |
|---|---|---|
| 穴 | 画面のいちばん下にふちだけ見える。中心は画面外 | `scenery.hole` |
| 地面 | 穴のふちの地面。上端に細い線 | `scenery.ground` |
| たき火 | `blaze` で揺れる。まわりの明かりもゆっくり強弱する | `scenery.campfire` |
| 火の粉 | もとからある、上へ昇る粒 | `particles` |
| メニュー | 8項目それぞれに絵がつく。選んだ項目は4px右へずれる | `menu.iconSize` |
| 所持金 | 額が変わると、数字が追いかけて動く | `gold.countSpeed` |

> **穴は地面より「あと」に描く。** 先に描くと地面に埋まって見えなくなる。
> また、ふちの線が操作説明の文字を横切らないよう、
> `cy - ry`（穴の上端 = 586）が文字の下端より下に来るようにしてある。

### メニューの絵

`data/sprites_ui.js` に `icon〇〇` として置く。項目に `icon` を書き、
`CommandMenu` に `SpriteRenderer` と `rect.iconSize` を渡した画面でだけ描かれる。

```js
// data/ui.js
menu: { x: 48, y: 122, w: 280, h: 372, lineHeight: 36, iconSize: 22 }
// シーン側
this.menu = new NS.CommandMenu(this.panel, this.layout.menu, this.sprites);
```

どちらか片方でも欠けていれば文字だけになるので、**他の画面は今までどおり**。
絵は 16×16 だが 22px に拡大されるので、細かい模様は入れず輪郭で形が分かるようにする。

### 画面の切り替え

いきなり別の画面に変わると目が驚くので、**いったん暗くしてから切り替える**。

```
今の画面を暗くする（100ms） → いちばん暗いところで入れ替える → 明るく戻す（100ms）
```

判定は `js/core/SceneManager.js` が全部やるので、**シーン側のコードは一切変わらない**。
`change()` を呼ぶだけで暗転がつく。

- 入れ替わりは**真っ暗な瞬間**に起きるので、切り替わりそのものは見えない
- 暗くしている間はシーンの `update` を止める。
  押しっぱなしのキーが次の画面へ持ち越されて、いきなり反応するのを防ぐため
  （`game.clock` は進み続けるので、絵の動きは止まらない）
- `data/ui.js` の `transition.duration` を **0 にすると演出なし**で即座に切り替わる

#### 場面ごとの切り替え方

`change(scene, "encounter")` のように名前を渡すと、特別な切り替え方になる。
定義は `data/ui.js` の `transition.effects`。書かなかった項目は共通の設定で埋まる。

```js
encounter: { duration: 380, color: "#0b0f1a",
             blockMax: 28, turns: 0.4, zoom: 1.6, veilPower: 3.2 }
```

| 項目 | 内容 |
|---|---|
| `blockMax` | 何倍まで粗くするか（モザイク）。1以下で無効 |
| `turns` | 何回まわすか |
| `zoom` | 最後にどれだけ寄るか |
| `veilPower` | 暗くなり始めを遅らせる度合い。**1のままだと歪む前に真っ暗になる** |

やり方は「一度キャンバスの中身を写し取って、加工して描き直す」だけなので、
**シーンは自分が歪められていることを知らなくてよい**。

> 敵と出会ったときに使っている。`veilPower: 3.2` で、
> 暗幕は 0.25→0.01 / 0.50→0.11 / 0.75→0.40 / 1.00→1.00 と、最後だけ効く。

### 階を降りるときの暗転

階段は**画面が変わらない**（同じ探索画面のまま地図だけ作り直す）ので、
`SceneManager` ではなく `js/ui/Fade.js` を使う。

```js
this.fade.start(function () { self._descend(); });   // いちばん暗いところで作り直す
```

暗転しているあいだは `update` が早く返るので、操作を受け付けない。

### 知らせの出方

「セーブしました」「○○を手に入れた」のような一時的な知らせは `js/ui/Notice.js` が持つ。
文と残り時間を持つだけの部品で、**どこに・どんな色で描くかは各画面が決める**。

| | 時間 |
|---|---|
| 出るとき | 140ms かけて濃くなる |
| 消えるとき | 340ms かけて薄くなる |

消えるほうを長くしてあるので、読み終わってからそっと消える。
設定は `data/ui.js` の `theme.notice`。

> タイトル・拠点・探索・ショップ・工房・持ち物・設定の7画面が同じ部品を使う。
> それぞれが同じコードを持っていたのをまとめたもの。

### 選択カーソル

`CommandMenu` と `ScrollList` は、`render(clock)` に時計を渡した画面でだけ
カーソルが明滅する（1.0〜0.72）。**渡さない画面は今までどおり点滅しない**ので、
新しい画面を足すときに気にしなくてよい。

## 拠点メニュー

並び・絵・解放条件は `data/home.js` が持つ。

```js
{ key: "craft", value: "craft", icon: "iconCraft", unlockedBy: "mossyMine" }
```

- **まだ使えない項目も隠さず並べる**（何が増えるのか分かるように）。灰色で表示し、
  選ぶと「工房 は 苔むす坑道 をクリアすると使える」と出る
- 拠点へ戻るたびに組み直すので、クリアした直後から使えるようになる
  （選んでいた場所は保たれる）
- 解放条件はダンジョン・店とまったく同じ書き方（`DungeonCatalog.isConditionMet`）

| 項目 | 解放 |
|---|---|
| 工房 | 苔むす坑道をクリア |
| 加護を選ぶ | 静寂の深層をクリア（謎の商人と同時） |
| その他 | 最初から |

## 店

`data/shop.js` の `shops` に並べる。**店を増やすのは1エントリ足すだけ。**

```js
{ id: "smith", name: "鍛冶屋", subtitle: "坑道の鉱石を打つ",
  keeper: "keeperSmith", keeperMotion: "breathe",
  unlockedBy: "mossyMine",              // 店そのものが開く条件
  stock: [ { item: "oreShard", price: 30 }, { item: "mossCharm" } ] }
```

いまは **よろず屋と謎の商人の2軒**。上のタブ（Q/E）で行き来する。

**よろず屋** —— 進むほど品揃えが増える

| 並ぶ時期 | 品 |
|---|---|
| 最初から | 薬草 20G / 回復薬 50G / 帰還の石 80G / 獣の牙 70G |
| 苔むす坑道クリア | 精気の実 70G / 石の帽子 120G / 光る提灯 180G / 鉱石のかけら 25G / 光る鱗粉 50G |
| 灼熱の亀裂クリア | 燃え殻 18G / 灰の羽根 45G / 焼けた殻 60G |
| 静寂の深層クリア | **解毒草 40G** / スライムのかけら 12G / 宵の露 22G / ねじれ蔦 45G / 雷光の翅 70G |

> **解毒草が帰還の石（80G）より安いのは意図的。**
> 同じ値段だと「毒を治す」より「引き返す」ほうが常に得になり、
> 毒を治すという選択自体が生まれない。

**謎の商人** —— 静寂の深層クリアで現れる。加護だけを売る

- `data/shop.js` に **`type: "blessing"`** と書いた店。品物は `stock` ではなく
  `data/blessings.js` の `locked: true` が付いたものが自動的に並ぶ
- **売ることはできない**ので、この店では「買う／売る」のタブが切り替わらない
- 買った加護は「所持」と出て、二度は買えない
- 詳しくは「加護」の節を参照

> **主が落とす素材と、工房で作れる装備は店に並べない。**
> 灼熱の牙・黄泉竜の鱗・王冠のかけらは、倒して手に入れることに意味を残してある。

### 並ぶ順番

`stock` に書いた順ではなく、**画面では並べ替えて見出しを挟む**。

```
- 回復 -            1. 分類（data/categories.js の item.order）
  薬草      20G        回復 → 装備 → 素材 → 重要
  回復薬    50G     2. 値段の安い順（手が届くものから目に入る）
- 装備 -          3. shop.js に書いた順（上の2つが同じときだけ）
  獣の牙  70G
  石の帽子  120G
  光る提灯  180G
- 素材 -
  鉱石のかけら 25G
  光る鱗粉   50G
```

- 並びを変えたいときは `categories.js` の `order` を入れ替えるのが手軽
- **売る側も同じ分類の順**にそろえてある（持ち物の画面と行き来しても迷わない）
- 売れる品が1つも無い分類は、**見出しごと出さない**（「重要」だけの見出しが残らない）

- **苔の外套は店に並ばない。** 工房でしか手に入らない
- **工房で作れる装備は、どれも店に並ばない**（風切りの羽根・炎よけの札・燃え殻の剣・灼牙の戦刃 など）
- **灼熱の牙も並ばない。** 主のドロップなので、倒すこと自体に意味を残している
- 亀裂の素材（燃え殻・灰の羽根・焼けた殻）は**亀裂をクリアすると買える**ようになる。
  ただし灼牙の戦刃だけは灼熱の牙が要るので、**金では解決できない**
- 画面上段のタブで店を切り替える（**Q / E**、またはタブをクリック）。下段は買う／売る
- 店を変えると「買う」に戻る。売る一覧は持ち物なので店に関係ない
- 開いている店だけがタブに並ぶ。1軒だけのときは Q/E の案内も出さない
- `keeper` を書くと店主が立つ。`keeperMotion` で動く（`data/motions.js` のid）

> 2軒目（鍛冶屋）は仕組みの確認用に一度入れて、いまは外してある。
> 店主の絵 `keeperSmith` は `data/sprites_ui.js` に残してあるので、
> `data/shop.js` に1エントリ足せばすぐ立てられる。

> **解放条件はダンジョンとまったく同じ書き方が使える。**
> `"id"` / `["id","id"]` / `{dungeons,count}` / `{region,count}` のすべて。
> 判定は `DungeonCatalog.isConditionMet` に1本化してあるので、
> 条件の形が増えたときにダンジョンと店の両方へ同時に効く。

品揃えを増やしたい店には、品ごとに `unlockedBy` を書けばよい（よろず屋がその例）。

### 攻撃・被弾の動き

「ずっと続く動き」とは別に、**1回だけ流れて終わる動き**がある。
`duration` を持つ定義がそれ。チャンネル（上下・左右・大きさ・濃さ）は同じものを使う。

```js
// data/motions.js
lunge:  { duration: 300, offsetY: { amount: 26, shape: "outBack", outRatio: 0.28 },
                         scale:   { amount: 0.08, shape: "outBack", outRatio: 0.28 } },
recoil: { duration: 260, offsetY: { amount: 13, shape: "decay", cycles: 2 },
                         alpha:   { amount: -0.45, shape: "fade" } }

// data/monsters.js — 変えたい場面だけ書けばよい（書かなければ既定が使われる）
rocky: { ..., motions: { faint: "crumble" } }
```

| shape | 動き方 | 向くもの |
|---|---|---|
| `outBack`（既定） | 素早く出て、ゆっくり戻る | 踏み込み |
| `windup` | **先に逆へ引いてから**、勢いよく出て戻る | 技を放つ |
| `decay` | 大きく始まり、揺れながら収まる | 当たった衝撃 |
| `pulse` | なめらかに出て、なめらかに戻る | 跳ねる・膨らむ |
| `fade` | 最大から、まっすぐ元へ戻る | 一瞬の明滅 |
| `rise` | 0から最大へ向かい、**戻らない** | 倒れて消える |

`rise` だけは元に戻らないので、**終わったら描かないこと**（倒れたあとに元の姿へ飛ぶ）。

### 場面ごとの動き（既定で全種族に付く）

`data/motions.js` の **`motionDefaults`** が場面ごとの既定を持っている。
`motions` を書いていない種族は全員ここから拾うので、
**モンスターを1体足すのに、モーションの行は1行も要らない。**

| キー | 場面 | 既定 | 内容 |
|---|---|---|---|
| `attack` | ぶつかりに行く技 | `lunge` | 相手へ踏み込む |
| `cast` | 離れて放つ技 | `cast` | **引いて溜めてから**放つ |
| `buff` | 自分・味方にかける技 | `charge` | その場で縦に伸び上がる |
| `hit` | 攻撃を受けたとき | `recoil` | 押された方へのけぞる |
| `faint` | 倒れるとき | `fall` | 沈んで消える |
| `heal` | 回復したとき | `recover` | ふわっと膨らむ |
| `guard` | 防御しているあいだ | `guard` | 縮こまって震える |
| `levelUp` | レベルが上がったとき | `cheerHop` | 小さく跳ねる |

種族ごとに変えたいときだけ1行書く。書いた場面だけが上書きされる。

```js
motions: { faint: "crumble" }   // 倒れ方だけ差し替える
motions: { attack: null }       // その場面だけ動かさない（既定へは落ちない）
```

**`attack` / `cast` / `buff` の出し分けは技ごとに書かない。** 技の `effect` から決まる。

| 技の条件 | 動き |
|---|---|
| `effect` が `impact` / `slash`（`motionDefaults.meleeEffects`） | `attack` 踏み込む |
| `target` が `self` / `ally` | `buff` その場でかける |
| それ以外 | `cast` 溜めて放つ |

見た目と動きを分けたい技だけ、`data/skills.js` に1行足して上書きする。

```js
// ウィンドは「切る」見た目だが、自分は踏み込まず離れて放つ
gust: { ..., effect: "slash", motion: "cast" }
```

**倒れる動きは全種族に付いている。** 見た目に合わせて3種類を使い分ける。

| 動き | 内容 | 使っている種族 |
|---|---|---|
| `fall` | 沈みながら縮んで消える | スライム、キングスライム、コケネズミ、ヨドミ、カゲヅタ、ミズダマリ（既定） |
| `tumble` | 傾きながら大きく落ちる | コウモリ、ハイバネ、ヒカリムシ、ビリムシ（飛んでいるので） |
| `crumble` | その場で小さく潰れる | イワゴロー、ヒビイワ、モスゴーレム、キノコン、フレイミン、スミビ、マグマウルフ、マグマガニ、ヨミリュウ |

> **倒れる相手は「HPが0になった時点」では消さない。**
> 倒れる動きは `faint` の出来事が届いてから始まるので、
> HPが0になった瞬間に消すと「消えてから倒れる」ことになる。
>   HPが0になっても残す → 倒れる動きを流す → 流し終えたら消す
> の順で見せている（`_shouldShowSprite`）。
> 倒れる動きを持たない種族は、今までどおりその場で消える。

`guard` だけは**ずっと続く動き**（`duration` を持たない）。防御中はふだんの動きに重ねる。
`_defending` は `BattleSystem` が立てるので、画面側は見るだけ。

回転は `rotate` チャンネル。単位は**回転数**（1で1回転）で、絵の中心を軸にまわる。

```js
cheerSpin: { duration: 560, rotate: { amount: 1, shape: "rise" } }
```

「縮こまったまま震える」のように**揺れの中心そのものをずらす**には `offset` を使う。

```js
guard: { scale: { offset: -0.10, amplitude: 0.015, period: 780 } }   // 0.885〜0.915
```

- 戦闘は**敵が上段・味方が下段**なので、踏み込みは横ではなく**縦**。
  向き（±1）は画面側が渡すので、同じ定義が味方にも敵にも使える
- **のけぞりは、攻撃してきた方向へ飛ぶ**（＝踏み込みと同じ向き）
- 自分・味方にかける技（`buff`）だけは相手の位置に関係がないので、向きを固定している

```
data/motions.js ──▶ Motion.playback ──▶ Motion.combine ──▶ drawMotion
                    （今の瞬間のずれ）   （ふだんの動きに重ねる）
      ui/MotionPlayer.js（誰が・いつから再生しているか）
```

`Motion` は状態を持たないので、「いつ始まったか」を覚える相手として
`MotionPlayer` を置いている。終わった分は毎フレーム片づけるので、
倒れた相手の分が残り続けることはない。

> 戦闘速度を上げても、この動きの速さは変わらない（`game.clock` は実時間で進むため）。
> 速い設定では、踏み込みの途中で次の出来事が始まることがある。

### ダンジョンからの帰り方

**どこからでも帰れるわけではない。** 危なくなったら必ず逃げ切れてしまうと、
どこまで潜るかが選択にならないため。

| 帰り方 | 場所 |
|---|---|
| 階段で「拠点へ戻る」 | 各階の階段の上 |
| ボス前で「拠点へ戻る」 | 最深階の階段の上 |
| **帰還の石**を使う | どこでも（使うとなくなる） |
| 全滅する | どこでも（拾ったものを失う） |

- 階段を踏むと **降りる / 拠点へ戻る / まだ潜る** を聞かれる。
  最深階では「主に挑む」に変わるので、**ボス前で引き返せる**
- 「帰還の石」は 80G でよろず屋に並ぶ。**保険を買うかどうかが、そのまま
  どこまで無理をするかの判断になる**
- Esc は帰れなくなった。押すと「階段か帰還の石が要る」と知らせる

> 問いかけの仕組み（`_openPrompt`）は仕掛けの「使う / やめておく」と共通。
> その場で決めることが増えても、同じ形で足せる。

## 結果画面

拠点へ戻る前に必ず通る。何を持ち帰れたか分からないまま終わらないようにするため。

| 出るもの | 中身 |
|---|---|
| 結果 | 帰還 / 討伐 / 勧誘 / 全滅（色も変わる） |
| 到達階 | 「苔むす坑道 B3F まで」 |
| ゴールド | その挑戦で得た額 |
| 持ち帰ったもの | 拾ったアイテムの一覧 |
| 落としてきたもの | 全滅したときだけ |

- 記録は `RunSession` が持つ。**`endRun` で記録が消えるので、その前に控える**
- ゴールドは `Game.giveGold` が挑戦中だけ記録する（全滅しても失わないので、常に「得た額」）
- 到達階はいちばん深く潜ったところ

## 探索中にできること

| キー | できること |
|---|---|
| P / Tab | 仲間の**並び替え**と装備の着け替え |
| I | 持ち物。`usableIn` に `"dungeon"` を書いたものだけ使える |
| F | 中断（問いかけのあと、中断データを書いてタイトルへ。→「探索中は「中断」」） |
| Esc | 拠点へ帰る（拾ったものを持ち帰れる） |

**「仲間」「持ち物」は地図の右下にボタンとしても出る**ので、マウスだけでも開ける
（`data/ui.js` の `dungeon.buttons`）。情報欄と状態欄には重ならない位置にしてある。

### 左上のパーティ表示

**仲間全員の「名前・状態異常の印・HP」**を並べる（`data/ui.js` の `dungeon.partyStatus`）。

- 枠の高さは**人数から決まる**ので、データに高さは書かない
- HPの数値は**残りの割合で色が変わる**（戦闘のHPバーと同じしきい値）。
  倒れている仲間は名前も赤くする
- 状態異常の印は名前のうしろ。**戦闘中に出る印とまったく同じ文字・同じ色**
  （`js/ui/StatusMarks.js`）
- 名前は自分で付けられるので、枠に入らないときは `…` で切り詰める

> 以前は**先頭の1体だけ**を横帯で出していた。
> 控えのHPを見るのに、そのつど仲間画面を開く必要があったのをやめた。
> 毒はダンジョンを歩くあいだも削ってくるので、
> 「いま誰が毒か」がここで分からないと解毒草を使う判断ができない。

- **並び替えで出撃メンバーが変わる。** 戦闘に出るのは先頭から `battleFieldSize`（3）体なので、
  4体目を先頭へ動かせば、その子が戦うようになる
- **探索中は預かり所を出さない。** 拠点にあるものへ手は届かないので、
  表そのものを隠し、「預ける」も選べないようにしてある（`PartyScene` に `allowStorage: false`）
- 探索中に使えるのは回復アイテムだけ（`data/items.js` の `usableIn`）。
  装備・素材・重要アイテムは並んでも選べない

## 戦闘中の交代

コマンドに「交代」がある。**控えの仲間と入れ替えるのが、その仲間のこのターンの行動**になる
（交代した本人は動かない）。

- 盤面は `BattleSystem` の**枠（slots）**。開始時に戦える者を先頭から `battleFieldSize`（3）体入れる
- 交代は枠の中身を入れ替え（`replaceSlot`）、パーティの並びも同じように入れ替える（戦闘後も残る）
- **倒れている仲間は前に出せない**（候補に出ない）
- **控えがいなければ「交代」の項目自体を出さない**（選べないものを並べない）
- 同じターンに2つの枠が同じ控えを選べない（先に選ばれた控えは候補から消える）
- **絵・HP・PPは「交代した」の出来事を見せた瞬間に入れ替わる**（`_showSwap`）。
  演出が終わるまで下がった者が残ることはない

### 倒れた仲間は自動では下がらない（α-7）

**倒れても控えが勝手に前に出ることはない。** 倒れた枠はそのまま残り、次のターンにその枠は
**「交代」と「そのまま」**を選べる（コマンド欄の文は「〜は 倒れている」）。
控えがいなければ、その枠は自動で飛ばされる。

- **「そのまま」は何もせず次の仲間の番へ進む**（`{ type: "skip" }`）。
  控えを温存したい・倒れた仲間を残しておきたいときのための選択肢。
  これが無いと、控えがいる限り交代を強制されてしまう（α-8 で追加）
- 倒れた枠の交代は、**行動順より先**に済む（倒れた者に手番は無い。入った者はそのターン動かない）
- 生きている者の交代は今までどおり素早さ順
- 敗北は**パーティ全員が倒れたとき**のまま。3枠ぜんぶ倒れていても控えが生きていれば続き、
  次のターンは交代しか選べない
- 倒れた仲間は名前を薄く出し、絵は倒れる動きのあとに消える

> 蘇生の技・道具を足すときのための仕様。自動で下がっていると、蘇生する相手が盤面にいない。
> 足すときは `BattleScene._canTarget` で、その行動のときだけ倒れた仲間も狙えるようにする。

> 交代は `BattleSystem` を通さない。
> 道具やスカウトと同じく `onNonSkillAction` で画面側が処理する
> （`BattleSystem` はパーティの並びを知らなくてよい）。

## 戦闘の速さ

出来事1つあたりの待ち時間は `data/ui.js` の `battle.animation`。

```js
eventDelay: 620,                                    // 標準の待ち時間
speedTable: [0.5, 0.65, 0.8, 1.0, 1.25, 1.6, 2.1, 2.8]  // 設定の1〜8に対応
```

| 設定 | 待ち時間 |
|---|---|
| 最も遅い | 1240ms |
| 標準（初期値） | 620ms |
| 最速 | 221ms |

**「標準」で文章を読み切れる**ようにしてある。全体を変えたいときは `eventDelay` を、
段階の刻みを変えたいときは `speedTable` を触る。

> 技の演出は最長680ms（シャドウ）。標準の待ち時間とほぼ同じにしてあるので、
> 演出が終わる前に次の出来事へ進むことはない。

## 技のエフェクト

**技ごとに絵を用意しない。** 形の型を用意し、色は属性から決まる。
技側に書くのは `effect: "burst"` の1行だけ。

```js
// data/skills.js
ember: { ..., element: "fire", effect: "burst" }   // 赤く弾ける
```

| 型 | 見え方 | 使っている技 |
|---|---|---|
| `impact` | 輪が広がり、短い線が四方へ散る | 攻撃 / 体当たり |
| `slash` | 太い筋が斜めに走る（3本が少しずつ遅れて） | 噛みつく |
| `burst` | 中心から粒が放射状に飛ぶ | ファイア |
| `shards` | 粒が横へ飛び、落ちていく | ストーン |
| `flash` | 円が一気に広がって、すぐ消える | フラッシュ / サンダー |
| `radiance` | `flash` の一段上。大きく閃いたあと光の筋が伸び、輪が外へ抜け、少し遅れてもう一度光る | シャイン |
| `rain` | 上から粒が降ってくる | シャドウ / アクア |
| `aura` | 輪が足元から立ち上がり、粒が昇る（弱体は逆向き） | キュア / こうか / ちからぬき |

`radiance` は「属性の基本技より強くなった」と分かる中間の見せ方で、最終奥義用ではない。
さらに上の技を作るときは、この数値を上げるより `SkillEffect.js` に新しい型を足すほうがよい。

**同じ型でも属性で色が変わる。** 火のファイアは赤、水の技なら同じ `burst` が青く出る。

**通常攻撃だけは、出した本人の `attackEffect`（`data/monsters.js`）が優先される。**
牙を持つものは `slash`、硬い体のものは `shards`、書かなければ `impact`。

### エフェクトの濃さ（設定）

設定の **エフェクトの濃さ**（`effectLevel`）で、技の演出と画面の揺れ・発光をまとめて調整できる。

| 設定 | 倍率 | 見え方 |
|---|---|---|
| 全くなし | 0 | **何も描かない**（画面の光と揺れも止まる） |
| 薄め | 0.5 | 濃さ半分・にじみ半分 |
| **標準** | 1.0 | 今までどおり |
| 濃いめ | 1.6 | にじみが強く、**消え際が長く残る** |

対応表は `data/ui.js` の `battle.animation.effectScale`。

> 形の関数はどれも `ctx.globalAlpha` を自分で設定するので、外から掛けても上書きされる。
> そこで `SkillEffect` の中では `setAlpha()` を通し、そこで濃さを掛けてから設定している。
> **新しい形を足すときも `ctx.globalAlpha = ...` ではなく `setAlpha(ctx, ...)` を使うこと。**
無属性の技は `data/elements.js` の `none` の色（灰）になる。

```
data/effects.js ──▶ ui/SkillEffect.js ──▶ ui/EffectPlayer.js ──▶ BattleScene
  （形と時間）        （その瞬間を描く）      （いつ・どこで・何色）
```

- `SkillEffect` は**状態も乱数も持たない**。粒の向きは番号から決まるので、
  何度描いても同じ形になりちらつかない
- 演出は**当たった時点**（`damage` / `miss` / `immune`）で出す。
  技を出した瞬間はまだ届いていないので、踏み込みが終わってから出ることになる
- **外れても効かなくても技は見える**（何が起きたか分かるように）
- `effect` を書いていない技は何も出ない
- 演出が消えきるまで戦闘は終わらない

> 型を増やすときは `data/effects.js` に1エントリ足して、
> `js/ui/SkillEffect.js` の `SHAPES` に描き方を1つ足す。**他は変更不要。**
> 「貫く（beam）」「渦（spiral）」あたりが次の候補。

### コマ絵を描いて渡すとき

**2〜3枚描けば十分。** 滑らかなループを描き切る必要はない。
形の変化はコマ絵が、滑らかさは上の「ずっと続く動き」が担当し、**両方が同時に掛かる**から。

```js
// data/sprites_abyss.js … 絵を1コマずつ登録する
slime1: { palette: {...}, pixels: [...] },
slime2: { palette: {...}, pixels: [...] },

// data/monsters.js … 並べて書く
slime: { sprite: ["slime1", "slime2"], motion: "frameFloat" }
```

**枚数はどこにも書かない。** 絵の枚数から読み取るので、あとから1枚足しても減らしても
`data/motions.js` は直さなくてよい。

| 動き | 切り替わる速さ |
|---|---|
| `frameSlow` | 320ms |
| `frameNormal` | 200ms |
| `frameFast` | 120ms |
| `frameFloat` | 260ms ＋ ふわふわ浮く |
| `slimeIdle` | 220ms ＋ 跳ねる（スライム専用の見本） |

### 見本：スライムの跳ねる動き

**描き足したのは2枚だけ**（潰れた姿・伸びた姿）。ふつうの姿を使い回して4コマにしている。

```js
sprite: ["slimeStretch", "slime", "slimeStretch", "slimeSquash"]
//         0 昇る途中     1 最高点   2 落ちる途中    3 着地（潰れる）
slimeIdle: { frames: { interval: 220 }, offsetY: { amplitude: -2.5, period: 880 } }
```

**コマ絵と上下の揺れをぴったり合わせるには、`コマ数 × interval` を `period` に一致させる。**
ここでは 4×220 = 880ms。こうすると、いちばん低いところで必ず潰れた姿になる。

> `speed`（1msあたりのラジアン）でも書けるが、`2π ÷ 周期` を手計算した丸め誤差で
> 少しずつずれていく。**合わせたいときは必ず `period` で書く。**
> 実際 `speed: 0.00714` で書いたときは、1時間で0.4コマぶんずれていた。

- 3枚とも**足元の行をそろえてある**ので、切り替えても浮き上がらない
- 位相のずらしは「コマ何個ぶん進めるか」として足すので、
  個体ごとにずらしても**コマと揺れの関係は崩れない**（4.9時間まわしてずれ 4.8e-11px）

- 1枚だけの種族はコマが進まないので、**今までの書き方（文字列1つ）もそのまま動く**
- 同じ種族が並んでも、個体ごとに**開始コマがずれる**ので揃わない
- コマが切り替わっても、浮き沈みは飛ばずになめらかに続く

絵はドット絵（`pixels` ＋ `palette`）でも、PNG（`{ src: "..." }`）でもよい。

### 絵の大きさ

**大きさはどこにも書かない。** `AssetLoader` が `pixels` の行数と1行目の文字数から読み取るので、
16×16 と 32×32 と 48×48 が同じゲームの中に混ざっていてよい。
表示サイズは `data/ui.js` 側（戦闘96 / 図鑑72 / 仲間48 / 拠点36）なので、
どの解像度で描いても同じ枠に収まる。

| 大きさ | 使いどころ | 数 |
|---|---|---|
| 32×32 | モンスターの標準／**主人公（2コマ）** | 18種＋2枚 |
| 48×48 | 竜など、特別に大きいもの | ヨミリュウ 1種 |
| 16×16 | 仕掛け・メニューの絵 | 26件 |

> **α-5で全19種を 32×32 以上へそろえた。** モンスターに 16×16 はもう残っていない。
> **α-7で主人公も 32×32 になった**（地図のタイルと同じ大きさなので等倍で出る）。

### 16×16の絵を 32×32 へ上げるとき

**ゼロから描き直さない。** キャラクターが別物になる。実際に一度フレイミンで
「炎をまとう獣」を二足の別モンスターにしてしまい、描き直すはめになった。

やることは次の3つだけ。

1. **2倍に拡大する**（シルエットが1マスも変わらない）
2. 拡大でできた**四角い出っ張りの角を1マス落とす**（ギザギザを消す）
3. 内側を**明暗6段**で塗り直す。元の絵で内側にあった輪郭線は、
   いちばん暗い段で「面と面のさかい」として戻す

目・苔・傘のまだらなど、**意味のある色はそのまま残す**。

そのうえで、材質が違う部分だけ段を差し替える。

| 例 | 差し替え | 理由 |
|---|---|---|
| コウモリの翼 | 体より一段暗く | 角を丸めると翼と体が溶けて一枚の板になる |
| ヒカリムシの翅 | 水色の段へ | 同じ階調だと体から生えた光の塊になる |
| キノコンの柄 | 白い段へ | 傘と柄は別材質。同じ階調だと一続きの塊になる |
| イワゴローの岩肌 | 3×2マスのノイズでざらつかせ | なめらかだとスライムの質感になる |

**コマ絵は足元の行がそろっていることを必ず確かめる。**
スライムの3枚（`slime` / `slimeStretch` / `slimeSquash`）は変換後も足元が29行目でそろっている。
ここがずれると、跳ねる動きで絵が切り替わるたびに浮き上がる。

- **解像度と「画面での大きさ」は別物。** 画面で大きく見せたいときは
  `data/monsters.js` の `sizeScale` を使う。**表示だけで、ステータスには効かない**

| | `sizeScale` | 戦闘での大きさ |
|---|---|---|
| 雑魚 | （書かない＝1） | 96px |
| モスゴーレム（坑道の主） | 1.15 | 110px |
| マグマウルフ（亀裂の主） | 1.25 | 120px |
| ヨミリュウ（竜） | 1.35 | 130px |
| キングスライム（深層の主） | 1.4 | 134px |

  主は奥のステージほど大きくしてある。戦闘に入った瞬間に格が伝わるようにするため。
  絵は下端をそろえて描かれるので、大きくしても足元は同じ高さに来る
- 32px で描くときは、**細部より形**を優先する。拠点は36pxまで縮むので、
  模様は消えてもシルエットは残る
- 同じステージの種族は**シルエットで見分けがつく**ようにする。
  深層の4種は「上が細い / ぶら下がる / 上が重い / 小さくて浮く」で分けてある。
  目も単眼・スリット・複眼と変えてあるので、縮んでも取り違えない

## 仕掛けマス（宝箱・泉・罠）

階層を生成するたびに、床のどこかへランダムに置かれる。

| 仕掛け | 見た目 | 内容 |
|---|---|---|
| 宝箱 | 木箱に金の帯 | 中身を1つ抽選（下記） |
| 泉 | 石のふちと水面 | 仲間全員のHPとPPを**最大値の50%**回復。1回だけ。**踏むと使うか選べる** |
| 罠 | **踏むまで見えない** | 仲間全員が最大HPの12%のダメージ |

### 宝箱の中身 —— 共通＋その場所の素材

中身は2か所に分けて書く。**上書きではなく足し算**なので、共通の中身はどこでも出続ける。

| 書く場所 | 何を書くか |
|---|---|
| `data/features.js` の `chest.effect.table` | **どのダンジョンでも出るもの**（消耗品だけ） |
| `data/dungeons.js` の `featureTables.chest` | **その場所でしか出ない素材** |

```js
// data/dungeons.js
featureTables: {
  chest: [
    { item: "emberAsh", weight: 0.45, min: 1, max: 2 }
  ]
}
```

**現在の中身**（重みは合計で割った割合）

| | 薬草 | 精気の実 | 回復薬 | その場所の素材 |
|---|---|---|---|---|
| 共通の重み | 1.0 | 0.3 | 0.2 | — |
| 苔むす坑道 | 42.6% | 12.8% | 8.5% | 鉱石のかけら 21.3%（1〜2個）／光る鱗粉 14.9% |
| 灼熱の亀裂 | 35.1% | 10.5% | 7.0% | 燃え殻 15.8%（1〜2個）／灰の羽根 12.3%／鉱石のかけら 10.5%（1〜2個）／焼けた殻 8.8% |
| 静寂の深層 | 52.6% | 15.8% | 10.5% | 深淵の欠片 21.1% |

- 素材が出る割合は 坑道 **36.2%** / 亀裂 **47.4%** / 深層 **21.1%**
- **主が落とす素材（苔むした核・灼熱の牙）は入れない。** 倒すこと自体に意味を残すため
- 鉱石のかけらは坑道と亀裂の両方に置いてある（ヒビイワとマグマガニも落とすため）
- 深層が薄いのは在来種がまだ無いから。在来種を足すたびに、その素材をここにも並べる

> 足し算にしているのは `js/systems/FeatureSystem.js` の `_effectFor`。
> 共通の表は複製してから足すので、**元の表は書き換わらない**
> （ダンジョンをまたぐと中身が増え続ける、という不具合を防ぐため）。
> ★ 新しいステージの宝箱に素材を入れるとき、コードを触る必要はない。

### 見た目

仕掛けはモンスターと同じ**ドット絵**で描く（`data/sprites_features.js`）。

| 状態 | 宝箱 | 泉 | 罠 |
|---|---|---|---|
| 置かれている | 閉じた宝箱 | 水をたたえた泉 | **描かない**（隠れている） |
| 使ったあと | フタの開いた宝箱 | 水の引いた泉 | 棘の出た穴 |

**使ったあとも跡が残る**ので、通った場所がひと目で分かる。
`data/features.js` の `sprite` と `usedSprite` で指定する。
`usedSprite` を書かなければ、使った時点で見えなくなる（従来どおり）。
絵を用意していない仕掛けは、`mark` の記号で描かれる。

### 使うかどうかを選べる仕掛け

`data/features.js` に `confirm: true` と書いた仕掛けは、
踏んでも**すぐには発動せず**、「使う / やめておく」を聞いてくる。

```
    ┌─────────────────────┐
    │ 澄んだ泉がわいている。      │
    │ 水を浴びますか?           │
    ├─────────────────────┤
    │ ▶ 使う                  │
    │   やめておく             │
    └─────────────────────┘
```

- **やめておいた仕掛けは使われないまま残る。** 傷ついてから戻ってくれば使える
- Esc / 右クリックは「やめておく」と同じ扱い
- 聞いている間は動けない（誤って通り過ぎないように）
- 問いかけの文は `data/messages.js` の `feature.〇〇Prompt`（`\n` で改行）、
  やめたときの文は `feature.〇〇Skipped`。`〇〇` は仕掛けのid

現在これが付いているのは**泉だけ**。宝箱と罠は今までどおり踏んだ瞬間に発動する。

- どれも**一度使うと効果はなくなる**（跡は残る）
- 開始位置と階段の上には置かれない
- 罠では**HPが1未満にならない**ので、罠だけで全滅することはない
- 仕掛けを踏んだその一歩では敵と遭遇しない
- 宝箱の中身はランの記録に入るので、**全滅すると失う**

個数は `data/dungeon.js` の `featureCounts`（全ダンジョン共通の既定）。
ダンジョンごとに変えたい場合は `data/dungeons.js` の `features` に書く。

```js
featureCounts: {
  chest:  { min: 1, max: 2 },
  spring: { min: 0, max: 1 },
  trap:   { min: 1, max: 2 }   // 中身は data/features.js の chest.effect.table
}
```

### 仕掛けを追加するとき

`data/features.js` に1エントリ足し、個数を指定するだけでよい。

```js
healSpot: {
  id: "healSpot", name: "祠", mark: "祠", color: "#e8b4ff",
  hidden: false, once: true,
  effect: { type: "heal", hpRatio: 1.0, ppRatio: 1.0 }
}
```

| 効果の種類 | 内容 |
|---|---|
| `giveItem` | `table`（重み付き）から1つ選んで渡す |
| `heal` | `hpRatio` / `ppRatio` の割合で回復 |
| `damage` | `hpRatio` の割合でダメージ。`leaveAtLeast` は必ず残すHP |

- `hidden: true` にすると踏むまで表示されない（罠など）
- 新しい**効果の種類**を足すときは `js/systems/FeatureSystem.js` の
  `EFFECT_HANDLERS` に関数を1つ追加する

## ダンジョン（ステージ選択）

拠点の「ダンジョンへ潜る」を選ぶと**ダンジョン選択画面**が開く。
挑む場所を選ぶ形式で、場所ごとに深さ・出る敵・ボスが違う。
**マップそのものは今までどおり毎回ランダム生成**される。

| ダンジョン | 最深 | 出現Lv | 敵の数 | ボス | 開放条件 |
|---|---|---|---|---|---|
| 苔むす坑道 | B3F | 階ごと（下記） | 階ごと（下記） | 坑道の主（モスゴーレム Lv8） | 最初から |
| 灼熱の亀裂 | B4F | 階ごと（下記） | 階ごと（下記） | 灼熱の獣（マグマウルフ Lv12） | 苔むす坑道をクリア |
| 静寂の深層 | **B4F** | 階ごと（下記） | 階ごと（下記） | 深層の主（キングスライム **Lv18**） | 灼熱の亀裂をクリア |
| **腐食の毒沼** | **B3F** | 14〜19 | 階ごと（下記） | 沼の主（ヌシガエル **Lv21**） | 静寂の深層をクリア |

**腐食の毒沼の階ごとの出方**（推奨レベル20）

| 階 | 出現Lv | 敵の数 | 出方 |
|---|---|---|---|
| B1F | 14〜17 | 1〜2体 | 浅場。ドクバチ42%／ドロガメ33%／ヌマボネ25% |
| B2F | 14〜19 | 2体 100% | **ドロガメ40%** に増える。壁役が2枚並ぶ |
| B3F | **17〜19** | 1体 40% ／ 2体 40% ／ **3体 20%** | 主の直前 |

> **3階しかない。** 亀裂・深層（4階）より短いのは、
> 歩くだけで毒が削ってくる場所だから。長いと「削られに行くだけの階」が増える。
> そのぶん1階ごとの密度を上げてある。**加護を選べるのは2回**（深層は3回）。

**静寂の深層の階ごとの出方**（推奨レベル16）

| 階 | 出現Lv | 敵の数 |
|---|---|---|
| B1F・B2F | 10〜13 | 1体 50% ／ 2体 50% |
| B3F | 10〜15 | 2体 100% |
| B4F | **13〜15** | 1体 40% ／ 2体 40% ／ **3体 20%** |

> **B4Fだけ体数を重み付きにしてある。** 均等（1〜3体）だと3体が33%も出て、
> 主の直前が重くなりすぎるため。`groupSize` は `{min,max}` でも
> `[{count,weight},…]` でも書ける（`data/dungeons.js` を参照）。
>
> **ヨミリュウはB4Fの表にだけ載せてある**（16%）。階を絞るだけなら、出現テーブルのエントリに
> `minFloor: 3` と書く方法もある（`maxFloor` もある）。

#### 門番としてのヨミリュウ

主ではないが、**主と同じ2つの仕組みを在来種のエントリに書いてある**（`data/dungeons.js`）。
どちらも「立ちはだかるあいだだけ」で、**仲間にすると外れる**。

```js
{ species: "abyssDragon", weight: 0.16,
  solo: true,                                              // 引かれたら単体戦
  statMultiplier: { hp: 2.25, attack: 0.9, defense: 1.25 },  // 1体ぶんの手応え
  actionPattern: ["abyssBreath", "bite", "normalAttack"] }   // 3手で一巡
```

| | |
|---|---|
| `solo` | 竜＋雑魚2体は推奨Lv16で勝率33%、竜2体は13%、単体なら97%だった。**出会う確率は変えず、体数だけ**外している |
| `statMultiplier` | Lv13で 75/36/35/24 → **170/32/43/24**。HPと守りを厚く、攻撃は落として「長く殴り合う相手」にしてある（事故で溶かされない） |
| `actionPattern` | 闇の息（全体）→ 噛みつく → 通常攻撃。**読めれば「息の番だけ守る」**という戦い方ができる |

闇が完全に効かず（耐性+10）、**光だけ2倍**（-5）。答えはステージ1のヒカリムシが覚えるフラッシュ。
知らないと詰み、知っていれば勝てる、という形にするための配置なので、耐性と光の弱点はセットで扱う。

- **最深階の階段でボスが出る**。それより浅い階の階段は次の階へ降りるだけ
- ボスに勝つと、そのダンジョンが**クリア済み**になり、次のダンジョンが開放されて拠点へ戻る
- **主からは共通して逃げられない**（`data/battle.js` の `bossCanFlee`）。
  ボス戦のコマンドに「逃げる」自体が出ない
- **はじめてクリアしたときだけ、その場で自動セーブする**（結果画面に「セーブ済み」と出る）
- `isFinal: true` のボスを倒したときだけエンディングへ進む。**いまは全ボスが false**
- 未開放のダンジョンは灰色で表示され、決定を押しても入れない（開放条件が出る）

> **クリアだけは手動セーブに任せない。**
> このゲームは手動セーブだが、クリアは「1回の挑戦の成果」ではなく
> 次のダンジョン・店・工房が開く**恒久的な変化**。
> セーブし忘れて消えると、もう一度主を倒しに行くことになる。
> 保存するのは `endRun` のあと ＝ 拠点に着いた状態（全快後・マップは持たない）。
>
> 全滅したときは保存しない。やり直せる余地は残したままにしてある。

> **灼熱の亀裂は在来種5種＋専用ボスがそろった。**
> 坑道のモンスター（コウモリ・スライム）は出さない方針。

**出やすさと役どころ**（重みの合計に対する割合）

| | 重み | 割合 | 役どころ |
|---|---|---|---|
| スミビ | 1.2 | 27% | いちばん弱い数合わせ。2発で落ちる |
| フレイミン | 1.0 | 23% | 標準的な攻め手 |
| ハイバネ | 0.9 | 20% | 最速。紙装甲 |
| ヒビイワ | 0.7 | 16% | 硬い壁。地で崩れる。**稼ぎ相手** |
| マグマガニ | 0.6 | 14% | 守りを固めてくる壁。**経験値が最多** |

弱いものほど重みを大きくして、**雑魚が多く・壁役はたまに**出るようにしてある。

**階ごとの出方**（`perFloor`）

| | 出現Lv | 敵の数 |
|---|---|---|
| B1F・B2F | 4〜8 | 1〜2体 |
| B3F・B4F | **5〜10** | **2〜3体** |

上2階は浅場、下2階でレベルも数も一段上がる。
**1戦あたりの重さ**（平均体数 × 平均レベル）で見ると 9.0 → 18.8 でちょうど倍。
苔むす坑道の最深部（4.5）から亀裂の入口（9.0）も倍なので、段差の付き方がそろっている。
- ボス名は**クリアするまで「？？？」**（`data/messages.js` の `dungeonSelect.unknownBoss`）
- クリア済みの記録はセーブに含まれる（古いセーブを読み込んだ場合は「未クリア」扱い）

| B1F | 1 | 1体 |

| 表示 | 内容 |

| 手に入るもの | 出るモンスターが落とすアイテムをまとめたもの。文字色は**分類の色** |

### ダンジョンを追加するとき

`data/dungeons.js` に1エントリ足すだけでよい（コードの変更は不要）。

```js
frozenHollow: {
  id: "frozenHollow", order: 4,
  name: "凍てつく空洞",
  subtitle: "一覧に出る短い説明",
  description: "詳細に出す説明。\n改行できる。",
  floors: 6,
  unlockedBy: "silentDepths",          // null なら最初から挑める
  generation: { width: 25, height: 18, roomMin: 3, roomMax: 7, roomCount: 8 },
  encounter: {
    rate: 0.09,                         // 1歩あたりの遭遇確率
    groupSize: { min: 2, max: 3 },
    levelRange: { min: 18, max: 24 },
    table: [ { species: "slime", weight: 1.0 } ]
  },
  boss: "frostLord"                     // data/bosses.js のid
}
```

- `order` が選択画面の並び順
- `region` はどの地方（穴）にあるか。`data/regions.js` の id で、現在はすべて `"cradle"`（揺籃の穴）。
  地方の名前はダンジョン選択の見出しの下に出る
- `generation` を省いた項目は `data/dungeon.js` の既定を使う（画面が広がる訳ではないので `width`/`height` は画面サイズが上限）
- `encounter.rate` を省くと `data/enemies.js` の `encounterRate` を使う
- ボス側は `data/bosses.js` に同じidで足す

### ダンジョンの見た目（テーマ）

ステージごとに**色と床の飾り**を変えられる。定義は `data/dungeonThemes.js`、
ダンジョン側は `theme: "mine"` のようにidで結びつけるだけ。

| ダンジョン | テーマ | 色 | 床の飾り |
|---|---|---|---|
| 苔むす坑道 | `mine` | 緑がかった湿った岩 | 苔・小石 |
| 灼熱の亀裂 | `ember` | 焼けた赤黒い岩 | 熱を持った床のひび・小石 |
| 静寂の深層 | `depths` | 冷たい青紫 | 古い骨・小石 |
| **腐食の毒沼** | `venom` | 体に悪い黄緑 | 苔・骨・小石 |

> **坑道と同じ緑にしないこと。** 坑道は「湿った岩と苔」の落ち着いた深緑（壁 `#3a4a3c`）、
> 毒沼は「体に悪い」黄緑（壁 `#4a5a2e`）。彩度と黄色みで振り分けてある。

```js
mine: {
  background: "#060a08",                       // マップの外側
  tiles: { wall: "#3a4a3c", floor: "#141c17", stairs: "#2a3a2c" },
  stairsMark: { color: "#ffb15e" },            // 省略可（階段の記号の色）
  decorations: {
    count: { min: 10, max: 16 },               // 1階層あたりの個数

      { sprite: "decoMoss",   weight: 1.0 },
      { sprite: "decoPebble", weight: 0.6 }
    ]
  }

```

- 書かなかった項目は**既定の色**（`data/dungeon.js` と `data/ui.js`）をそのまま使う。
  `theme` を書かないダンジョンは今までと同じ見た目になる
- **飾りは見た目だけ**。当たり判定も効果もなく、踏んでも何も起きない
- 開始位置・階段・仕掛けの上には置かれない（宝箱を隠さないため）
- 飾りは保存しない。階を作り直すたびに撒き直される
- 飾りの絵は `data/sprites_features.js`（`decoMoss` / `decoPebble` / `decoEmber` / `decoBone`）。
  増やすときは、そこに1つ足して `table` に並べるだけでよい

> 同じテーマを複数のダンジョンで使い回してもよい。
> 地方が増えたら、その地方のテーマをこのファイルに足して見た目を揃える。

### 解放条件の書き方

`unlockedBy` は次の4通りが書ける。判定は `js/systems/DungeonCatalog.js` の `isUnlocked`。

```js
unlockedBy: null                                  // 最初から挑める
unlockedBy: "mossyMine"                           // そのダンジョンをクリア
unlockedBy: ["mossyMine", "scorchingFissure"]     // 並べた全部をクリア
unlockedBy: { dungeons: [...], count: 2 }         // 並べたうちの2つをクリア
unlockedBy: { region: "cradle" }                   // その地方を全部クリア
unlockedBy: { region: "cradle", count: 3 }         // その地方のうち3つをクリア
```

地方単位で書けるのは、**今後「この地方を全部クリアしたら次の地方が開く」形にするため**。

### α-9 の勝率（主4体とヨミリュウ）

α-9 の変更前後で、同じ乱数・同じパーティを戦わせて比べた（各300戦）。
**味方は素の3体**（道具・加護・装備なし、回復も防御もしない）。毎ターン「いま撃てる中でいちばん効く技」を撃つ。

> 深層の主の「前」30% は、`data/bosses.js` に書いてある以前の実測（22〜29%）とほぼ一致しているので、
> 測り方は以前と揃っている。

| 相手 | 味方 | 前 | 今 |
|---|---|---|---|
| 坑道の主 | Lv6 スライム・イワゴロー・キノコン | 63% | **99%** |
| 灼熱の獣 | Lv11 スライム・イワゴロー・ヒカリムシ | 9% | **53%** |

> 技の段階（tier2〜4）を足すとこちらの火力はさらに伸びるので、主は技の追加と合わせて見直す予定。

## 戦闘システム（3対3）

- 連れていけるのは最大 **6体**（`config.partyMax`）、盤面に出るのは先頭から **3体**（`config.battleFieldSize`）
- 盤面の味方**全員のコマンドを決めてから**、味方・敵をまとめて**素早さの大きい順**に行動する
- 素早さは `baseSpeed`（`data/monsters.js`）から、レベル・性格・個体値を掛けて算出する
- 味方が倒れても**自動では入れ替わらない**。次のターンに「交代」で入れ替えるか、「そのまま」で見送る（→「戦闘中の交代」）。**全員倒れて初めて敗北**
- 戦闘中だけ使う印（`_removed` / `_defending`）は、**戦闘開始時に必ず消してから付け直す**
  （`BattleSystem._resetFieldMarks`）。特にスカウトで仲間になった個体に `_removed` が残ると、
  その仲間は次の戦闘以降ずっと行動しなくなる
- 攻撃対象は「並びの番号」ではなく**選んだ個体そのもの**で覚える。先に別の相手が倒れて並びがずれても、狙った相手を攻撃する（狙った相手が倒れていた場合だけ他へ切り替わる）
- 同じ名前の敵が並んだときは **A・B・C** の印が付き、ログでは敵の名前に **「敵の」** が付く（味方と敵に同名がいても見分けられる）
- 同じ素早さのときの順番は `data/battle.js` の `speedTieBreak` で決める

### 計算式

```
実効ステータス = floor( 基礎値 × (1 + (Lv-1) × 成長率) × 性格補正 × 効果倍率 ) + 個体値 + 効果加算
                 （効果＝特性・装備・加護・バフ／デバフ）

基礎ダメージ（技）     = 攻撃力×0.40 + 技威力×1.35 - 防御力×0.30   （0未満は0）
基礎ダメージ（通常攻撃）= 攻撃力×0.75              - 防御力×0.30
                 「通常攻撃」は normalAttackSkill の技だけ。体当たりなどの無属性技も「技」の式
ダメージ     = floor( 基礎 × 属性倍率 × 会心倍率 × 防御倍率 × 効果倍率 × 乱数(0.9〜1.1) )
                                                                       （最低1。無効なら0）

属性倍率 = 耐性0以上: 1 - 耐性×0.10 ／ マイナス: 1 + |耐性|×0.20 ／ +10で無効
会心倍率 = 2.0（確率 3% ＋ 技のcriticalBonus）
命中     = 技の accuracy（未指定なら 100%）× 盲目などの倍率。そのあと相手の回避率で再判定
行動順   = 素早さ × 乱数(0.8〜1.2) の大きい順
必要経験値 = floor( 12 × Lv ^ 1.5 )

もらえる経験値 = floor( expReward × (1 + (相手のLv - 1) × 0.15) )
```

数式の一覧と例は **`早見表/計算式.txt`** にまとめてある（こちらが最新）。

**倒した相手のレベルが高いほど、もらえる経験値が増える**（`data/growth.js` の `expRewardPerLevel`）。
`monsters.js` の `expReward` は Lv1 のときの量。0 にするとレベルに関係なく一定になる。

| | Lv1 | Lv3 | Lv6 | Lv10 |
|---|---|---|---|---|
| コケネズミ（基準11） | 11 | 14 | 19 | 25 |
| キノコン（基準16） | 16 | 20 | 27 | 37 |
| モスゴーレム（基準90） | 90 | 117 | 157 | 211 |

主を倒したときにもらえる量：坑道の主（Lv8）**184**、灼熱の獣（Lv12）**304**、深層の主（Lv18）**284**。

**1戦あたりの取り分**（その階の平均体数込みの実測）

| | 経験値 | ゴールド |
|---|---|---|
| 苔むす坑道 B1F / B3F | 12 / 23 | 6 / 12 |
| 灼熱の亀裂 B1F / B4F | 36 / 68 | 20 / 37 |
| 静寂の深層 B1F / B3F | 73 / 115 | 37 / 61 |

> **ボスの `expReward` / `goldReward` は、レベルを上げると一緒に膨らむ。**
> レベルで強くするとレベルで報酬も増えるので、
> 強さは `data/bosses.js` の `statMultiplier` で足し、報酬は基準値で別に決める。

通常攻撃は「威力0の技」として同じ式で計算する（`data/skills.js` の `normalAttack`）。

### 相性の伝え方

**「効果は抜群だ!」「効果はいまひとつだ...」という文章は出さない。**
ダメージの数字と画面の効果（橙に光る／数字が小さく灰色になる）で伝える。

- 文章で出したくなったら `data/messages.js` の `battle.effective` / `battle.resisted` に
  文言を書き戻すだけでよい（**空文字なら、その行は表示されない**）
- 「{target} には効かない!」は残してある。ダメージ0の理由が分からなくなるため

### 属性と耐性

属性は **火・水・風・地・雷・光・闇** の7種＋**無**（`data/elements.js`）。
「無」は耐性の影響を受けない（`physical: true`）。通常攻撃や体当たりに使う。

耐性は `data/monsters.js` の `resistances` に **-5〜10** で書く。
**プラス側とマイナス側で1あたりの効き方が違う。**

```
耐性が0以上   … 倍率 = 1 - 耐性 × 0.10   （+10 で無効）
耐性がマイナス … 倍率 = 1 + |耐性| × 0.20 （-5 で2倍）
```

| 耐性 | 倍率 | | 耐性 | 倍率 |
|---|---|---|---|---|
| **+10** | **無効（0）** | | 0 | ×1.00 |
| +9 | ×0.10 | | -1 | ×1.20 |
| +8 | ×0.20 | | -2 | ×1.40 |
| +6 | ×0.40 | | -3 | ×1.60 |
| +5 | ×0.50 | | -4 | ×1.80 |
| +3 | ×0.70 | | **-5** | **×2.00** |
| +1 | ×0.90 | | | |

弱点側を2倍の速さで動かしているのは、**「苦手な相手にはよく通る」をはっきり見せるため**。
耐性 -2 でも1.4倍になるので、少ない値でも相性が伝わる。

**耐性 +10 は「無効」と同じ扱い**になり、ダメージ0で「〜には効かない!」と出る。
`immunities: ["light"]` と書いた場合も同じ結果になる（耐性を上げきる道と、
最初から無効にする道の2通りがある）。

**種族の値＋装備の合計は +10 〜 -5 に収まる**（`maxValue` / `minValue`）。
+10 が無効なので、そこから先はいくら足しても効果が変わらない。
毒耐性8のスライムに毒よけの護符（+7）を着けても **+10 と出る**。
装備を重ねても壊れないための決めごとで、挟むのは `MonsterInstance._clampResist` 一か所だけ。

数値はすべて `data/battle.js` の `resistance`
（`resistStep` / `weaknessStep` / `immuneAt` / `maxValue` / `minValue`）で決まる。

### 属性ごとの役どころ

耐性や新しい技を決めるときの拠りどころ。**詳しくは `data/elements.js` のコメント**に書いてある。

| 属性 | 役どころ | 技 | 装備 |
|---|---|---|---|
| 火 | 標準的な攻め手 | ファイア／火の息 | 炎よけの札（耐性+3）／**燃え殻の剣**（与ダメ×1.10） |
| 水 | 火と岩に強い。スライム系が得意 | アクア／あわ | — |
| 風 | 使い手も弱点も少ない | ウィンド | **風乗りの羽飾り**（与ダメ×1.10） |
| 地 | 坑道では通りにくいが、亀裂と深層に弱点がある | ストーン | 泥重の甲（耐性+3） |
| **雷** | **使い手が少ない代わりに技が強力。多くの相手に通る** | **サンダー**（威力20/PP3） | **帯電の芯**（与ダメ×1.10）／雷光の羽衣（耐性+2） |
| 光 | 闇と対。深層の竜への唯一の答え | フラッシュ／**シャイン**（威力32/PP5） | 光る提灯（与ダメ×1.15） |
| 闇 | 光と対。深層の主属性 | シャドウ／**奈落の息** | **宵よけの札**（耐性+3）／**竜牙の指輪**（与ダメ×1.15）／沼骨の槍（×1.10）／黄泉鱗の鎧（耐性+2） |

> **与ダメージを強める装備は 火・風・雷・光・闇 の5つ**（水・地の分はまだ無い）。
> 耐性を上げる装備は 火・地・雷・闇 の4つ。

> **雷の釣り合いは PP で取る**方針。威力を上げるかわりに消費PPを重くし、
> 「強いが撃てる回数が少ない」形にする。入手の難しさだけで縛らない
> （運が悪いと一生触れないため）。

### 成長率

`data/monsters.js` の `growthRate` でモンスターごとに設定する。**0.01〜0.55**の範囲（`data/growth.js` の `minGrowthRate` / `maxGrowthRate`）に自動で収まる。

```js
growthRate: 0.10                                          // 全ステータス共通
growthRate: { hp: 0.15, attack: 0.15, defense: 0.17,      // ステータスごとに指定
               speed: 0.14, pp: 0.10 }
```

- オブジェクトで書けば **HP・攻撃・防御・素早さ・PP を別々**に設定できる
- 書かなかった項目は `default` →（それも無ければ）`growth.js` の `defaultGrowthRate` の順に使う
- 未指定の種族は `defaultGrowthRate`（0.06）

**現在の設定**

| モンスター | HP | 攻撃 | 防御 | 素早さ | PP |

### 特性（アビリティ）

モンスターが常に持っている効果。`data/abilities.js` で定義し、`data/monsters.js` の `abilities` に
特性idを書いて割り当てる。

> **1体が持てる特性は `data/config.js` の `abilityMax`（現在 1つ）まで。**
> データに多く書いても、先頭から数えてこの数までしか効かない。
> 複数持たせたくなったら `abilityMax` を増やすだけでよい。

```js
guts: {
  id: "guts", name: "こんじょう",
  description: "HPが少なくなると攻撃が大きく上がる。",
  effects: [
    { type: "statMultiplier", stat: "attack", value: 1.5,
      condition: { hpBelow: 0.25 } }
  ]
}
```

| 効果の種類 | 内容 |
|---|---|
| `statMultiplier` | HP・攻撃・防御・素早さ・PP に倍率（`stat` で指定） |
| `damageDealt` | 自分が**与える**ダメージに倍率。`element` で属性を限定できる |
| `damageTaken` | 自分が**受ける**ダメージに倍率。`element` で属性を限定できる |

条件（`condition`）を付けると、その状況のときだけ効く。

| 条件 | 内容 |
|---|---|
| `hpBelow` | HP割合がこの値以下のとき（0.25 なら1/4以下） |
| `hpAbove` | HP割合がこの値以上のとき |

同じ種類の効果が複数あれば、倍率はすべて掛け合わされる。

### 強化・弱体（バフ／デバフ）

**状態異常とは別の仕組み。** ステータスや倍率が変わるだけで、行動そのものは変えない
（状態異常は次の節）。

技に `modifier` を1つ足すだけで、バフ技もデバフ技も書ける。

```js
harden: {
  id: "harden", name: "こうか",
  power: 0, pp: 2, target: "self", element: "none", effect: "aura",
  modifier: {
    duration: 3,                                 // かけたターンを含めて数える
    message: "{target} の 守りが 高まった!",       // 省略可
    effects: [ { type: "statMultiplier", stat: "defense", value: 1.5 } ]
  }
}
```

`effects` の書き方は**特性・装備・加護とまったく同じ**。`EffectSystem` が
`monster.modifiers` も読むようにしてあるので、**ステータス計算もダメージ計算も変更不要**。
攻撃・防御・素早さ・与ダメージ・被ダメージが最初から全部使える。

| | 決めごと |
|---|---|
| 重ねがけ | **効果は重ならず、残りターン数が建て直されるだけ**（強さが青天井にならないように） |
| 別の技どうし | 共存する（防↑と速↓が同時に掛かる） |
| 威力0の技 | ダメージを与えない。`power` があれば、掛けたうえで殴る |
| `target: "self"` | 相手を選ばずにそのまま出せる |
| 戦闘が終わったら | **全部消える**（`clearAllModifiers`）。セーブにも含めない |
| 画面 | 名前の横に「防↑」（緑）「攻↓」（赤）。文字は `messages.js` の `statMarks` |
| 演出 | **掛かった瞬間に1回だけ**出る（出っぱなしにはならない）。ずっと見えるのは名前の横の印のほう |

> **印は `monster.modifiers` を直接描いてはいけない。**
> 1ターンぶんの計算は `takeTurn` で一度に終わり、そのあと出来事を1つずつ見せていく。
> つまり効果は「見せる前」からもう掛かっているので、そのまま描くと
> **まだ順番が回っていない相手の印が先に出てしまう**（実際にそのバグが出た）。
> HPバーを `HpAnimator` で遅らせているのと同じ理由で、
> 印は `BattleScene.shownModifiers` に別で持ち、`modifier` / `modifierEnd` の
> 出来事を見せた瞬間に増減させる。見せ終わりに `_syncModifierMarks` で実際の状態に揃える。

**強化・弱体の演出だけは、属性ではなく「何が変わるか」で色が決まる。**
`data/effects.js` の `statColors` で指定していて、守り＝青・攻撃＝赤・素早さ＝緑。
色は上下で変えず、**向きで見せる**——強化は輪が**下から上へ**、弱体は**上から下へ**流れる
（`EffectPlayer.play` の `direction`）。

> **防御の倍率だけでは効かない。** ダメージ式は `防御 × 0.25` を引くだけなので、
> `statMultiplier defense ×1.5` では2ダメージしか減らない（6発が8発になる程度）。
> かといって ×3.0 まで上げるとダメージが11→2まで落ちて極端になる。
> **守りのバフは `damageTaken` を混ぜる**のが素直（防御コマンドも `damageTaken 0.5` で作られている）。
> こうかは 防御×1.5 ＋ 被ダメージ×0.8 の2本立てで、6発→10発になる。

> **敵AIは、すでに効いている自分向けの強化を選び直さない**（`_modifierAlreadyOn`）。
> 重ねがけはターン数が建て直されるだけなので、掛け直すと手番を捨てることになるため。

入れ物は `MonsterInstance.modifiers`。状態異常用の `statusEffects` とは**別の配列**にしてあるので、
状態異常と混ざらない。

> 新しい**効果の種類**を足すときは `js/systems/EffectSystem.js` に集計メソッドを追加する。
> 特性の追加・数値変更は `data/abilities.js` の編集だけで済む。
> 同じ効果の形式は**装備でも使える**（「ゴールドと装備」の章を参照）。

### 状態異常

**バフ／デバフとの違いは「行動そのものを変える」こと。** 中身は `data/statuses.js`。

技に1行足すだけで付与できる（書き方は `modifier` と同じ考え方）。

```js
venomFang: { ..., status: { id: "poison", chance: 0.45 } }
```

| | 効果 | 続く長さ |
|---|---|---|
| **毒** | ターン終了時に最大HPの1/8（上限50）。**ダンジョンでも5歩ごとに1** | 自然には解けない |
| 麻痺 | 50%の確率で行動できない | 3〜5ターン |
| 眠り | 必ず行動できない。**殴られると50%で起きる** | 2〜4ターン |
| 封印 | 技が使えない（**通常攻撃はできる**） | 2〜5ターン |
| 盲目 | 命中率 ×0.65 | 2〜4ターン |
| 呪い | 受けるダメージ ×1.3 | 3〜5ターン |
| 即死 | 当たった時点で戦闘不能 | — |

**耐性は属性耐性とまったく同じ式**（`data/battle.js` の `resistance`）。
種族は `statusResist: { poison: 5 }`、装備は属性と同じ `resistBonus` で足す。
覚える仕組みを2つにしないため。**10で無効、5で半減**。
上限・下限も属性と共通で、**素＋装備の合計は +10 で頭打ち**になる。

> **α-8 で種族の耐性を大幅に下げた。** ほとんどの種族・ほとんどの状態異常が **0** で、
> 耐性を持つのは「その状態異常を受ける理由が無い」相手だけ（岩は毒が効かない、
> 目に頼らない相手は盲目が効かない、など）。
> 種族の耐性が高いままだと、装備（毒よけの護符 +7 など）で足しても効きが変わらず、
> **装備を着ける理由そのものが無くなる**ため。全23種の値は `早見表/状態異常耐性.txt`。

| | 決めごと |
|---|---|
| 重ねがけ | 残りターン数が建て直されるだけ（バフ／デバフと同じ） |
| 種類違い | 同時に掛かる（毒を受けている最中に眠りも入る） |
| 戦闘が終わったら | `persists` 以外は消える。**毒だけ残る** |
| 拠点へ帰ったら | **全部消える**（`Game.endRun` の `healOnReturn` と同じ扱い） |
| セーブ | **含める**。毒が残ったままセーブできるので、再開しても消えない |
| 主（ボス） | **即死・封印・盲目が効かない**（全ボス共通。`data/battle.js` の `bossImmuneToStatus`）。毒は仕組みとしては効くが、**いまの主4体は個別に無効**（HPが小さく1ターン10%以上削れるため。`data/bosses.js` の `immuneToStatus`）。結果いま効くのは麻痺・眠り・呪い。仲間に迎えると種族の耐性に戻る |
| 画面 | 名前の横に**絵**（`icon`。無ければ `short` の1文字）。**戦闘・探索の左上・仲間画面で同じ印**（`ui/StatusMarks.js`） |

### 絵の印（α-8）

属性・状態異常・強化／弱体は、文字ではなく **16×16 の絵**で出す（`data/sprites_icons.js`）。

| 何の絵 | どこから引く | 使う場所 |
|---|---|---|
| 属性（7） | `data/elements.js` の `icon` | 仲間画面の耐性の表 |
| 状態異常（7） | `data/statuses.js` の `icon` | 戦闘の名前の横・探索の左上・仲間画面・「状態を見る」 |
| ステータス（HP／攻／防／速／PP／効） | `data/ui.js` の `icons.stats` | 強化／弱体の印。**上向き（緑）／下向き（赤）の矢印を右下に重ねる**（`icons.arrowUp/Down`） |

- 描くのは `StatusMarks.draw`（状態異常）・`drawModifier`（強化／弱体）・`drawElement`（属性）。`sprites` を渡すと絵、渡さなければ文字
- 大きさは `data/ui.js` の `icons.size`（14）。文字の下端に合わせ、2px 下げて重心をそろえる
- 強化／弱体の「何が上がったか」の判定は `StatusMarks.summarizeModifier`（効果の最初の1つで代表する）
- 描いたときの決まりは他のスプライトと同じ（光は左上、K が輪郭）。文字の隣に 12〜16px で出すので、
  細かい模様は入れず「色と形」で見分けられることを優先した

> **呪いだけは効果の書き方が特性・装備・加護と同じ。**
> `effects: [{ type: "damageTaken", value: 1.3 }]` と書いてあり、
> `EffectSystem.collectEffects` が `getStatusDefs()` も読むので、
> **ダメージ計算側は何も変えなくてよい**。
>
> **封印は通常攻撃を止めない。** 「攻撃」はコマンドであって覚えた技ではないので、
> これも封じると何もできない相手になってしまう
> （`data/battle.js` の `normalAttackSkill` を見て除外している）。
>
> **眠りの起床判定は「殴られたとき」だけ。** 毒のターン終了ダメージでは起きない。
> 「起こしてしまうので殴れない」という読み合いを作るための仕掛けなので、
> こちらが選んで殴ったときにだけ働くようにしてある。
>
> **盲目は命中率に掛け算**（引き算ではない）。属性耐性と同じ考え方にそろえるため。
> 命中判定を抜けたあとに**回避判定がもう一度ある**ので、当たりにくさは2段構え。
> 実測では、体当たり（命中1.0）でコウモリを狙うと 86% → 52% になる。

**毒の歩きダメージ**（`MonsterInstance.walkStep`）

- 5歩ごとに1ずつ削る。歩数は**状態異常ごとに数える**（治って掛け直されたら0から）
- **HPは1で止まる。** 戦闘の外で戦闘不能になる経路は、このゲームにまだ1つも無い
  （罠も `leaveAtLeast: 1`）。毒だけ例外にはしない
- **知らせは出さない。** 5歩ごとに画面中央を遮ると、歩いている最中ずっと視界を潰す。
  左上のパーティ表示に「毒」の印とHPが常に出ているので、減っていることはそちらで分かる
- 治すには**解毒草**（40G・静寂の深層クリアで店に並ぶ）。拠点へ帰れば消える

### レベル上限

`data/monsters.js` の `maxLevel` でモンスターごとに設定する。
`data/growth.js` の `levelCap`（**99**）を超えることはできない。未指定なら `defaultMaxLevel`（50）。

### 戦闘の演出

計算は一瞬で終わるが、結果は**1つずつ順番に見せる**。

- 攻撃が表示された瞬間に、その相手のHPバーが**少しずつ減る**
- ダメージ量が対象の**頭のすぐ上**に浮かび上がる。出た瞬間は大きく、上へ流れながら薄くなる
- 同じ相手に続けて出しても重ならないよう、左右へ少し散らばる
- 倒れた相手は演出が終わるまでその場に残り、HPバーが0になった時点で姿を消す
- **決定キーを押している間は早送り**できる
- メッセージ欄が埋まったら **古い行を消さずに送り待ち**になる（`▼` が出る）。
  行が流れて消えないので、味方が何をしたか必ず読める

| 場面 | 数字 | 画面効果 |
|---|---|---|
| 通常ダメージ | 白 20px | 軽く揺れる |
| 会心の一撃 | **黄・30px** | 大きく揺れる＋金色に光る |
| 相性がよい | 橙 24px | 揺れる＋橙に光る |
| 相性が悪い | 灰 17px | なし |

| 設定 | 内容 |

| `quickDelay` | 早送り中の待ち時間（ms） |
| `hpDrainPerSecond` | HPバーが1秒に動く量 |
| `hpMinDrainTime` | 少量のダメージでも最低これだけ時間をかける |
| `speedTable` | 設定の「戦闘速度」1〜8に対応する倍率 |
| `popup` | 浮かぶ数字の動き（高さ・散らばり・弾む大きさなど） |
| `styles` | 場面ごとの色・大きさ・揺れ・発光 |

> 表示用のHPは `js/battle/BattleAnimator.js` が実際のHPとは別に持っている。
> 浮かぶ文字は `js/ui/FloatingText.js`、画面の揺れと発光は `js/ui/ScreenEffects.js`
> （どちらも戦闘以外でも使い回せる）。
> 今後モーションやエフェクトを足すときは、`_playEvent` と `styles` に追加する。

### ターンの頭「戦う／逃げる」（α-8）

毎ターン、仲間ごとのコマンドの前に **「戦う／逃げる」** が出る（phase `turnMenu`、`_beginTurnMenu`）。

- **戦う** → 仲間ひとりずつのコマンドへ（`_beginCommandPhase`）。最初の仲間で Esc を押すとここへ戻る
- **逃げる** → 全員ぶんの行動を `flee` にしてそのまま解決する。失敗すると**誰も動けず**、敵だけが動く
- 主との戦いでは「逃げる」を**薄く出して選べない**（`CommandMenu` の `disabled`。押すと「主からは逃げられない!」）。
  無いのではなく「できない」と分かるようにするため
- 説明（チュートリアル）は `turnMenu` トリガーで出る。仲間ごとのコマンドの説明（`battleStart`）は「戦う」を選んでから

### 戦闘コマンド

| コマンド | 内容 |
|---|---|
| 攻撃 | 通常攻撃。技を選ばずそのまま対象を選ぶ。**PPを使わない** |
| 技 | 技を選び、対象の敵を選ぶ。**PPを消費する** |
| 防御 | そのターンの間、受けるダメージが **0.5倍**（属性も会心も問わない）。次のターンで解除 |
| スカウト | 敵を仲間に誘う。成功率は `data/scout.js` の式（HPが低いほど上がる）。**成功するとその場で戦闘が終わる**。連れていける数がいっぱいでも誘える（下記）。**1ターンに1回だけ**（下記） |
| 道具 | `usableIn` に `"battle"` を含むアイテムを、味方に使う |
| 状態を見る | 盤面の全員（味方→敵）を1体ずつ見る。掛かっている状態異常と強化／弱体を、**効果の中身と残りターン**つきで並べる（無ければ「状態異常なし」）。**行動にはならず**、見終わるとコマンドへ戻る（phase `inspect`、`_inspectLines`） |

> 「逃げる」は仲間ごとのコマンドには無い（ターンの頭へ移した）。
> ボスは `data/bosses.js` の `scoutableWhen` でスカウトを制限できる。逃走は `data/battle.js` の `bossCanFlee`。

### 敵が誰を狙うか

**前に出ている仲間ほど狙われる。** 盤面の左から **50% / 35% / 15%**
（`data/battle.js` の `targetWeights`）。並び順がそのまま「誰を盾にするか」の選択になる。

- 盤面に出ている数が少ないときは、その数だけで割り直す（2体なら 59% / 41%）
- `targetWeights` を書かなければ、今までどおり均等に選ぶ
- **範囲全体の技（火の息）はこの重みを受けない。** 全員に当たる

### スカウトは1ターンに1回（と、そこから生まれる小技）

スカウトには**二重の制限**がかかっている。

1. **選んだ瞬間にそのターンが締め切られる**（`BattleScene._commitAction`）。
   まだ指示していない仲間は行動できない
2. **誘った1体以外の味方は、行動順から丸ごと外れる**（`BattleSystem._buildTurnOrder`）。
   すでに指示を出していても、攻撃・技・道具は出ない

**ところが防御だけは通る。** `takeTurn` は行動順を組む**前**に `_applyDefend` を呼び、
`allyActions` から直接 `_defending` を立てているため、行動順に載らなくても効く。

| 選び方 | 結果 |
|---|---|
| 1体目でスカウト | 残り2体は**何もできずに**ターン終了 |
| 攻撃 → 攻撃 → スカウト | **攻撃は出ない**。スカウトだけ |
| 防御 → 防御 → スカウト | **前の2体が守りを固めたまま**誘える |

**これは意図して残してある。** 「誘うのは最後の1体」「その前は防御」と気づいた人が得をする形で、
守りを固めて粘るか、先に殴って成功率を上げてから誘うかの駆け引きになるため。
`_buildTurnOrder` のコメントに、防御以外も通したくなったときの直し方も書いてある。

### ボスを仲間にする

**ボスは一度倒してから、2度目の挑戦で誘えるようになる。** 初回は倒す相手。

条件は `data/bosses.js` の `scoutableWhen` に書く。**ダンジョンや店の開放条件と同じ書き方・同じ判定**（`DungeonCatalog.isConditionMet`）なので、次のどれでも書ける。

```js
scoutableWhen: "mossyMine"          // そのダンジョンをクリアしたら（＝2度目の挑戦から）
scoutableWhen: { region: "cradle" }  // その地方を全部クリアしたら（＝地方解放後）
scoutableWhen: true                 // 最初から誘える
// 書かなければ一生誘えない
```

現在は3体とも「2度目の挑戦から」。**地方解放後に変えたくなったら、その1行を書き換えるだけ**でよい。

**仲間になるときはレベルが下がる。** ボスは高いレベルで戦う相手なので、そのまま連れて行くと強すぎる。
既定は `data/scout.js` の `bossJoinLevel`（**Lv1**）で、ボスごとに `scoutLevel` で上書きできる。

- **性格と個体値は戦った個体のものを引き継ぐ**ので、「その一体を捕まえた」感じは残る
- 覚えている技はそのレベルのものに戻る（キングスライムなら体当たりだけ）
- 通常のエンカウントは今までどおり、**戦った個体がそのまま**仲間になる
- レベルが下がったことは**画面には出さない**（仲間の一覧を見れば分かるため）

**ボスの勧誘が終わると、その挑戦はそこで終わって拠点へ帰る。** 結果画面には「勧誘」と出る。
ボス戦が終わったことに変わりはないという扱いで、その場に残れると主を何体でも狩れてしまうため。

> 連れていける数がいっぱいで「逃がす」を選んだ場合も、同じように挑戦は終わる。
> 誘いに応じてもらった時点でボス戦は決着しているため。

### スカウトの行動順

スカウトは他のコマンドと扱いが違う。

1. スカウトを選んだ時点で、**他の仲間のコマンド選択は行われない**
2. 誘った1体が**素早さに関係なく最初に行動**する
3. **成功** → その場で戦闘終了（敵は行動しない）
4. **失敗** → そのあと**敵だけ**が行動する（他の仲間は動かない）

つまりスカウトは「1ターンを丸ごと賭ける」行動になっている。

### 連れていける数がいっぱいのとき

以前は「これ以上連れていけない!」で終わっていたが、**判定は行い、成功したら行き先を選ぶ**。

| 選択肢 | 内容 |
|---|---|
| 入れ替える | 連れている仲間を1体選ぶ。**その仲間は拠点の預かり所へ送られ**、新しい仲間が加わる |
| 逃がす | 仲間にしない。図鑑には「仲間にした」記録が残る |
| 拠点に送る | 新しい仲間をそのまま預かり所へ送る |

- 預かり所もいっぱいだった場合は、理由を出して**選び直しになる**（相手は消えない）
- この画面は取り消せない。誘いに応じた相手の行き先は必ず決める

## 拠点の預かり所

連れていける6体に入りきらない仲間を預けておく場所。上限は `data/config.js` の `storageMax`（**30体**）。

拠点の「仲間」画面で **←→** で「連れていく / 預かり所」を切り替える。

**「仲間を選ぶ → その仲間に何をするか決める」**という一方向の流れになっている。

| いる場所 | 決定を押すと選べること |
|---|---|
| 連れていく仲間 | **様子を見る**／預かり所へ預ける／並び替える／装備／やめる |
| 預かり所 | **様子を見る**／パーティに加える／装備／やめる |

- **最後の1体は預けられない**（戦えなくなるため）
- パーティが満杯のときは加えられないので、**先に誰かを預ける**
- 並び替えを選ぶと移動先を選ぶ状態になり、決定でその位置と入れ替わる
- 預かり所は6体より多く入るので、一覧は画面に収まる分だけ窓のようにずらして表示する
- 預かり所の中身はセーブに含まれる（古いセーブを読み込んだ場合は空）

> 以前は「2体を選んで入れ替える」方式だったが、
> 何が起きるか分かりにくく、預かり所が空のときに操作できない問題もあったため作り直した。

### 様子を見る

**何も変えない項目なので、選択肢の先頭に置いてある。** 間違えて押しても損がない。

選んだ1体だけを画面いっぱいに出す。

| 場所 | 出るもの |
|---|---|
| 左 | 絵（**128px**。一覧の48pxより大きい）と、名前・Lv・性格。その下に**技・特性** |
| 中央 | HP／PP／攻撃／防御／素早さ／次のLvまで・**装備（枠ごと。名前だけ）** |
| 右 | **属性への耐性**（7属性）と**状態異常への耐性**（7種）を2列で。名前の前に絵。その下に**効果** |

- 文字は一覧の詳細欄より一段大きい（`inspect.stats.font` / `inspect.resist.font`、14px）。ゆっくり眺める画面なので読みやすさを優先
- 耐性はどちらも装備込みの値。「（装備込み）」の注記は消した（着けた本人は分かっている）。
  代わりに**装備で動いたぶんを「(+3)」と値の隣に出す**（`_resistancesWithout` で外した値と比べる）。
  ステータスも同じで「攻撃 17 (+8)」（`_statsWithout`）。特性・加護のぶんは含まない——装備の効き目だけが見える
- 上限（耐性 10）で止まったときは、止まったぶんだけの差になる（毒 8 に +7 を着けると「+10 (+2)」）
- **状態異常への耐性を見られるのはこの画面だけ。** 一覧の詳細欄は狭く、属性耐性までしか入らない
- **↑↓ でそのまま別の仲間へ移れる**（いちいち一覧へ戻らなくてよい）。決定か Esc で一覧へ戻る
- 配置は `data/ui.js` の `party.inspect`。絵の大きさや列の位置・文字の大きさはデータだけで変えられる

#### 効果欄（α-8）

```
効果
攻撃 ×1.2      （野生の勘）
被ダメージ ×1.15 （野生の勘）
素早さ ×1.1     （深淵の牙）
光の与ダメージ ×1.15 （光る提灯）
```

**特性と装備でいま効いている効果を、1か所にまとめて出す**（`_effectLines` / `_renderEffectList`）。
以前は装備1つずつの下に並べていたが、4枠ぶんで中央の欄が窮屈だったため右下へ移した。

- **ステータスの加算（攻撃+3）と耐性の加算（毒+7）は並べない。**
  その2つは、すでに数値の隣に「(+15)」「(+5)」として出ている。ここに書くと同じことの二度書きになる。
  出すのは**他では見えない効果**（倍率・与ダメージ・被ダメージ）だけ
- **特性の効果がここで初めて見えるようになった**（今までは特性の名前しか出ていなかった）
- 後ろに出どころ（特性名・装備名）を薄く小さく。条件つきの効果（`攻撃 ×1.5（HP25%以下のとき）`）で
  行が長くなるときは、はみ出すので出どころを省く（`maxX`）
- 効果が1つも無いときは、見出しごと出さない

### 敵の数

ダンジョンごとに `encounter.groupSize: { min, max }` で指定する（盤面上限 3 を超えない）。
書かなければ `data/enemies.js` の `defaultGroupSize` を使う。

### 出現レベル

**ダンジョンごと**にも**モンスターごと**にも設定できる。

```js
encounter: {
  levelRange: { min: 4, max: 8 },        // このダンジョンの既定
  table: [
    { species: "flamin", weight: 1.2 },  // 既定（Lv4〜8）で出る
    { species: "slime",  weight: 0.4, minLevel: 1, maxLevel: 6 }  // この種族だけ別枠
  ]
}
```

階ごとに変えたい場合は `perFloor` を書く（書いた項目だけが上書きされる）。

```js
encounter: {
  levelRange: { min: 1, max: 1 },
  groupSize:  { min: 1, max: 1 },
  table: [ ... ],
  perFloor: {
    "1": { levelRange: { min: 1, max: 1 }, groupSize: { min: 1, max: 1 } },
    "3": { levelRange: { min: 2, max: 4 }, groupSize: { min: 1, max: 2 } }
  }
}
```

レベルは**上から順に、最初に見つかったもの**を使う。

1. `table` の `minLevel` / `maxLevel` … モンスターごと
2. `perFloor` の `levelRange` … その階の指定
3. `encounter` の `levelRange` … その場所の既定
4. `data/enemies.js` の `defaultLevel` … 全体の既定（現在 Lv1）

敵の数と遭遇率も同じ順に探す（`perFloor` → その場所 → 全体の既定）。

### 戦闘中の表示

- **敵のレベルは表示しない**（味方のみ表示）
- 味方は**HPバーの下にPPバー**を出す。数値も左にPP・右にHPで並べる
- PPバーは残量で色が変わらない（`theme.ppBarColor`）。**色が変わるのはHPだけ**なので、
  減っていても危険かどうかをHPの色だけで判断できる
- 技を選ぶときは、左のメッセージ欄に**属性・威力・命中・PP・説明**が出る。
  道具を選ぶときも同じ場所に説明が出る（文言は `data/skills.js` / `data/items.js` の `description`）

### 戦闘の終わり方

| 結果 | 経験値 | ドロップ | 戻る先 |
|---|---|---|---|
| `win`（全滅させた） | あり | あり | 探索 |
| `scouted`（スカウト成功） | なし | なし | 探索 |
| `flee`（逃走成功） | なし | なし | 探索 |
| `lose`（全滅した） | なし | なし | 拠点（HP全回復） |

## アイテムドロップ

倒したモンスターが落とすアイテムは `data/monsters.js` の `drops` で指定する。

```js
drops: [

```

> PPは**泉か拠点でしか戻らなかった**ので、精気の実を宝箱にも入れてある。

## 名前をつける

仲間の画面で**決定 → 「名前を変える」**を選ぶと、文字盤が開く。**8文字まで**。

**なぜ文字盤なのか**：ゲーム画面は Canvas なので**日本語入力（IME）が使えない**。
キーを直接拾う方法だと英数字しか打てないため、画面に文字を並べて1文字ずつ選ぶ形にしている。

| | 中身 |
|---|---|
| 文字表・最大文字数 | `data/naming.js`（ひらがな／カタカナの2面。面は1エントリ足すだけで増やせる） |
| 置き場所 | `data/ui.js` の `nameInput` |
| 部品 | `js/ui/NameInput.js`（操作と描画だけ。どこからでも開ける） |

- 上下左右で選び、決定で1文字入れる。**下端の「けす／かな／けってい」もカーソルで選べる**
- Esc は1文字消す。**空のときだけ**名前つけそのものをやめる
- Q / E でも面を切り替えられる。マス目はマウスで直接押せる
- 名前を空にすると**種族名に戻る**

名前は `MonsterInstance.nickname` に入り、`getName()` が返す。セーブにも入る。
種族名が要るところ（図鑑など）は `getSpeciesName()` を使う。

> 文字数を増やすときは `data/ui.js` の `battle.allyRow` / `enemyRow` の `statusW`（190px）も
> 一緒に広げること。12pxの等幅で全角8文字＝96pxなので、Lv表示と強化の印を入れてちょうど収まっている。

## 図鑑画面

**モンスター／アイテム／特性／技／性格／加護**を **←→** で切り替える（タブのクリックでも切り替わる）。

| 表 | 中身 | 伏せるか |
|---|---|---|
| モンスター | 出会った相手 | 未発見は ??? |
| アイテム | 手に入れたもの | 未入手は ??? |
| 特性 | 持っている仲間がいる特性 | 未判明は ??? |
| **技** | **仲間が実際に覚えた**技 | 未判明は ??? |
| **性格** | ステータス補正の一覧 | **最初から全部見える** |
| **加護** | 効果と出やすさの一覧 | **最初から全部見える** |

### アイテムの詳細（α-8）

- 装備は分類が「装備・武器」のように枠まで出て、**効果**も並ぶ
- **「手に入る場所」**に、落とすモンスターと確率・宝箱（どこでも／その場所だけ）が出る。
  **まだ会っていないモンスターは「???  ?%」**（出会う前に落とすもので正体が割れないように）。
  店・工房は出さない（そちらの画面で分かる）。落とす相手も宝箱も無いものは「落とす相手はいない（店か工房で）」
- 一覧では「装備」のくくりの中が**武器／防具／アクセサリー**の小見出しで分かれる（`buildRows` の `subgroups`）。
  持ち物・工房の画面も同じ分け方（工房は「回復」「装備」の見出しも付く）。分類の名前と並びは `data/categories.js` の `equipSlot`

仲間画面の詳細欄（右の狭い枠）は、**中身の量から行間を決める**（`_detailLineHeight`）。技4つ・装備4つの仲間でも
枠からはみ出さない。空いている装備枠は「空き 2」とまとめる（枠ごとの表示は「様子を見る」で見られる）。

技は**属性ごとに区切って**並ぶ（見出しの色も属性の色）。並び順は `data/elements.js` の `order`。
詳細には**属性・威力・消費PP・命中・会心**と、**覚えるモンスターとそのレベル**が出る。
威力0の技は数字ではなく「通常攻撃と同じ」と表示する。

> 通常攻撃（「攻撃」）は覚える技ではなくコマンドなので、
> `data/skills.js` で `showInDex: false` と書いて図鑑には載せていない。

### ★ 技だけ「覚えたか」で判明する

**特性は捕獲、技は習得。** ここだけ条件が違う。

- **特性**は種族そのものが持つものなので、その種族を1体でも仲間にすれば判明する
- **技はレベルで覚える**ので、捕まえただけでは判明しない。
  実際にそのレベルへ到達して覚えたときに判明する

> 以前は技も「覚える種族を仲間にしていれば判明」だった。
> そのため**ゲーム開始時点で5個も出ていた** ——
> Lv5のスライムを連れているだけで、Lv8の「アクア」もLv11の「キュア」も、
> コウモリのLv9「吸血」まで見えてしまっていた。いまは「体当たり」の1個だけになる。
>
> 記録は `Discovery.skillsLearned`（捕獲・入手の記録と同じ場所）。
> **逃がした個体が覚えていた技も記録には残る** ——
> 図鑑は「いま持っているもの」ではなく「これまでに見たもの」の記録なので、
> 捕獲の記録が消えないのと同じ扱いにしてある。
>
> 記録するのは3か所。仲間に加わったとき（`Game.addMonster`）、
> 預けたとき（`storeMonster`）、レベルアップで覚えたとき（`BattleScene` の `skillLearned`）。
> `BattleSystem` は `Game` を知らないままにしたいので、
> イベントに `skillId` を載せて画面側で記録している。
>
> **古いセーブにもこの記録は無い。** `Game._recordInitialDiscoveries` が
> 読み込み時に手持ちと預かり所を見て拾い直すので、覚えている技は「???」に戻らない。

性格と加護は「集めるもの」ではなく**確認するための一覧**なので伏せていない。
加護は今後ショップでの購入や厳選を予定しているため、
どんなものがあるかを先に見られるほうが計画を立てやすい。

説明が枠に入りきらないときは、**決定キーで詳細にカーソルを移し、↑↓で読み進める**（Esc または決定で一覧へ戻る）。続きがあるときは枠の右端に ▲▼ が出て、読んでいる間は色が変わる。

**マウスなら、説明の上でホイールを回すだけで読み進められる**（読むモードに入らなくてもよい）。

- 右の詳細は「行の配列」を組み立ててから、枠に入る分だけ描いている。
  項目を増やしても**はみ出さず、自動でスクロールできる**
- モンスターの詳細では、0でない**耐性が属性の色つきで並ぶ**
- スプライトは枠の上部に固定し、その下だけがスクロールする
- 折り返す文字数は `data/ui.js` の `dex.detail.charsPerLine`

### ボスを強くする3つの道と、その使い分け

| やり方 | 起きること |
|---|---|
| レベルを上げる | 報酬も `基準 × (1 + (Lv-1) × 0.15)` で膨らみ、**レベルが走りすぎる** |
| 基礎値を上げる | **仲間にしたときまで強くなる**（スカウトはLv1だが基礎値はそのまま） |
| **`statMultiplier`** | 主として立ちはだかっているあいだ**だけ**強い |

**基本は `statMultiplier` を使う。** `data/bosses.js` に書き、
`{ hp, attack, defense, speed, pp }` のうち書いたものだけが効く（省略で等倍）。

```js
blazeBeast: {
  species: "magmaBeast", level: 12,
  statMultiplier: { hp: 2.16, attack: 0.85, defense: 1.65, speed: 0.70, pp: 2.13 }
}
```

灼熱の獣は 基礎 HP35 攻16 防8 速7 PP6 に成長率と上の倍率が掛かり、
**Lv12で HP208 攻42 防29 速14 PP31**。
仲間にすると倍率が外れ、**Lv1で HP35 攻16 防8 速7 PP6**（在来種の最大がHP28なので、少し上）。

> **倍率が1を下回っていても弱体化とは限らない。**
> マグマウルフは攻撃の成長率が高い（0.19）ので、素のままだとLv12で攻撃47まで伸びる。
> `attack: 0.85` は、調整済みの42へ戻すための打ち消し。
> 速さの `0.70` のほうは意図的な弱体で、大きく重い獣らしくするために掛けている。

- 仕組みは `MonsterInstance.bossEffects`。特性・装備・加護と同じ `effects` の形で、
  `EffectSystem` が5つ目の出どころとして読む。**ステータス計算もダメージ計算も変更不要**
- 敵を作る `DungeonScene._startBossBattle` でだけ付ける。スカウトは個体を作り直すので引き継がれない
- **3体とも `statMultiplier` を持つ。** 書かないボスは今のところ無い

## アイテムを追加するとき

`data/items.js` に1エントリ足すだけでよい。

```js
antidote: {
  id: "antidote", name: "解毒草", category: "heal",
  description: "苦い葉。噛むと毒が抜ける。", maxStack: 99, price: 40,
  effect: { type: "cureStatus", statuses: ["poison"] },  // 種類は ItemUsage が処理する
  usableIn: ["home", "dungeon", "battle"]
}
```

| 効果の種類 | 内容 |
|---|---|
| `healHp` | HPを `value` だけ回復 |
| `healPp` | PPを `value` だけ回復 |
| `cureStatus` | 状態異常を治す。`statuses` に書いたものだけ。**省略すると `curable: true` を全部治す**（万能薬を作るとき） |
| `escape` | その場から拠点へ帰る（実際に帰らせるのは画面側） |

- 新しい**効果の種類**を足すときは `js/systems/ItemUsage.js` の `EFFECT_HANDLERS` に関数を1つ追加し、
  `data/messages.js` の `items.used` と `battle.itemHealed` にも**同じ名前で1行足す**。
  書かなければ `default` の文が使われる
- **使ったときの文は効果の種類ごとに分けてある。** 1つの文しか無かったころは、
  精気の実（PP回復）でも「HPが 5 回復した!」と出ていた
- **効果が無ければ持ち物は減らない**（毒でない仲間に解毒草を使っても消費されない）。
  満タンに回復薬を使ったときと同じ扱い
- 戦闘中に緑の回復表示とHPバーの反映を出すのは `healHp` のときだけ
  （`ItemUsage.healsHp`）。解毒草でHPが増えたように見せないため
- `usableIn` に `"battle"` を入れると戦闘中の「道具」コマンドに出る。`"home"` は拠点の持ち物画面。
- ゲーム中にアイテムを渡すときは必ず `game.giveItem(itemId, count)` を使う（持ち物と図鑑が同時に更新される）。仲間を加えるときは `game.addMonster(monster)`。

未実装の項目を有効にするときは、`js/scenes/HomeScene.js` 冒頭の `MENU_ITEMS` で
その項目の `ready` を `true` にし、`_openFeature` に処理を追加する。
項目の並び順や表示名も同じ場所（並び順は `MENU_ITEMS`、表示名は `data/messages.js` の `home`）で変更できる。

## 設定画面

拠点の「設定」から開く。左でゲーム設定を調整し、右で操作キーを確認する。

| 項目 | 内容 |
|---|---|
| 名前と見た目 | 主人公の名前と服の色を決め直す画面を開く |
| 戦闘速度 | **8段階**（最も遅い〜最速）。演出の進む速さが変わる |
| エフェクトの濃さ | **4段階**（全くなし〜濃いめ）。技の演出と画面の揺れ・発光 |
| スクロール速度 | **5段階**（1行ずつ〜5行ずつ）。マウスのホイールを1段回したときに動く行数 |
| チュートリアル | 出す／出さない |
| 全体音量 / BGM音量 / 効果音量 | 0〜100%。動かすとその場で反映される |

- 操作キーの一覧は `data/keys.js` の内容をそのまま表示するため、キーを変えれば表示も自動で変わる

### 設定はセーブファイルごと

設定は**セーブファイルごとに別々**に持つ。ファイル1で「チュートリアルを出さない」にしても、
ファイル2の冒険には関係しない。

| 場面 | どの設定になるか |
|---|---|
| タイトル・ファイル選択 | 最後に保存した設定（＝最後に遊んだファイルの音量） |
| 続きから・中断から | そのファイルの設定 |
| 新しく始める | **既定値**（前のファイルの設定を持ち越さない） |
| 拠点で別のファイルへセーブ | いまの設定ごと、そのファイルへ移る |

| 保存先（localStorage） | 中身 |
|---|---|
| セーブのキー ＋ `.settings`（例 `my-first-app.save.slot2.settings`） | そのファイルの設定。キーの決め方は `SaveManager.settingsKeyFor` |
| `abyss-chronicle.settings`（`data/settings.js` の `storageKey`） | 最後に保存した設定の写し。タイトルで使う |

- **書くのは3か所**：設定画面を閉じたとき・セーブしたとき・中断したとき（`Game.saveProgress` / `suspendRun` が `settings.save()` を呼ぶ）。
  ふきだしを Esc で止めたときのように、設定画面を通らずに変わった値も、セーブすれば残る
- セーブファイルの**コピー・移動・削除**では、設定も一緒に運ぶ・消す（`SaveManager.copySlot` / `clear`）
- **分ける前の設定**は `abyss-chronicle.settings` 1つだけだった。起動時に、中身のあるファイルで
  まだ設定を持っていないものへ写す（`Game._migrateSettings`）。すでに持っているファイルには触らない
- 新しく始めたときは**まだ書かない**。セーブ本体と同じで、最初のセーブで初めて書く
  （選んだだけでタイトルへ戻ったら、そのファイルに前からあった設定はそのまま）

設定項目を増やすときは `data/settings.js` の `items` に1エントリ足すだけでよい。

```js
{ id: "textSpeed", label: "文字速度", type: "range",
  min: 1, max: 5, step: 1, default: 3 }
```

## 起動方法

`app.html` を **ダブルクリック** して開くだけで動作します（ローカルサーバ不要）。

> **ファイルの読み込みについて**
> `app.html` はスクリプトを配列で並べて読み込んでいる。
> 通常の `<script src="...">` だと、ブラウザが**古いファイルを使い回して**
> 「一部だけ古い処理が動く」という分かりにくい不具合が起きるため、
> 読み込みごとに変わる印（`?t=...`）を付けて必ず最新が読まれるようにしている。
> ファイルを追加したときは `app.html` の配列に**順番を守って**足すこと。

> `file://` での動作を優先しているため、データは `.json` ではなく `data/*.js` として持っています。
> 各データファイルは `MyGame.rawData` に登録され、`DataLoader` → `GameData` を通して参照されます。

### Claude のプレビュー画面で動かすとき

**プレビュー画面では `file://` で開いてはいけない。** ページが `data:` の静的スナップショットとして
描かれるため、`<script src="js/...">` が1つも読み込まれず、**エラーすら出ないまま真っ黒になる**
（コンソールにログが1行も出ないのが、この状態の見分け方）。

ローカルサーバ経由で開けば動く。`.claude/launch.json` に設定を置いてあるので、
`preview_start` に `abyss-chronicle` を渡すだけでよい。

```json
{
  "name": "abyss-chronicle",
  "runtimeExecutable": "python",
  "runtimeArgs": ["-m", "http.server", "8123", "--directory", "my-first-app"],
  "port": 8123
}
```

- `http://localhost:8123` を開くと `index.html` → `app.html` と送られてタイトル画面になる
- ダブルクリックでの起動（上記）はこれまでどおり。**この設定はプレビュー画面のためだけのもの**

## ボスを追加するとき

`data/bosses.js` にエントリを足し、`data/dungeons.js` の `boss` からそのidを指すだけでよい
（コードの変更は不要）。

```js
frostLord: {
  id: "frostLord", species: "kingSlime", level: 32, title: "凍える王",
  scoutableWhen: "frozenHollow", isFinal: false
}
```

- `species` は `data/monsters.js` の種族id。ボス専用の種族を追加してもよい。
- **逃走はボスごとに書かない。** 主からは共通して逃げられない（`data/battle.js` の `bossCanFlee`）。
  ボスごとの設定にしていたころは、ボスを足すときに書き忘れると逃げられる主ができた。
- 誘えないボスは `scoutableWhen` を書かなければよい（書かなければ一生誘えない）。
  誘えないときは戦闘コマンドから「スカウト」の項目自体が消える。
- ボスは**そのダンジョンの最深階**に出る（何階かは `data/dungeons.js` の `floors`）。
- `isFinal: true` のボスを倒すとエンディングへ。false ならクリア記録を付けて拠点へ戻る
  （**いまは全ボスが false**）。

## マウス操作

キーボードと同じことをマウスでもできる。**どちらで操作してもよく、混ぜて使える**。

| 操作 | 内容 |
|---|---|
| 重ねる | その項目・行・相手に選択が移る |
| 左クリック | 決定（重ねているものを選ぶ） |
| 右クリック | 取り消し・戻る（Esc と同じ） |
| ホイール | 一覧の上では選択を上下、図鑑の説明の上ではその説明をスクロール |

> **ホイールは端で止まる**（回り込まない）。いちばん下まで送ったつもりが先頭へ戻ってしまい、
> どこを見ていたか分からなくなるため。キーボードの ↑↓ は今までどおり端で折り返す。

ホイール1段で動く行数は、**設定画面の「スクロール速度」**（1〜5行）で変えられる。
`Input` が設定を見て `pointer.wheel` を倍にするので、**一覧にも図鑑の説明にも同じだけ効く**。
| 「戻る」ボタン | 各画面の右下。1つ前へ戻る（Esc と同じ） |

**「戻る」ボタン**は全画面の同じ位置（右下）に出る。カーソルを重ねると色が変わる。
途中の状態（ショップの個数選び・工房の確認・装備の選択など）で押すと、画面を閉じずに**1つ前へ戻る**。
位置は `data/ui.js` の `theme.backButton` で全画面まとめて変えられる（部品は `js/ui/BackButton.js`）。

対応している場所：

- 拠点・タイトルなどの**縦並びメニュー**（`CommandMenu` を使う画面すべて）
- 持ち物・図鑑・ショップ・工房・装備選択などの**一覧**（`ScrollList` を使う画面すべて）
- 図鑑とショップの**タブ**、仲間画面の**連れていく／預かり所の切り替え**
- 仲間・預かり所の**行**、ダンジョン選択の**行**
- 戦闘の**コマンド／技／道具**、**狙う相手**（敵の絵かHP欄を押す）
- 戦闘のメッセージ送り（画面のどこを押しても進む）

### 作りについて

マウスの状態は `js/core/Input.js` が持つ。**キーボードと同じ入り口（`game.input`）から見えるので、
画面ごとにマウス用の処理を書き足さなくてよい**。

- 位置は**キャンバス座標に直してから**渡すので、画面が拡大縮小されていても
  `data/ui.js` に書いた座標とそのまま比べられる
- 当たり判定は `Panel.containsPoint(rect, point)` で共通化してある
- **カーソルを動かしたときだけ**選択が移る。置いたままキーボードで操作しても邪魔にならない
- 一覧は `ScrollList.clickedEntry(input)` が「行が押されたか」を返すので、
  呼び出し側は `決定キー または クリック` と書くだけでよい
- ボタンを押している最中は `pointer.down`（スクロールバーをつまむのに使う。画面の外で離しても `window` の `mouseup` で解く）

### 一覧のスクロール（`ScrollList`）

一覧は **px 単位**でスクロールし、表示は目標へ少し遅れて追いつく（`theme.scrollbar.smoothing`）。
右端に細いバーが出て、**つまんで動かす／溝を押してそこへ飛ぶ**ができる。

- **上下キー**は選択を動かし、選んだ行が枠の外なら見える所までスクロールする。
  見出しの直下の行を選んだときは**見出しも一緒に見せる**（以前は一番上へ戻ると「- スライム系 -」だけ隠れる不具合があった）
- **ホイール**は選択を動かさず、中身だけをずらす（1段で `wheelRows` 行ぶん × 設定のスクロール速度）。
  以前は「↓キーを速く押す」のと同じで、項目が多いと途中で止まれなかった
- 枠の外は描かない（`clip`）ので、端の行が途中で切れて見え、スクロールの途中だと分かる
- 中身が枠に収まっているときはバーを出さない
- 一覧を作り直したあとにカーソル位置を戻すときは `setIndex(i)` を使う（`index` に直接入れるとスクロールが追いつかない）
- 太さ・色・つまみの最小の長さは `data/ui.js` の `theme.scrollbar`

> まだ対応していないもの：ダンジョン内の移動（クリックで移動するには経路探索が要る）、
> ショップの個数指定。いずれもキーボードで操作できる。

## 操作方法

- 移動: `W A S D` または 矢印キー
- 決定: `Enter` / `Space` / `Z` / **左クリック**
- キャンセル / 戻る: `Esc` / `X` / **右クリック**（探索中は拠点へ、拠点ではタイトルへ）
- パーティ編成: `P` / `Tab`（探索中）
- 預かり所へ預ける: `Q`（仲間画面）
- 装備を着け替える: `E`（仲間画面）
- セーブ: 拠点の「セーブ」（書く先を選ぶ）／中断: `F`（探索中）／ロードはタイトルの「つづきから」「中断したところから」
- ダンジョン再生成（確認用）: `R`

## 開発方針

- 数値（HP・攻撃力・出現率・捕獲率・スキル威力など）は `data/` のデータファイルで管理する。
- モンスター・スキル・アイテム・敵・ボス・特性はデータ駆動。追加はデータファイル編集だけで対応できる構造にする。
- ロジックと描画を分離し、責務ごとにファイルを分割する。
- グローバル変数を極力使わない（`MyGame` 名前空間 + IIFE）。
- 小さな機能単位で実装し、毎回動作確認できる状態を保つ。
- データ管理部分（DataLoader/GameData）は分離しており、将来 JSON へ移行しやすい。
